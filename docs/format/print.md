# 한셀 인쇄 배치와 PDF 규칙

> 작성: yoomin53 · 대상 버전: 한컴오피스 2024 한셀 (HCell.exe 13.0.0.711), 기본 프린터 Hancom PDF
>
> rcell 의 인쇄 배치(`src/print/paginate.rs`)와 PDF 출력(`src/print`, `src/render/page.rs`)이 따르는 한셀 규칙.
> 모두 한셀 COM(`PageSetup`, `Pages.Count`, `HPageBreaks`·`VPageBreaks`)과 한셀이 쓴 PDF(`ExportAsFixedFormat`)를
> rcell 이나 COM 으로 만든 실험 문서와 대조해 얻은 관찰이다. 실험 문서·한셀 PDF 는 저장소에 두지 않는다.

## 1. 측정 방법

| 도구 | 하는 일 |
|---|---|
| `tools/probe/print-oracle.ps1` | 한셀(COM)로 문서를 열어 시트마다 페이지 수, 가로·세로 페이지 나누기(새 페이지의 첫 행·열, 수동 표시), 배율, 인쇄 영역을 TSV 로. `-PdfDir` 면 통합 문서 PDF 도 저장 |
| `tests/print_layout.rs` | 코드로 만든 문서 64 가지의 페이지 수·나누기·그릴 배율을 한셀에서 잰 사실과 대조 (`RCELL_PRINT_CASES=<폴더>` 로 그 문서들을 저장해 한셀에 다시 물을 수 있다). `RCELL_PRINT_ORACLE=<TSV>` 면 정답 생성기가 잰 문서들 모두 |
| `tools/probe/print-diff.ps1` | 한셀 PDF 와 `rcell pdf` 를 Windows.Data.Pdf 로 같은 해상도의 그림으로 바꿔 페이지마다 픽셀 비교 (다른 픽셀 %, 잉크 겹침 % — `visual-diff.ps1` 과 같은 잣대) |
| `rcell pages <문서>` | rcell 의 페이지 수·나누기·배율 (정답 생성기와 같은 꼴) |

한셀의 시트 `ExportAsFixedFormat` 은 통합 문서의 보이는 시트를 모두 차례로 PDF 에 쓴다. 한셀 COM 은 바이너리
`.cell` 을 다시 열지 못하므로 정답은 XML·레거시 판으로 잰다.

## 2. 용지와 장치 단위

- 한셀은 페이지를 600 dpi 장치 단위로 그린다 (PDF 의 글자는 `0.12 0 0 −0.12 0 H cm` 아래 정수 자리). 1pt = 25/3 장치.
- 장치 용지는 참 용지 크기 (A4 4961 × 7016, Letter 5100 × 6600). PDF 의 MediaBox 는 용지를 mm 정수로 반올림해 pt 로 바꾼
  값을 정수로 자른 것 (A4 595 × 841, Letter 216 × 279mm → 612 × 790, Legal 612 × 1009, B4 728 × 1031). 내용은 두 크기의
  비율로 줄여 넣는다 (Letter 세로 790/(6600 × 0.12)).
- 용지 번호는 OOXML 과 같고 B4·B5 는 JIS 판 (257 × 364, 182 × 257mm — 페이지 나누기 대조). 가로 방향은 너비·높이만
  바꾸고 여백은 그대로.
- 용지 높이의 문턱 (행 15pt 에 위 여백을 문턱 ±0.15pt 로 바꿔 첫 페이지 행 수가 하나 바뀌는 자리): Letter 87.89pt·Legal
  87.89pt (인치 그대로 — mm 로 반올림한 279·356mm 이면 문턱이 1.1pt 옮겨 어긋난다)·A3 97.64pt·A5 92.77pt·B5(JIS) 96.39pt
  에서 한셀 COM 과 모두 같다. MediaBox: Letter 612 × 790, Legal 612 × 1009, A3 841 × 1190, A5 419 × 595, B5 515 × 728.
- 여백·머리글 여백은 장치 단위로 반올림 (위 여백 70.87pt → 591). 한셀 새 문서의 기본은 왼쪽·오른쪽 53.86pt(19mm),
  위·아래 70.87pt(25mm), 머리글·바닥글 36.85pt(13mm).

## 3. 인쇄 범위

- 인쇄 영역(`_xlnm.Print_Area`, 시트 범위 이름)이 없으면 **A1** 부터 쓰는 범위의 끝까지 (값이 B5 부터여도 페이지 나누기는
  1행부터).
- 쓰는 범위의 끝: 값·수식이 있는 칸, 테두리나 채우기가 있는 빈 칸, 선택 영역의 가운데로(`centerContinuous`) 맞춘 빈 칸,
  숨기지 않은 그리기 개체. 글꼴·표시 형식만 있는 빈 칸은 넣지 않는다 (서식 파일 Basic_Invoice 의 P15 — COM `UsedRange` 는
  B2:P49 지만 인쇄는 A:I, Retirement_Budget 의 제목 줄 G2:H2 까지).
- 넘친 글자가 닿는 열까지 넣는다 (화면과 같은 넘침 규칙 — 값이 있는 칸에서 멈춘다). 말뭉치 strings: 값은 A 열뿐이지만 긴
  문자열 하나가 116 열(DL) 근처까지 넘쳐 10 × 13 = 130 페이지. 만든 사례 overflow: B1 의 154 자가 AG 열까지 → 4 페이지,
  H1 에 값을 두면 1 페이지.
- 외부 문서를 가리키는 인쇄 영역(`'[1]시트'!$B$3:$H$46`)과 `#REF!` 는 쓰지 않는다. 여러 영역이면 영역마다 따로 나눈다.
- 반복 행·열은 `_xlnm.Print_Titles` (`$1:$3`, `$A:$B`).

## 4. 페이지 나누기

배율 지정(`pageSetup/@scale`)이면 쓸 수 있는 자리를 1/100 인치 단위로 정한다:

- 쓸 자리 = round((용지 − 위 − 아래 여백) / 0.72pt) (반은 올림 — 위 여백을 0.01pt 씩 바꾼 문턱 실험).
- 행은 화면 px (행마다 반올림한 px, `docs/format/screen.md`) × 배율 % 를 쌓아 넘으면 다음 페이지. 열도 같다.
  예: A4 기본 여백 972 에 22px 행 44 개, 배율 50% 면 88 개.
- 숨긴 행·열은 건너뛴다. 페이지보다 높은 행은 혼자 한 페이지.
- 수동 나누기(`rowBreaks`·`colBreaks`)는 그 행·열에서 새 페이지 (COM `Type` 수동). 나누기 목록은 영역마다 새 페이지의 첫
  행·열과, 마지막이 아닌 영역의 끝 + 1.
- 반복 행·열: 제목을 붙이지 않고 그 페이지를 지었을 때 제목 행이 들어가면 그 페이지에는 붙이지 않고, 아니면 제목 높이만큼
  자리를 빼고 붙인다 (제목 1–3 행: 첫 페이지 44 행, 다음부터 41 행. 제목 100–102 행: 1·2 페이지도 41 행, 100 행이 든 페이지만
  44 행).
- 페이지 순서는 나누기를 바꾸지 않고 인쇄 차례만 (`overThenDown` 이면 왼쪽에서 오른쪽 먼저).
- 머리글·바닥글, 행·열 머리글 인쇄, 가운데 맞춤은 나누기를 바꾸지 않는다.

## 5. 페이지에 맞추기

`sheetPr/pageSetUpPr/@fitToPage` 면 `fitToWidth`×`fitToHeight` 페이지 (0 은 제한 없음)에 들어가는 가장 큰 배율 zf 를 찾는다:

- 이때는 쓸 자리가 화면 px 단위 (용지 − 여백) / 0.75pt, 크기는 한셀 안의 크기 (COM `Width`·`Height`, 행마다 반올림하지
  않은 값 — 서식 파일 Basic_Invoice 의 서식 시트: 행 높이 합 817.45pt 로 85%, 반올림한 px 합이면 84%).
- 95 부터 1 씩 줄여 25 까지 보고, 그래도 넘치면 12 (200 행 × 20px 를 한 페이지에: 23% 가 아니라 12%, 400 행이면 12% 에
  2 페이지). 내용이 작아도 95 를 넘지 않는다.
- 페이지 수를 정한 방향의 수동 나누기는 쓰지 않는다 (1×3 맞추기의 20 행 나누기는 사라지고, 세로 제한이 없으면 남는다).
- 한셀이 저장하는 `scale` 은 이 값과 다를 수 있다 (서식 파일은 Excel 이 계산한 값이 남아 있다 — 한셀은 열 때 다시 찾는다).

## 6. 그릴 배율

페이지 나누기와 별도로, 그릴 때 행·열은 하나씩 round(px × z/100) (반은 올림) 화면 px 이고, 화면 1px 은 6.25 장치 (96 dpi).
z 는 모든 페이지가 1:1 쓸 자리 (용지 − 여백)/0.75pt 에 들어갈 때까지 1 씩 줄인다:

- 배율 지정 z 에서 시작한다. 단 100 은 인쇄 차례(보이는 시트 순서)에서 처음 나오는 **한 페이지짜리 시트만** 99 부터이고,
  나머지 시트(두 번째 한 페이지 시트, 여러 페이지 시트)는 100 에서 시작한다 (시트 셋·다섯 개 실험: 한 페이지 시트 가운데
  첫째만 글자 91, 나머지는 92. 첫 시트를 지우거나 옮기거나 숨겨도 인쇄 차례의 첫 한 페이지 시트). 배율 98·99·101 은 그대로.
- 맞추기면 zf 에서 시작한다 (1×3 맞추기 zf 69 → 67).
- 그래서 1/100 인치로 꽉 찬 페이지는 늘 줄어든다: 22px 행 44 개 = 968 > 933 → 97 (행 21px). 20px 행: 97, 13px: 96, 6px:
  91, 40px: 96 (행마다 반올림한 합으로 본다).
- 배율 100 에서 내용이 아주 작으면 (모든 페이지에서 행 px 합 × 6.25 ≤ 쓸 자리) 한셀은 세로만 6.25 배로 늘려 그린다 (가로
  1:1, 20px 행이 125px — 7 행 140px 는 늘고 150px 는 아니다). rcell 도 같게 그린다.
- 글꼴 크기는 round(pt × 25/3 × z/100) 장치 (11pt: z 99 → 91, 97 → 89, 12 → 11).

## 7. 페이지 위 자리

- 원점: 왼쪽 위 여백을 장치로 반올림한 자리. 행·열 경계는 원점 + ⌈Σ(인쇄 px × 6.25) − 0.5⌉ (반은 내림).
- 가운데 맞춤: 쓸 자리를 6.25 로 나눠 내림한 px 에서 내용 px 를 빼고 반을 내림한 px 만큼 옮긴다 (round(px × 6.25)).
- 칸 상자는 경계에서 장치 6 왼쪽·위 (화면에서 칸의 마지막 픽셀이 격자선 자리인 것과 같다). 채우기는 이 상자.
- 테두리 (선 가운데 = 경계 − 6, 굵은 선만 경계 위): 가는 선 6, 중간 13, 굵은 19, 머리카락 1 장치. 이중선은 가는 선 둘을
  경계 − 12 와 경계. 점선 무늬 (장치, 배율 99): dashed 9·13, dotted 18·10, dashDot 64·16·18·16, dashDotDot
  64·16·18·16·18·16, mediumDashed 37·15 (13 굵기), mediumDashDot 73·16·18·16, mediumDashDotDot 73·16·18·16·18·16.
  한셀은 점선을 토막마다 따로 그린다.
- 인쇄 격자선(`printOptions/@gridLines`)은 장치 1 굵기 검정. 행·열 머리글(`@headings`)은 너비 = 글꼴 0 숫자 폭 × 8,
  높이 = 기본 행 높이 (배율 반영), 가는 선 상자에 열 이름·행 번호 가운데.

## 8. 칸 글자

- 왼쪽 맞춤: x = 열의 인쇄 왼쪽 경계 + pad px. 배율 100 은 pad 2, 아니면 pad = ceil((2 + 들여쓰기) × z/100 − 0.5) − 1 (반은
  내림: 배율 50·75·99·125·150·200 의 첫 열 자리 0·0·1·1·2·3px). 열 경계는 열마다 `한셀 안의 너비(소수 px) × z` 를 반올림한
  인쇄 px 의 누적이다 (아래).
- 열의 인쇄 너비 (너비 3.3·5·8.43·2·1.5 글자, 배율 50–200 실험): 한셀 COM 의 열 너비는 소수 px (5 글자 = 46.2px, 3.3 글자 =
  32.6px, 8.43 글자 = 73.67px, 22 글자 = 182.2px) 이고 인쇄 열 너비는 이 값에 배율을 곱해 반올림한 정수 px 다 (5 글자: 배율
  50·75·99·125·150·200 에서 23·34·46·58·69·92). 화면 격자 px (반올림한 값)에 배율을 곱하면 3.3 글자 열이 33 → 32.67 → 33
  으로 한셀(32)과 어긋난다. 소수 px 가 .5 근처인 열은 배율에 따라 한셀이 ±1px 다르게 반올림하는 것이 남는다 (3.3 글자 열 배율
  50·125·200: 한셀 17·40·65, rcell 16·41·65).
- 오른쪽·가운데 맞춤 (글자 폭 실험: 9 글꼴, 배율 50–200, 열 너비 142–157px 를 1px 씩): 한셀은 **화면 배치(배율 100)** 에서
  글자 폭 W = 글꼴 advance 의 합 × pt·4/3 (px)로 자리를 정수 px 로 정하고, 그 px 를 배율로 옮긴다. 칸 안 자리 (너비 = 칸의 화면
  px): 오른쪽 맞춤 = 너비 − 3 − 들여쓰기 − round(W), 가운데 = floor(너비/2) − floor(W/2). 배율 100 이면 그 px 그대로
  (실험 모두 장치 1 안), 아니면 칸의 인쇄 시작에서 round(x·z/100 − 1.75) (가운데 1.5) px — 배율 50–150 에서 글자 시작이
  오른쪽 72%·가운데 85% 가 장치 1 안이고 나머지는 1px (6.25) 어긋난다. 이웃 칸으로 넘치는 글자도 같은 규칙 (칸 자신의 너비로
  — 오른쪽 맞춤은 칸 왼쪽 밖에서, 가운데는 양쪽으로 시작: 칸 두 개 폭의 영문·한글·숫자 5 글자열 × 배율 75·99·150 에서 15 개
  가운데 12 개가 장치 1 안, 나머지는 1px). 줄 바꿈 칸·돌린 글자·선택 영역 가운데는 예전 규칙: 글자 끝이 범위 끝 − 4.2px ×
  z/100, 가운데 − 1.3px × z/100, 폭은 글꼴 파일의 advance.
- 세로 (글꼴 9종 × 크기 10 가지 실험): 한 줄 높이 L = 화면 줄 높이표(`metrics.rs`)의 글꼴 높이 × 25/3 × z/100, 크기 S
  (장치). 위 맞춤 기준선 = 위 + L/2 + k·S + c, 아래 맞춤 = 아래 − L/2 + k'·S − c', 가운데 = 가운데 + k''·S + c''. 상수는 줄
  높이표가 같은 글꼴끼리 같다 (맑은 고딕·Arial·Times New Roman: k 0.378 c −9.0, k' 0.425 c' 24.8, k'' 0.386 c'' −11.5 /
  굴림·돋움·바탕·궁서: 0.415 −10.2, 0.434 23.9, 0.423 −13.6 / 함초롬돋움·바탕: 0.386 −9.4, 0.394 21.4, 0.392 −12.4).
  화면에서 글이 행에 들어가면 (행 px ≥ 줄 수 × 줄 높이 px) 아래·가운데 맞춤도 위 맞춤 자리보다 올라가지 않는다 (22px 행의
  아래 맞춤 숫자, 배율 97). 들어가지 않으면 아래에 붙인 채 위로 넘친다 (행 4.5–15pt 실험: 6px 행에는 숫자 아랫부분만 찍힌다).
- 줄 바꿈 줄 간격 = L. 넘치는 글자는 화면과 같은 범위로 이웃 칸까지. 페이지 안 칸의 넘친 글자는 페이지 영역에서 자르지
  않고 넘친 범위만큼 (오른쪽 여백을 지나 종이 끝까지) 찍고, 옆 페이지에는 앞 페이지 칸에서 넘쳐 들어온 글자를 이어 찍되 그
  페이지 영역에서 자른다.
- 오류 값 인쇄(`pageSetup/@errors`): `blank` 은 비우고, `dash` 는 `--`, `NA` 는 `#N/A` (가운데 맞춤).
- 수식 칸은 한셀이 열 때 다시 계산하는 범위에 따라 (값을 틀리게 적은 20 칸 — 값이 없는 칸, 0, 틀린 값, 휘발성 함수 —
  문서를 형식·계산 엔진 번호별로 한셀 COM 에서 읽은 값): XML·xlsx 는 엔진 번호(`calcPr/@hs:hclCalcId`, 없으면 Excel
  `calcId`)가 904(한셀 2024) 이상이면 **저장된 값 그대로** (휘발성 함수도 값이 없으면 빈칸. 하나 예외: 엔진 번호 904 인 말뭉치 probe_fn08
  의 값 없는 수식 32 개 가운데 `RANDBETWEEN(1,1)` 만 한셀 PDF 에 값이 찍혔다 — 따르지 않는다), 903 이하이거나 없으면
  **모두 다시 계산**한다. 레거시·xls 는 0xA101 이 904 면 **휘발성 함수(NOW·TODAY·RAND·RANDBETWEEN·OFFSET·INDIRECT)와 그에
  기대는 칸만** 다시 계산하고 (저장된 값은 그대로), 그보다 낮거나 없으면 (2·100·903 도) 모두. ODS 는 늘 모두. 바이너리 .cell 은
  한셀이 `.bin.cell` 이름으로는 열지 못하고 `.xlsb` 이름의 사본으로는 열어서 (오라클·`bin-as.ps1` 이 쓰는 길) 쟀다:
  BrtCalcProp 의 recalcID 가 0·1 이면 모두, 2 이상 (10·100·903·904·191029) 이면 휘발성 칸과 그에 기대는 칸만. Excel `calcId`
  만 있고 `hs:hclCalcId` 가 없는 XML 은 값 100·904·191029 모두 저장된 값 그대로다. rcell 은 `rcell::print::open_recalc` 로 이 범위를 정하고 `rcell::calc` 로
  계산한다 (`PdfOptions::recalc`, `rcell pdf` 는 자동). 순환 참조·구현하지 않은 함수·해석하지 못한 수식의 칸은 저장된 값
  (한셀 CalculateFull 은 순환 참조에서 멈춘다).
- 글꼴: 문서 글꼴을 시스템에서 찾아(이름 표의 가족 이름, 한글 이름 포함) 부분 집합으로 넣는다. 굵게는 굵은 글꼴 파일
  (맑은 고딕 굵게 = malgunbd.ttf), 없으면 흉내. 글꼴에 없는 글자(Arial 칸의 한글)는 맑은 고딕.

## 9. 머리글·바닥글

- 코드: `&L` `&C` `&R` 구역, `&P` (`&P+n`) `&N` `&D` `&T` `&F` `&A` `&Z` `&&`, `&"글꼴,모양"`, `&크기`, `&B` `&I` `&U` `&E`
  `&S` `&X` `&Y` `&K색`, 한셀 꼴 `&[PAGE NUMBER]`·`&[SHEET]` 등.
- 글꼴 크기는 인쇄 배율과 상관없이 round(pt × 25/3), 기본 글꼴은 글꼴 0. 날짜 `2026-10-28`, 시간 `06:13 오후`, `&Z` 는
  폴더 경로(끝에 `\`).
- 머리글 기준선 = 머리글 여백 + 글꼴 오름(winAscent), 바닥글 = 용지 − 바닥글 여백 − 내림. 왼쪽은 왼쪽 여백, 오른쪽은
  오른쪽 여백에 붙이고 가운데는 두 여백 사이 가운데.
- 쪽 번호 (시트 셋 통합 문서 PDF 실험): `&P` 는 **PDF 의 쪽 차례** (시트가 바뀌어도 이어진다), `&N` 은 PDF 전체 쪽 수다. 시트가
  첫 쪽 번호(`firstPageNumber` + `useFirstPageNumber`)를 주면 그 시트만 `&P` 와 `&N` 에 (값 − 1) 을 더한다 (3·3·4 쪽 시트에
  첫 시트만 5: 5·6·7 / 14, 이어서 4·5·6 / 10, 7·8·9·10 / 10 — 이어지는 시트는 앞 시트의 값을 이어받지 않는다).
- 첫 페이지·짝수 페이지 머리글(`differentFirst`·`differentOddEven`): **첫 쪽 머리글은 PDF 의 첫 쪽**에만 (둘째·셋째 시트의
  첫 쪽은 쪽 번호의 홀짝을 따른다), 홀짝은 찍히는 쪽 번호의 홀짝.
- 날짜·시간 시간대: `RCELL_TZ`(분)가 없으면 +9:00 (한국 표준시).

## 10. 그리기 개체

- 도형·글상자·그림·차트·그룹을 페이지 영역 안에 그린다. 자리는 **칸 경계가 아니라 시트의 절대 화면 px × 배율** (그림·도형
  실험, 배율 60–150, 개체 14 개): 왼쪽·위 = floor(원점 + 절대 px × 6.25 × z/100 + a) − 8 장치, 크기 = ceil(px 크기 × 6.25
  × z/100) 장치. a 는 그림 +0.25, 도형 −0.25 (장치 0.5 안). 절대 px = 앵커 칸의 (배율 100) 시작 + 오프셋 — 한셀 PDF 와 장치
  0.5 안에 모두 같다. 행·열을 배율에 맞춰 반올림한 인쇄 경계(22px 행이 배율 99 에서도 22)와 어긋나므로, 칸 경계에 앵커한
  개체가 배율에 따라 칸과 조금씩 벗어나는 것도 한셀 그대로다. 크기는 두 칸 앵커면 (끝 − 시작), 아니면 `ext`.
- 도형 모양은 화면 렌더러가 만든 SVG 를 그대로 옮긴다 (`render/svgops.rs`: 경로·사각형·선·원·글, 변환, 자르기 사각형 —
  그라데이션·무늬는 첫 색, 불투명도는 흰 바탕과 섞는다). 글상자 글은 원본 txBody 의 문단·줄 간격·여백으로 줄을 짓는다.
- 차트: 한셀 PDF 는 차트를 **비트맵(JPEG)** 으로 찍는다 (페이지에 `/Im Do` 하나, 글자 `Tf` 가 없다). rcell 은 인쇄 크기의 px 로
  벡터로 다시 짠다 (34% 로 인쇄한 차트의 눈금 간격 수가 인쇄 크기를 따른다) — 비트맵과 글자·눈금 자리는 같을 수 없다.
  비트맵의 자리는 개체 상자보다 반 px 씩 넓다: 왼쪽·위 = round(원점 + 절대 px × k − 8.5 − k/2), 크기 = round((px 크기 + 1) × k
  + 1) 장치 (k = 6.25 × z/100; 배율 60·75·99·150 과 앵커 둘에서 장치 1.5 안에 같다). 차트가 여러 페이지에 걸치면 페이지마다
  같은 비트맵을 그 페이지 영역으로 잘라 찍는다.
- 그림은 JPEG 그대로, PNG·BMP (1·4·8 비트 색표, 16·24·32 비트) 는 풀어 넣는다 (알파는 SMask).
- EMF·WMF 그림은 벡터로 (`render/metafile.rs`, 공개 명세의 레코드를 읽는다): 선·다각형·다중 다각형·곡선(16·32비트), 사각형·
  둥근 사각형·타원, 경로(BEGINPATH…FILLPATH), 펜(실선·점선·굵기)·붓, 글꼴·글자 정렬·색·각도, 비트맵(STRETCHDIBITS 등), 세계
  변환·매핑 방식·창/뷰포트, 장치 상태 저장·복원. 호·부채꼴·활꼴·무늬 붓·자르기는 그리지 않는다. 한셀 PDF 실험 (GDI+ 가 만든
  EMF 3 개와 손으로 만든 WMF 를 그림으로 넣어 인쇄): 한셀은 벡터 그대로 그린다. 메타파일 틀(EMF `rclFrame` 을 기준 장치의 px
  로, WMF 는 창 크기) 전체가 그림 상자에 가로·세로 따로 늘어나고, 펜 굵기와 점선은 가로 배율을 따르고, 글자는 글꼴 오름(
  winAscent, 반올림)만큼 내린 기준선에 놓이며 (Arial 24px: 22, 맑은 고딕 28px: 30, Times 20px: 18), 비트맵은 상자 안에 늘어난다
  (한셀은 JPEG 로 다시 압축한다). rcell 은 한셀 PDF 와 꼭짓점 0.12pt (장치 1), 글자 장치 1 안에 같다. 화면 렌더러도 같은 목록을
  SVG 로 바꿔 넣는다 (`metafile::to_svg`).
- 한셀은 레거시 문서에서 읽은 도형의 글을 그리지 않는다 (서식 파일 소개 시트의 레거시 판 PDF 에 글이 없다) — rcell 은
  문서 내용대로 그린다.

## 11. 한셀 PDF 가 따르지 않는 설정

- 메모 인쇄 (`cellComments` 시트 끝에·화면대로): 한셀 PDF 에 메모가 없다. rcell 도 그리지 않는다.
- 흑백 인쇄·간단히 인쇄 (`blackAndWhite`·`draft`): 한셀 PDF 는 색과 채우기를 그대로 그린다. rcell 은 `PdfOptions::
  quality_settings` 를 켜야 따른다 (흑백: 글자·선 검정, 채우기 없음 / 간단히: 채우기 없음).
- 메모·오류 인쇄 설정 자체는 세 형식 모두 읽고 쓴다: 레거시 SETUP fNotes 0x20·fEndNotes 0x200·iErrors 10–11 비트, 바이너리
  BrtPageSetup fNotes 0x20·fEndNotes 0x100·iErrors 9–10 비트 (한셀 저장 대조).

## 12. PDF

- 순수 Rust: `pdf-writer`(PDF 객체), `ttf-parser`(글꼴 읽기), `subsetter`(부분 집합), `zeno`(차트 비트맵의 윤곽 래스터라이저) — 모두 MIT OR Apache-2.0 (zeno 는 Apache-2.0 OR MIT).
- 글꼴은 TrueType 부분 집합을 CIDFontType2 + Identity-H + ToUnicode 로 넣는다 (한셀 PDF 와 같은 꼴). 웹 어셈블리처럼 글꼴
  파일이 없으면 한국어 표준 CID 글꼴(`HYGoThic-Medium`, UniKS-UCS2-H)을 이름만 적는다.
- 선·채우기는 pt 좌표, 글자만 장치 단위 변환 아래 (한셀 PDF 처럼 — 같은 렌더러에서 선 굵기가 같게 그려진다).
- `rcell pdf <문서> <출력.pdf> [--sheet …] [--font …]`, 라이브러리 `rcell::print::workbook_pdf`, 웹 어셈블리
  `rcell_pdf`·`rcell_doc_pdf`·`rcell_font_add`.

## 14. 남은 차이

- 글자 폭: 오른쪽·가운데 맞춤은 화면 글자 폭으로 정수 px 를 정해 한셀과 배율 100 에서 장치 1 안에 같다 (8절). 배율이 다르면
  px 반올림이 1px 어긋나는 글자가 남는다 (오른쪽 28%·가운데 15%) — 한셀의 반올림 규칙을 다 풀지 못했다. 넘친 글자의 길이는
  예전 규칙 (글꼴 advance) 이다.
- 차트: 화면 차트 렌더러를 인쇄 크기로 다시 짠 근사라 축 글자·눈금 자리가 다르다 (서식 파일 차트 페이지의 글자 짝이 적다).
  레거시 3 차원 차트, 레거시 차트의 흰 바탕 상자는 다르게 그린다.
- 그림: EMF·WMF 의 호·부채꼴·활꼴·무늬 붓·자르기, EMF+ 전용 파일(GDI 레코드가 없는 것)은 그리지 않는다. WMF 글자 기준선이
  장치 5 쯤 어긋난다 (글꼴 오름 규칙이 EMF 와 다른 듯하다).
- 저장된 값: 한셀이 열 때 다시 계산하는 범위는 따른다 (3·8절). 바이너리 .cell 은 한셀 COM 이 열지 못해 재지 못했다.
- 한셀이 레거시 문서의 도형 글을 그리지 않는 것은 따르지 않는다 (문서 내용대로 그린다).
- 용지: 페이지 나누기 사실은 A4·B4·A3·A5·B5·Letter·Legal 과 가로 방향으로 쟀다 (2절).
- 한셀 COM: 열 A 하나가 한 페이지면 첫 `VPageBreaks` 위치가 빈 값이다 (정답 대조는 그 자리를 묻지 않는다). 쓰는 범위가
  1,048,576 행인 시트는 한셀이 페이지를 세다 멈추므로 정답이 없다 (rcell 은 `MAX_PAGES` 5000 에서 자른다).
