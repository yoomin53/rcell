# 한셀이 여닫는 그 밖의 형식

> 작성: yoomin53 · 대상: 한셀 2024 (13.0.0.711). `.cell` 세 형식(XML·바이너리·레거시) 밖의 형식 — 무엇을 열고
> 저장하는지, rcell 이 무엇을 읽고 쓰는지, 한셀과 같게 하려고 확인한 규칙.
>
> 근거: 한셀 COM 자동화(`SaveAs` FileFormat 코드를 하나씩, `Workbooks.Open`), 한셀 `불러오기` 대화 상자의 파일 형식
> 목록(UI 자동화로 읽기만), 레지스트리 파일 연결, 형식 라이브러리(`HCell.tlb`)의 `XlFileFormat` 열거. 실험 파일은
> 저장소 밖에 둔다 (한컴 파일은 커밋하지 않는다).

## 2. 한셀이 같은 문서를 다시 연 결과 (한셀 자기 저장의 왕복)

기본 문서(두 시트, 서식이 있는 수·날짜·글·수식·오류·논리값)를 각 형식으로 저장하고 한셀로 다시 열어 XML 로 저장해

바뀐다. `.htm`·`.mht` 는 칸의 줄 바꿈이 행으로 나뉘고 수식이 값이 된다.

## 3. CSV·텍스트 (`src/csv.rs`)

### 3.1 저장 (6 CSV, -4158 탭, 36 PRN)

- **활성 시트 하나**만 쓴다. 코드 페이지 949, 줄 끝 CRLF (마지막 줄 뒤에도).
- **행**: 셀이 있는 행만 쓴다 — 빈 행은 줄도 쓰지 않는다 (Excel 과 다름). 셀로 세는 것: 값·수식이 있는 칸, 서식이 0 이
  아닌 빈 칸, 병합 영역 안의 칸. 서식 0 의 빈 `<c>` 와 높이만 정한 행·숨긴 빈 행은 세지 않는다. 열 서식은 셀이 아니다.
- **열**: CSV 는 A 열부터, 텍스트·PRN 은 셀이 있는 첫 열부터, 셀이 있는 마지막 열까지. 모든 줄이 같은 수의 칸.
- **칸 글**: 화면에 보이는 글 (표시 형식을 적용한 글, 수식은 계산된 값). 일반 서식은 열 너비와 상관없이
  `1.23457E+11`·`0.333333333`, 좁은 열도 `###` 이 아니라 글. 숨긴 행·열도 쓴다. 글자 접두(`'`)는 쓰지 않는다.
- **따옴표**: 칸 글에 구분 문자(`,` 탭 공백)나 `"`·LF·CR 이 있으면 `"` 로 싸고 `"` 는 `""`. PRN 은 공백이 구분
  문자라 공백이 든 칸(앞 공백의 분수 ` 3/4` 포함)을 싸고 쉼표·탭은 싸지 않는다. Excel 의 PRN 과 달리 고정 폭이 아니다.
- **인코딩**: 949 에 없는 글자는 `?` (기본 평면 밖 글자는 `??`). 예외 둘: 숫자의 표시 형식에서 나온 원 기호
  U+20A9 는 0x5C (같은 글자가 글 칸에 있으면 `?`), U+0E0A 는 FE ED (949 에 없는 BMP 글자 54946 자를 한 칸씩 저장해 본
  결과 `?` 가 아닌 유일한 것). `€` 는 949 의 A2 E6.
- 대조: 말뭉치 문서 72개(XML 44·레거시 28) × CSV·텍스트·PRN 216개가 한셀 저장과 바이트까지 같다.

### 3.2 열기

- **인코딩**: BOM(UTF-8, UTF-16 LE/BE) → 없으면 파일 전체가 올바른 UTF-8 이면 UTF-8 (한글이 3만 줄 뒤에 처음 나와도),
  아니면 949. 글은 첫 NUL 에서 끝난다 (BOM 없는 UTF-16 은 949 로 읽혀 `t??`). 949 의 짝이 맞지 않는 두 바이트는 `?` 하나.
- **구분 문자**: 확장자로 — `.csv` 쉼표, `.txt` `.tsv` `.out` 탭 (쉼표 파일도 `.txt` 면 탭). 세미콜론은 구분 문자가 아니다.
  시트 이름은 파일 이름 (확장자 빼고).
- **필드**: `"` 로 시작하면 닫는 `"` 까지 (구분 문자·CR·LF 그대로, `""` 는 `"`), 닫은 뒤의 글은 구분 문자까지 이어
  붙인다 (`"c"d` → `cd`, `"a"  ` → `a  `). 닫지 않으면 파일 끝까지. 중간의 `"` 와 공백 뒤의 `"` 는 글자 (` "g"`).
  줄 끝은 CRLF·LF·CR. 빈 줄은 빈 행, 빈 필드는 빈 칸.
- **긴 필드**: 따옴표 없는 필드는 32759 자마다 잘려 나머지가 **다음 행 A 열**에 들어간다 (딱 32759 자여도 다음 행으로
  넘어간다). 따옴표로 싼 필드는 32767 자까지 남고 나머지는 버려지며, 그 줄의 다음 필드는 한 행 아래 같은 열로 간다.
  글자 수로 센다 (UTF-8 한글도 같다).
- **값**: 셀 입력 규칙(일반 서식 칸)과 같다 — 따옴표로 싸도 같다 (`"123"` 은 수). 셀 입력과 다른 점:
  - 256 자보다 긴 필드는 해석하지 않고 글 + 글자 서식 `@` (49). 숫자 300 자리도 글.
  - 대분수는 수: `1 1/2` → 1.5 (`# ?/?`, 분모 10 이상은 `# ??/??`). 앞 공백은 괜찮고 뒤 공백·음수는 글.
  - `+`·`-` 로 시작하는 글은 수식으로 읽어 보고 (`+1+2` → `=1+2`, `-A1`, `+TRUE`), 문법에 맞지 않으면 글 (`-1 1/2`,
    `-1:2.5`, `-1E-400`). `=` 수식도 문법에 맞지 않으면 글 (`=1+`, `=SUM(`, `==1`, `=1 2`) — 입력처럼 괄호를 닫아 주지 않는다.
  - LF 가 든 글은 줄 바꿈 맞춤 (CR 만 든 글은 그대로).
- 셀 입력과 함께 확인한 규칙 (`src/edit/input.rs`): 자릿점 없는 통화는 통화 형식 — `$123`·`123$`·`1,234$` → 24,
  `$1234.5`·`$5.` → 26, `\123`·`₩123`·`(\123)` → 6, `\0.5` → 8. 통화 기호가 앞에 있고 자릿점이 있으면 3/4 (`$1,234` → 3).
  `$1e3` → 11, `$(123)` → -123 (24). 부호 뒤의 원 기호는 자릿점이 있어야 수 (`-\123` 은 수식 `=-\123` → #NAME?,
  `-\1,500.00` 은 -1500). 전각 `￦123` 은 글. `(5%)` → -0.05 (9). 분:초.소수 `12:34.5` → `mm:ss.0` (47, 분 두 자리까지,
  초 61 미만, 소수는 셋째 자리까지). 지수가 -309 보다 작게 쓰인 수 (`1E-310`, `100E-310`, `4.9E-324`, `1E-400`) 는 글,
  그 안에서 비정규 수가 되면 0 (`1E-309`·`1.5E-308` → 0). 수는 유효숫자 15자리에서 자른다 (`1234567890123456` →
  1.23456789012345E+15).
- 수식 고르기 (`src/edit/refs.rs`): 숫자 바로 앞의 단항 `+` 는 버린다 (`=+1+2` → `=1+2`, `=-+1` → `=-1`, `=++1` → `=+1`;
  `=+A1`·`=+(1)`·`=+-1` 은 그대로).
- 한셀은 칸의 CRLF 를 그대로 들고 있다가 XML 로 저장할 때 LF 마다 CR 을 붙여 `\r\r\n` 으로 쓴다. rcell 은 CR 을
  `&#13;` 로 써서 한셀이 같은 글로 읽게 한다.
- 열기 대조 (HCell(텍스트) 대 HCell(rcell(텍스트))): 손으로 만든 시험 파일 23개(값 141종 × 3 꼴, 구조, 인코딩 12종,
  긴 필드)와 한셀이 말뭉치 문서를 저장한 CSV·TXT 128개 모두 같다 (`NOW()` 의 시각과, 한셀 세션의 기본 프린터를 따르는
  용지 크기는 빼고).

## 4. Excel `.xlsx` (`src/writer.rs` Flavor::Xlsx)

한셀의 `.xlsx` 저장(51)은 XML `.cell` 저장과 **같은 XML** 이다 — `x:` 접두사, `hs:` 확장, `mc:AlternateContent` 를 그대로
두고 다른 것은 통합 문서 콘텐츠 형식(`…spreadsheetml.sheet.main+xml`) 하나다 (같은 세션의 `.cell` 과 파트별 비교:
저장마다 달라지는 SST 차례, 메모 상자 GUID, 그리기 파트 번호, 저장 폴더 `x15ac:absPath` 를 빼면 같다). 다른 점:

- 매크로 프로젝트(`vbsProject.bin`)를 버린다. rcell 도 버린다.
- 구조 잠금 문서는 바이너리처럼 기본 암호(VelvetSweatshop)로 감싼 복합 문서다. rcell 도 감싼다 (`binary::encrypt`).
- 메모 VML 은 `.cell` 과 같은 한셀 꼴. rcell 도 그렇게 쓴다 (전에는 Excel 꼴이었고 한셀이 메모 상자 서식을 잃었다).
- 한셀은 `.xlsx` 에도 `x:abstractNums`(문단 번호 정의)를 쓴다 — CT_Stylesheet 에 없는 요소다. rcell 은 쓰지 않는다
  (한셀은 문단 모양에서 다시 만든다 — 대조에서 같다).

대조: 말뭉치·실험 문서 61개(서식 파일 28, 기능 문서 8, 조건부 서식·필터·개요·그림·보기 9, 차트 15, 매크로 1)에서
HCell(rcell `.xlsx`) 와 HCell(원본) 60개가 같고, 매크로 문서는 HCell(한셀 `.xlsx`) 와 같다. 파트 구성은 한셀 `.xlsx`
와 같다 (그리기·차트·메모 파트 번호만 다르다 — 한셀은 세션 안에서 번호를 이어 간다). 독립 구현 검사: rcell `.xlsx`
61개 모두 OPC 구조(모든 XML 파트가 짝이 맞고, 콘텐츠 형식이 모든 파트를 덮고, 관계 대상이 있다)가 맞고 SheetJS 가
읽은 칸 값이 한셀 `.xlsx` 와 같다. ExcelJS 는 `x:` 접두사를 읽지 못해 한셀 `.xlsx` 도 rcell `.xlsx` 도 열지 못한다
(접두사를 모르는 읽기의 한계 — Excel 은 이름공간을 따른다).

## 5. Excel 97-2003 `.xls` (`src/legacy/xls.rs`)

한셀의 `.xls` 저장(56)은 레거시 `.cell` 저장(-2005)과 **같은 레코드를 BIFF8 꼴로 바꾼 것**이다 — 같은 세션에서 문서
61개를 두 형식으로 저장해 레코드마다 맞대 보면 차트·SST 차례 밖은 규칙 몇 가지로 서로 바뀐다. rcell 도 레거시 쓰기·
읽기를 그대로 쓰고 `/Workbook` 의 레코드만 바꾼다: 쓰기는 레거시로 쓴 뒤 `xls::to_biff8`, 읽기는 `xls::to_hancom` 으로
레거시 레코드를 만든 뒤 레거시 리더. 문서 속성(`SummaryInformation`)은 그대로 담는다. 분석용 명령:
`rcell biff8 X.legacy.cell X.xls` (`--reverse` 는 거꾸로).

### 5.1 레거시 → BIFF8 (쓰기)

- **BOF**: 버전 0x0600, 빌드·연도 `BB 0D CC 07`, 전역 BOF 의 플래그 `00 80 01 00 06 06 00 00`. 시트 BOF 도 같은 빌드.
- **행 번호** u32 → u16 (셀, ROW, PANE, WINDOW2, SELECTION, NOTE, 페이지 나누기, MERGECELLS, CONDFMT·CF12·CFEX·DV·
  HLINK 의 범위, 그리기 앵커). 행 65536·열 256 밖의 칸은 버리고, 그 밖을 가리키는 수식은 값
  `#REF!` 에 토큰 `PtgErr #REF!` 하나 (한셀의 `.xls` 와 같다).
- **문자열**: 레거시는 플래그와 상관없이 UTF-16 — BIFF8 은 플래그 1. 레코드 길이가 8224 를 넘으면 CONTINUE (레거시는
  길이 칸의 0x8000 비트로 길이를 늘린다). SST 는 문자열이 CONTINUE 경계에서 나뉘면 다음 조각 앞에 플래그 바이트,
  EXTSST 는 버킷 하나만 (dsst 8 — 한셀). TXO 의 글과 서식 런은 CONTINUE 둘로, 맞춤 번호를 BIFF8 값으로.
- **FONT·XF**: 한컴 확장(글꼴 78바이트, XF 의 색·문단 연결)을 뗀다. XF 의 들여쓰기는 연결된 문단 모양(0xA001)의 왼쪽
  (오른쪽 맞춤이면 오른쪽) 여백 ÷ 1134. XF 들 뒤에 XFCRC ([MS-OSHARED] 2.4.3.2 CRC, 다항식 0xAF — 한셀 값과 같다),
  그 뒤 XFEXT, DXF (레거시는 XF, XFEXT, STYLE, DXF 차례). 머리글·바닥글의 글꼴 지정은 한셀 꼴로 고쳐 쓴다.
- **한컴 전용 레코드를 뺀다**: 0xA030, 0x0900, 0xA001, 0xA011, 0xA020, 0x009F, 0xB005–0xB00E, 0x7EF0, 0x7EF8 등.
  행 반복(0xB002)은 ROW 로 풀어 쓴다. ROW 는 남은 첫 행부터 32 행씩 묶어 그 행들의 셀 앞에, 빈 행의 colMac 은 256.
- **수식 토큰**: 행 u32 → u16, 열 14비트 → 8비트, 상대 참조(공유 수식·CF·DV)의 행 오프셋은 레거시가 20비트, PtgStr 의
  cch u16 → u8, 길이가 바뀌면 PtgAttr(IF·CHOOSE·건너뛰기)·PtgMem 의 길이를 다시 센다.
- **시트**: WINDOW2 의 머리글 색·확대율 칸과 꼬리, WINDOW2 뒤 PLV, WSBOOL 의 요약 행·열 위치 (레거시에는 쓰지 않는다 —
  모델에서), 하이퍼링크의 도구 설명은 HLINK 의 표시 이름 자리에 플래그 0x02 와 (한셀), 그리기 앵커 22 → 18바이트
  (dx·dy 를 1/32 로), SHEETEXT 는 20바이트 (탭 색 COLORREF 를 뗀다 — 팔레트 번호만 남는다).
- **조건부 서식**: CF 의 DXFN 은 flags2 높은 바이트 0, 글꼴 블록의 이름 플래그 1, 한컴 확장과 차등 서식 번호를 뗀다.
  CFEX 의 DXFN12 는 표준 블록 + XFExtNoFRT (한컴 확장을 머리 모양 `00 00 FF FF 00 00` 으로 찾아 뗀다), CF12 의
  수식·CFVO 토큰을 바꾼다. 맞춤 번호는 레거시 그대로 (표준보다 1 큰 한컴 꼴 — 한셀의 `.xls` 도 그렇다).
- **유효성(DV)**: 빈 글은 NUL 하나, 목록의 쉼표는 NUL + fStrLookup.
- **하이퍼링크**: hlstmfIsAbsolute(0x02) 는 파일 모니커와 `mailto:` 가 아닌 URL 에 켠다 (레거시는 끈다 — 하이퍼링크 종류
  실험: URL·조각 있는 URL·파일·메일·문서 안 위치 다섯 가지가 한셀 `.xls` 와 바이트까지 같다).
- **차트** (5.4절): 레거시는 차트를 한컴 0x7EF0 에만 담는다. `.xls` 는 차트 도형을 그리기의 처음에 넣고 (OfficeArt 종류 0,
  잠금 0x007F = 031E031E, 0x0304 = 0, 0x033F = 00080008, 이름, 앵커, OBJ ot 5 플래그 0x0011) OBJ 뒤에 BIFF8 차트 부분
  스트림을 둔다. 다른 도형의 번호는 차트 뒤로 밀린다.
- **담지 않는 것**: 피벗 표·캐시, 매크로 프로젝트, 묶음 안의 차트. 쓰기 보고에 경고.

### 5.2 BIFF8 → 레거시 (읽기)

위의 거꾸로에 더해, 한셀이 `.xls` 를 열 때 붙이는 것을 만든다 (한셀이 `.xls` 61개를 연 결과):

- CONTINUE 로 나뉜 SST·STRING·TXO 를 잇고, 1바이트 글자를 UTF-16 으로. 시트 안 차트 부분 스트림은 건너뛴다.
- XFEXT 의 색 → 레거시 XF 확장 색 (무늬 배경·채우기·테두리 네 변), XFEXT 의 글자 색이 글꼴과 다르면 그 색의 FONT 를
  더 만들어 XF 가 가리키게 한다.
- FONT 의 한컴 확장: 크기 1/100 pt, 밑줄 위치 아래 + 모양 (두 줄이면 7), 취소선 실선, 외곽선 비트면 외곽선 실선, 그림자
  위치 10·10, 그림자 색 C0C0C0, 상대 크기·장평 100.
- 가로 맞춤이 일반이 아닌 셀 서식(왼쪽 맞춤은 들여쓰기가 있을 때만)에 기본 문단 모양 (줄 간격 75 betweenLines, 영문
  keepWord·한글 breakWord, 기준선, 여백 = 들여쓰기 × 1134).
- 조건부 서식: CF 의 DXFN(+ CFEX 의 XFExtNoFRT 색)으로 레거시 차등 서식 표(0x088D)를 만들어 번호를 단다 — 서식 블록이
  없는 규칙도 빈 차등 서식 (BIFF8 CF 에는 차등 서식 번호가 없다).
- 값 목록 필터: AUTOFILTER12 + CONTINUEFRT12 의 값 → 레거시 0x009F.
- 하이퍼링크의 표시 이름 → 도구 설명 (HLINKTOOLTIP 이 없을 때 — 한셀이 그렇게 읽는다).
- 표 스타일 표가 없으면 새 문서의 기본 표·피벗 스타일 (`TableStyleMedium2`, `PivotStyleLight16`).

### 5.4 차트 부분 스트림 (`src/legacy/xls_chart.rs`)

한셀의 `.xls` 차트는 레코드 몇 가지의 틀이다 (차트 문서 17개·차트 23개): BOF dt 0x20 (빌드 `BB 0D CC 07`), 빈
HEADER·FOOTER, SETUP, Chart (자리 0), SCL 1/1, PlotGrowth, 차트 영역 Frame (자동 선·흰 채우기), 계열마다 Series + BRAI 넷
(이름·값·항목·거품) + SeriesText + DataFormat (Chart3DBarShape, 선·채우기가 있으면 LineFormat·AreaFormat — 색 번호는
팔레트에서 가장 가까운 색) + SerToCrt, ShtProps, DefaultText + Text, AxesUsed, AxisParent (축마다 Axis + CatSerRange·AxcExt
또는 ValueRange + Tick + AxisLine·LineFormat, 주 눈금선이면 AxisLine 1 + LineFormat), PlotArea, ChartFormat (varyColors),
종류 레코드 (Bar 의 겹침은 모델의 `overlap` 의 부호를 바꾼 값, 누적 0x02, 가로 0x01 / Line / Area / Pie / Scatter), CrtLink,
3차원이면 Chart3d (회전 Y, X, 원근 30, 높이·깊이 100, 간격 150), 범례 (자리 0 아래, 3 오른쪽 …), 제목 Text + SeriesText +
ObjectLink 1, 값 캐시 (DIMENSIONS, SIIndex 2 의 LABEL = 항목 글, SIIndex 1 의 NUMBER = 값 — 행 = 점, 열 = 계열), 끝에
한컴 0x7EF8 (`ff ff ff ff`).

- 축 Tick: 주·보조 눈금 (없음 0, 안 1, 밖 2, 교차 3), 이름표 자리 (없음 0, 아래 1, 위 2, 옆 3). 축 선 LineFormat 의 플래그는
  보이면 5, 지운 축이면 0.
- 계열 값: 캐시가 있으면 캐시, 없으면 참조하는 칸 (항목은 칸에 보이는 글). BRAI 값의 ifmt 는 캐시 형식이 내장 형식이면
  그 번호. 참조가 깨진 계열(`#REF`)은 값 BRAI 가 토큰 없는 참조, 항목이 없으면 항목 BRAI 종류 0, 항목 캐시 SIIndex 2 를
  쓰지 않는다.
- 한셀은 차트마다 FONT 를 더 쓴다 (10pt 보통, 제목이 있으면 12pt 굵게 둘) — 어디서도 가리키지 않아 rcell 은 쓰지 않는다
  (한셀이 연 결과가 같다).

읽기는 이 부분 스트림을 한셀이 `.xls` 를 열어 XML 로 쓰는 차트의 꼴로 바꿔 XML 차트 리더로 읽는다: 차트 영역 흰 채우기 +
검정 1pt 선, 그림 영역 채우기·선 없음, 범례 흰 채우기, 축 글자 = 문서 기본 글꼴 (FONT 0 의 이름·크기), 제목 10pt,
3차원 회전은 Chart3d 와 상관없이 X 15·Y 20, 축의 눈금 표시는 늘 밖/없음 (이름표 자리만 Tick 에서), 누적 막대면 축마다
`0%` 표시 형식 (원본에 연결 안 함), 계열 선은 기본 검정 0.75pt, LineFormat 이 있으면 1pt 와 색 번호의 팔레트 색, 채우기도
색 번호의 팔레트 색, 값 캐시 형식은 값 칸의 서식 (`G/표준`, 따옴표·`\` 를 벗기고 `[빨강]`), 값 참조가 없는 계열은 버린다.
차트 도형의 잠금은 읽지 않는다.

### 5.3 대조

- **레코드**: 한셀 레거시 61개를 rcell 이 바꾼 것 대 한셀 `.xls`: 차트 레코드(0x1002 …)·SST 차례·EXTSST 위치를 빼면
  같다. 조건부 서식 CF 46·CF12 4·CFEX 48 모두 바이트까지 같다.
- **쓰기** (HCell(rcell `.xls`) 대 HCell(한셀 `.xls`), 원본은 같은 `.cell`): 한셀이 61개를 모두 열고 **59개가 같다**.
  차트 부분 스트림은 차트 23개 모두 한셀 `.xls` 와 바이트까지 같다. 남은 것: 차등 서식의 테마 색 밝기 1 차이 2
  (`ffb689`/`ffb589`, `b0c0ea`/`b0c1ea` — 레거시 쓰기의 색 계산과 같은 원인, 7절).
- **읽기** (rcell(한셀 `.xls`) 대 HCell(한셀 `.xls`)): **31/61** 같다, 도형 글을 빼면 52/61 (차트 문서 17개 모두 같다).
  남은 것은 대부분 한셀의 `.xls` 읽기가 잃는 것이다 — rcell 은 원본대로 읽는다:
  - 도형 글상자의 글 (한셀은 비운다), 차트가 든 `.xls` 의 그리기 (한셀은 자리 0 의 도형 여러 개를 만든다),
  - 조건부 서식 차등 서식의 세로 맞춤·가로 분산 (한셀은 잃고 같은 규칙을 합친다), 평균 규칙의 '아래', 위·아래 규칙의
    백분율, 데이터 막대 x14 확장의 기본값, 값 목록 필터의 백분율,
  - 행·열 범위를 넘는 참조의 캐시 값 (한셀은 다시 계산해 `#REF!`).
- **왕복** (`tests/other_formats.rs`, 말뭉치): 한셀 레거시 48개 → `.xls` → 읽기 = 레거시 읽기 (차트·도형 앵커 밖).
  `.xls` 가 담지 못하는 것만 다르다 — 레거시 DXFN 의 안쪽 가로·세로 선, 값 목록 필터의 빈 칸, 실선이 아닌 한컴
  외곽선·윗줄, 탭 색 (팔레트 번호), 서식 없는 CF 규칙 (빈 차등 서식), HLINK 표시 이름 (도구 설명이 된다). 한셀의
  `.xls` 도 같은 것을 잃는다. 그리기 앵커의 dx·dy 는 1/32 로 줄어 1 픽셀까지 어긋난다.

Excel 이 쓴 `.xls` 와의 대조는 하지 못했다 (Excel 이 없다). 표준과 다른 한셀의 꼴(차등 서식 맞춤 번호, HLINK 표시
이름의 쓰임)은 한셀이 쓴 `.xls` 를 기준으로 했다.

## 6. 넥셀 `.nxl` (`xls::to_nxl`, `legacy::write_nxl`, `src/legacy/vbs.rs`)

한셀의 넥셀 저장(-2003)은 **BIFF8 틀(BOF 0x0600, 16비트 행, 플래그가 있는 문자열)에 한컴 꼴을 섞은 것**이다: FONT 는
BIFF8 FONT + 한컴 확장 플래그 0 (확장 없음), XF 는 레거시와 같은 한컴 확장(54바이트 이상), 문단 모양(0xA001·0xA011)과
0x0900·COUNTRY 가 있고 XFCRC·표 스타일·PLV·DXF·CF12·CFEX 가 없다. BOF 의 빌드·연도는 `01 01 D8 07` (플래그 없음). 그
밖에 레거시와 같은 것: FONT·XF 의 한컴 확장(FONT 의 이름 플래그만 1), SETUP, 머리글·바닥글 (글 플래그만 1), WINDOW2 의
머리글 색 0·꼬리 0x80000000, 탭 색 COLORREF. 차트는 레거시와 같은 한컴 0x7EF0 (CONTINUE 로 나눔) — 앵커와 수식의 행이
16비트, 앵커 dx·dy 는 1/32, 예약 11바이트의 끝 바이트 1.

- **하이퍼링크**: Ref8U + CLSID + 2 뒤에 종류 u32 (1 URL, 2 문서 안 위치, 3 메일, 5 파일), u32 3, 주소와 도구 설명 (u32 글자
  수 + 플래그 + 글자). 문서 안 위치는 주소가 비어 있다 (넥셀은 위치를 담지 않는다).
- **매크로** `/_VBS_PROJECT`: 머리 256바이트는 `_W` 와 같고, 글은 길이 (0xFF + u16) + 코드 페이지 949, 줄 끝 CRLF,
  `CLASS 이름` 줄의 글과 `End Class` 줄이 없고 앞에 빈 글이 하나 더 있다 (한셀은 되읽을 때 `CLASS CLS_GM_MODULE` 을 붙인다 —
  표본 하나).
- **조건부 서식**: 넥셀 CF 는 DXFN 대신 124바이트 고정 블록 (글꼴 굵기·밑줄·색 번호 …) 이고 CONDFMT 의 nID 칸은 1 —
  한셀도 넥셀 CF 를 읽으면 규칙 종류를 잃는다 (모두 cellIs lessThan). rcell 은 BIFF8 CF 를 쓴다 (풀지 못한 것).

대조 (한셀이 말뭉치 61개를 `.nxl` 로 저장한 것): **읽기** rcell 대 한셀 **30/61**, 도형 글을 빼면 49/61 (남은 것은 `.xls`
와 같은 한셀의 읽기 손실). **쓰기** HCell(rcell `.nxl`) 대 HCell(한셀 `.nxl`) **57/61** — 남은 것: 넥셀 조건부 서식 3,
꺾은선 계열의 표식 1 (레거시 차트 쓰기). 하이퍼링크 종류 실험 다섯 가지는 읽기·쓰기 모두 한셀과 바이트까지 같다.
`.nxt`·`.nxk`·`.nav` 는 대화 상자 목록의 같은 계열 확장자다 (따로 대조하지 않았다).

## 7. 테마 색 밝기(tint) — 풀지 못한 것

레거시 쓰기는 테마 색 + 밝기를 RGB 로 바꿔 차등 서식(0x088D)·확장 색에 쓴다. 한셀의 계산과 같게 하려고 테마 색 10가지 ×
밝기 22가지 = 220개를 한셀이 레거시로 저장한 RGB 와 맞대 보았다 (차등 서식 22개짜리 실험 문서 10개): ECMA-376 의 HLS 실수
계산 그대로면 181개가 같고, 밝기를 32비트 실수로 다루면 회색 44개가 모두 맞는다 (`0.9 × 255` 가 229 — 한셀은 밝기를
f32 로 들고 있다). 남은 38개는 채도 있는 색의 한 채널이 1 다르다 (`FAF3DB` +0.05 → 한셀 `faf3dc`, 실수 계산 `faf4dd`).
HLS 정수 단계(240·255·256), 반올림·내림 조합을 찾아보았지만 220개를 모두 맞추는 식은 찾지 못했다 (가장 많이 189개).
rcell 은 지금의 실수 계산을 그대로 둔다 — `.xls` 쓰기 대조의 남은 2개가 이것이다.

## 8. ODF `.ods` (`src/ods.rs`)

한셀의 `.ods` 저장(60)은 `content.xml`·`styles.xml`·`meta.xml`·`settings.xml`·매니페스트로 `mimetype` 이 없다. 수식은
`of:=` 뒤에 A1 참조를 그대로 (ODF 표준의 `[.A1]` 꼴이 아니다), 인수 구분 `;`, 다른 시트 참조는 `#REF.` 로 잃는다. 표시
형식이 빈 글인 수식 칸(값 `""` 이나 0 을 감추는 형식)은 쓰지 않는다. 한셀의 `.ods` 읽기는 표시 형식을 모두 잃고, 논리값
칸을 `ISLOGICAL(값)` 수식(값은 늘 TRUE)으로, 참조의 `$` 를 버리고, `시트.A1` 의 시트를 버린다.

rcell 은 값·수식·구조만 옮긴다 — 시트, 칸 값 (수·글·논리·날짜·시간), 수식 (괄호 참조와 한셀 꼴의 맨 참조·`시트.A1`·
`#REF.` 를 읽고, 한셀 꼴로 쓰되 다른 시트 참조는 표준 `[시트.A1:.B2]`), 병합, 열 너비·숨김, 행 높이·숨김, 이름 정의.
값이 없는 수식은 다시 계산해 쓴다. 칸 서식은 읽지도 쓰지도 않는다 (한셀도 잃는다).

대조 (한셀이 말뭉치 56개를 `.ods` 로 저장한 것 — 셋은 한셀이 자기 `.ods` 를 열다 멈춘다, 칸 값·수식만 비교):
- **읽기** rcell 대 한셀 **33/56**. 남은 23개는 위의 한셀 읽기 결함 (논리값 19, `$` 3, 다른 시트 참조·지수 표기 1) —
  rcell 은 따라 하지 않는다.
- **쓰기** HCell(rcell `.ods`) 대 HCell(한셀 `.ods`) **27/56**. 남은 것은 한셀이 `.ods` 에 쓰지 않는 빈 표시 수식 칸
  (rcell 은 수식을 남긴다), 다른 시트 참조, 계산 차이 (INDEX 1).
