# 한셀이 여닫는 그 밖의 형식

> 작성: yoomin53 · 대상: 한셀 2024 (13.0.0.711). `.cell` 세 형식(XML·바이너리·레거시) 밖의 형식 — 무엇을 열고
> 저장하는지, rcell 이 무엇을 읽고 쓰는지, 한셀과 같게 하려고 확인한 규칙.
>
> 근거: 한셀 COM 자동화(`SaveAs` FileFormat 코드를 하나씩, `Workbooks.Open`), 한셀 `불러오기` 대화 상자의 파일 형식
> 목록(UI 자동화로 읽기만), 레지스트리 파일 연결, 형식 라이브러리(`HCell.tlb`)의 `XlFileFormat` 열거. 실험 파일은
> 저장소 밖에 둔다 (한컴 파일은 커밋하지 않는다).

## 2. 한셀이 같은 문서를 다시 연 결과 (한셀 자기 저장의 왕복)

기본 문서(두 시트, 서식이 있는 수·날짜·글·수식·오류·논리값)를 각 형식으로 저장하고 한셀로 다시 열어 XML 로 저장해

바뀐다. `.htm`·`.mht` 는 칸의 줄 바꿈이 행으로 나뉘고 수식이 값이 된다.

## 3. CSV·텍스트 (`src/csv.rs`)

### 3.1 저장 (6 CSV, -4158 탭, 36 PRN)

- **활성 시트 하나**만 쓴다. 코드 페이지 949, 줄 끝 CRLF (마지막 줄 뒤에도).
- **행**: 셀이 있는 행만 쓴다 — 빈 행은 줄도 쓰지 않는다 (Excel 과 다름). 셀로 세는 것: 값·수식이 있는 칸, 서식이 0 이
  아닌 빈 칸, 병합 영역 안의 칸. 서식 0 의 빈 `<c>` 와 높이만 정한 행·숨긴 빈 행은 세지 않는다. 열 서식은 셀이 아니다.
- **열**: CSV 는 A 열부터, 텍스트·PRN 은 셀이 있는 첫 열부터, 셀이 있는 마지막 열까지. 모든 줄이 같은 수의 칸.
- **칸 글**: 화면에 보이는 글 (표시 형식을 적용한 글, 수식은 계산된 값). 일반 서식은 열 너비와 상관없이
  `1.23457E+11`·`0.333333333`, 좁은 열도 `###` 이 아니라 글. 숨긴 행·열도 쓴다. 글자 접두(`'`)는 쓰지 않는다.
- **따옴표**: 칸 글에 구분 문자(`,` 탭 공백)나 `"`·LF·CR 이 있으면 `"` 로 싸고 `"` 는 `""`. PRN 은 공백이 구분
  문자라 공백이 든 칸(앞 공백의 분수 ` 3/4` 포함)을 싸고 쉼표·탭은 싸지 않는다. Excel 의 PRN 과 달리 고정 폭이 아니다.
- **인코딩**: 949 에 없는 글자는 `?` (기본 평면 밖 글자는 `??`). 예외 둘: 숫자의 표시 형식에서 나온 원 기호
  U+20A9 는 0x5C (같은 글자가 글 칸에 있으면 `?`), U+0E0A 는 FE ED (949 에 없는 BMP 글자 54946 자를 한 칸씩 저장해 본
  결과 `?` 가 아닌 유일한 것). `€` 는 949 의 A2 E6.
- 대조: 말뭉치 문서 72개(XML 44·레거시 28) × CSV·텍스트·PRN 216개가 한셀 저장과 바이트까지 같다.

### 3.2 열기

- **인코딩**: BOM(UTF-8, UTF-16 LE/BE) → 없으면 파일 전체가 올바른 UTF-8 이면 UTF-8 (한글이 3만 줄 뒤에 처음 나와도),
  아니면 949. 글은 첫 NUL 에서 끝난다 (BOM 없는 UTF-16 은 949 로 읽혀 `t??`). 949 의 짝이 맞지 않는 두 바이트는 `?` 하나.
- **구분 문자**: 확장자로 — `.csv` 쉼표, `.txt` `.tsv` `.out` 탭 (쉼표 파일도 `.txt` 면 탭). 세미콜론은 구분 문자가 아니다.
  시트 이름은 파일 이름 (확장자 빼고).
- **필드**: `"` 로 시작하면 닫는 `"` 까지 (구분 문자·CR·LF 그대로, `""` 는 `"`), 닫은 뒤의 글은 구분 문자까지 이어
  붙인다 (`"c"d` → `cd`, `"a"  ` → `a  `). 닫지 않으면 파일 끝까지. 중간의 `"` 와 공백 뒤의 `"` 는 글자 (` "g"`).
  줄 끝은 CRLF·LF·CR. 빈 줄은 빈 행, 빈 필드는 빈 칸.
- **긴 필드**: 따옴표 없는 필드는 32759 자마다 잘려 나머지가 **다음 행 A 열**에 들어간다 (딱 32759 자여도 다음 행으로
  넘어간다). 따옴표로 싼 필드는 32767 자까지 남고 나머지는 버려지며, 그 줄의 다음 필드는 한 행 아래 같은 열로 간다.
  글자 수로 센다 (UTF-8 한글도 같다).
- **값**: 셀 입력 규칙(일반 서식 칸)과 같다 — 따옴표로 싸도 같다 (`"123"` 은 수). 셀 입력과 다른 점:
  - 256 자보다 긴 필드는 해석하지 않고 글 + 글자 서식 `@` (49). 숫자 300 자리도 글.
  - 대분수는 수: `1 1/2` → 1.5 (`# ?/?`, 분모 10 이상은 `# ??/??`). 앞 공백은 괜찮고 뒤 공백·음수는 글.
  - `+`·`-` 로 시작하는 글은 수식으로 읽어 보고 (`+1+2` → `=1+2`, `-A1`, `+TRUE`), 문법에 맞지 않으면 글 (`-1 1/2`,
    `-1:2.5`, `-1E-400`). `=` 수식도 문법에 맞지 않으면 글 (`=1+`, `=SUM(`, `==1`, `=1 2`) — 입력처럼 괄호를 닫아 주지 않는다.
  - LF 가 든 글은 줄 바꿈 맞춤 (CR 만 든 글은 그대로).
- 셀 입력과 함께 확인한 규칙 (`src/edit/input.rs`): 자릿점 없는 통화는 통화 형식 — `$123`·`123$`·`1,234$` → 24,
  `$1234.5`·`$5.` → 26, `\123`·`₩123`·`(\123)` → 6, `\0.5` → 8. 통화 기호가 앞에 있고 자릿점이 있으면 3/4 (`$1,234` → 3).
  `$1e3` → 11, `$(123)` → -123 (24). 부호 뒤의 원 기호는 자릿점이 있어야 수 (`-\123` 은 수식 `=-\123` → #NAME?,
  `-\1,500.00` 은 -1500). 전각 `￦123` 은 글. `(5%)` → -0.05 (9). 분:초.소수 `12:34.5` → `mm:ss.0` (47, 분 두 자리까지,
  초 61 미만, 소수는 셋째 자리까지). 지수가 -309 보다 작게 쓰인 수 (`1E-310`, `100E-310`, `4.9E-324`, `1E-400`) 는 글,
  그 안에서 비정규 수가 되면 0 (`1E-309`·`1.5E-308` → 0). 수는 유효숫자 15자리에서 자른다 (`1234567890123456` →
  1.23456789012345E+15).
- 수식 고르기 (`src/edit/refs.rs`): 숫자 바로 앞의 단항 `+` 는 버린다 (`=+1+2` → `=1+2`, `=-+1` → `=-1`, `=++1` → `=+1`;
  `=+A1`·`=+(1)`·`=+-1` 은 그대로).
- 한셀은 칸의 CRLF 를 그대로 들고 있다가 XML 로 저장할 때 LF 마다 CR 을 붙여 `\r\r\n` 으로 쓴다. rcell 은 CR 을
  `&#13;` 로 써서 한셀이 같은 글로 읽게 한다.
- 열기 대조 (HCell(텍스트) 대 HCell(rcell(텍스트))): 손으로 만든 시험 파일 23개(값 141종 × 3 꼴, 구조, 인코딩 12종,
  긴 필드)와 한셀이 말뭉치 문서를 저장한 CSV·TXT 128개 모두 같다 (`NOW()` 의 시각과, 한셀 세션의 기본 프린터를 따르는
  용지 크기는 빼고).

## 4. Excel `.xlsx` (`src/writer.rs` Flavor::Xlsx)

한셀의 `.xlsx` 저장(51)은 XML `.cell` 저장과 **같은 XML** 이다 — `x:` 접두사, `hs:` 확장, `mc:AlternateContent` 를 그대로
두고 다른 것은 통합 문서 콘텐츠 형식(`…spreadsheetml.sheet.main+xml`) 하나다 (같은 세션의 `.cell` 과 파트별 비교:
저장마다 달라지는 SST 차례, 메모 상자 GUID, 그리기 파트 번호, 저장 폴더 `x15ac:absPath` 를 빼면 같다). 다른 점:

- 매크로 프로젝트(`vbsProject.bin`)를 버린다. rcell 도 버린다.
- 구조 잠금 문서는 바이너리처럼 기본 암호(VelvetSweatshop)로 감싼 복합 문서다. rcell 도 감싼다 (`binary::encrypt`).
- 메모 VML 은 `.cell` 과 같은 한셀 꼴. rcell 도 그렇게 쓴다 (전에는 Excel 꼴이었고 한셀이 메모 상자 서식을 잃었다).
- 한셀은 `.xlsx` 에도 `x:abstractNums`(문단 번호 정의)를 쓴다 — CT_Stylesheet 에 없는 요소다. rcell 은 쓰지 않는다
  (한셀은 문단 모양에서 다시 만든다 — 대조에서 같다).

대조: 말뭉치·실험 문서 61개(서식 파일 28, 기능 문서 8, 조건부 서식·필터·개요·그림·보기 9, 차트 15, 매크로 1)에서
HCell(rcell `.xlsx`) 와 HCell(원본) 60개가 같고, 매크로 문서는 HCell(한셀 `.xlsx`) 와 같다. 파트 구성은 한셀 `.xlsx`
와 같다 (그리기·차트·메모 파트 번호만 다르다 — 한셀은 세션 안에서 번호를 이어 간다). 독립 구현 검사: rcell `.xlsx`
61개 모두 OPC 구조(모든 XML 파트가 짝이 맞고, 콘텐츠 형식이 모든 파트를 덮고, 관계 대상이 있다)가 맞고 SheetJS 가
읽은 칸 값이 한셀 `.xlsx` 와 같다. ExcelJS 는 `x:` 접두사를 읽지 못해 한셀 `.xlsx` 도 rcell `.xlsx` 도 열지 못한다
(접두사를 모르는 읽기의 한계 — Excel 은 이름공간을 따른다).

## 5. Excel 97-2003 `.xls` (`src/legacy/xls.rs`)

한셀의 `.xls` 저장(56)은 레거시 `.cell` 저장(-2005)과 **같은 레코드를 BIFF8 꼴로 바꾼 것**이다 — 같은 세션에서 문서
61개를 두 형식으로 저장해 레코드마다 맞대 보면 차트·SST 차례 밖은 규칙 몇 가지로 서로 바뀐다. rcell 도 레거시 쓰기·
읽기를 그대로 쓰고 `/Workbook` 의 레코드만 바꾼다: 쓰기는 레거시로 쓴 뒤 `xls::to_biff8`, 읽기는 `xls::to_hancom` 으로
레거시 레코드를 만든 뒤 레거시 리더. 문서 속성(`SummaryInformation`)은 그대로 담는다. 분석용 명령:
`rcell biff8 X.legacy.cell X.xls` (`--reverse` 는 거꾸로).

### 5.1 레거시 → BIFF8 (쓰기)

- **BOF**: 버전 0x0600, 빌드·연도 `BB 0D CC 07`, 전역 BOF 의 플래그 `00 80 01 00 06 06 00 00`. 시트 BOF 도 같은 빌드.
- **행 번호** u32 → u16 (셀, ROW, PANE, WINDOW2, SELECTION, NOTE, 페이지 나누기, MERGECELLS, CONDFMT·CF12·CFEX·DV·
  HLINK 의 범위, 그리기 앵커). 행 65536·열 256 밖의 칸은 버리고, 그 밖을 가리키는 수식은 값
  `#REF!` 에 토큰 `PtgErr #REF!` 하나 (한셀의 `.xls` 와 같다).
- **문자열**: 레거시는 플래그와 상관없이 UTF-16 — BIFF8 은 플래그 1. 레코드 길이가 8224 를 넘으면 CONTINUE (레거시는
  길이 칸의 0x8000 비트로 길이를 늘린다). SST 는 문자열이 CONTINUE 경계에서 나뉘면 다음 조각 앞에 플래그 바이트,
  EXTSST 는 버킷 하나만 (dsst 8 — 한셀). TXO 의 글과 서식 런은 CONTINUE 둘로, 맞춤 번호를 BIFF8 값으로.
- **FONT·XF**: 한컴 확장(글꼴 78바이트, XF 의 색·문단 연결)을 뗀다. XF 의 들여쓰기는 연결된 문단 모양(0xA001)의 왼쪽
  (오른쪽 맞춤이면 오른쪽) 여백 ÷ 1134. XF 들 뒤에 XFCRC ([MS-OSHARED] 2.4.3.2 CRC, 다항식 0xAF — 한셀 값과 같다),
  그 뒤 XFEXT, DXF (레거시는 XF, XFEXT, STYLE, DXF 차례). 머리글·바닥글의 글꼴 지정은 한셀 꼴로 고쳐 쓴다.
- **한컴 전용 레코드를 뺀다**: 0xA030, 0x0900, 0xA001, 0xA011, 0xA020, 0x009F, 0xB005–0xB00E, 0x7EF0, 0x7EF8 등.
  행 반복(0xB002)은 ROW 로 풀어 쓴다. ROW 는 남은 첫 행부터 32 행씩 묶어 그 행들의 셀 앞에, 빈 행의 colMac 은 256.
- **수식 토큰**: 행 u32 → u16, 열 14비트 → 8비트, 상대 참조(공유 수식·CF·DV)의 행 오프셋은 레거시가 20비트, PtgStr 의
  cch u16 → u8, 길이가 바뀌면 PtgAttr(IF·CHOOSE·건너뛰기)·PtgMem 의 길이를 다시 센다.
- **시트**: WINDOW2 의 머리글 색·확대율 칸과 꼬리, WINDOW2 뒤 PLV, WSBOOL 의 요약 행·열 위치 (레거시에는 쓰지 않는다 —
  모델에서), 하이퍼링크의 도구 설명은 HLINK 의 표시 이름 자리에 플래그 0x02 와 (한셀), 그리기 앵커 22 → 18바이트
  (dx·dy 를 1/32 로), SHEETEXT 는 20바이트 (탭 색 COLORREF 를 뗀다 — 팔레트 번호만 남는다).
- **조건부 서식**: CF 의 DXFN 은 flags2 높은 바이트 0, 글꼴 블록의 이름 플래그 1, 한컴 확장과 차등 서식 번호를 뗀다.
  CFEX 의 DXFN12 는 표준 블록 + XFExtNoFRT (한컴 확장을 머리 모양 `00 00 FF FF 00 00` 으로 찾아 뗀다), CF12 의
  수식·CFVO 토큰을 바꾼다. 맞춤 번호는 레거시 그대로 (표준보다 1 큰 한컴 꼴 — 한셀의 `.xls` 도 그렇다).
- **유효성(DV)**: 빈 글은 NUL 하나, 목록의 쉼표는 NUL + fStrLookup.
- **하이퍼링크**: hlstmfIsAbsolute(0x02) 는 파일 모니커와 `mailto:` 가 아닌 URL 에 켠다 (레거시는 끈다 — 하이퍼링크 종류
  실험: URL·조각 있는 URL·파일·메일·문서 안 위치 다섯 가지가 한셀 `.xls` 와 바이트까지 같다).
- **차트** (5.4절): 레거시는 차트를 한컴 0x7EF0 에만 담는다. `.xls` 는 차트 도형을 그리기의 처음에 넣고 (OfficeArt 종류 0,
  잠금 0x007F = 031E031E, 0x0304 = 0, 0x033F = 00080008, 이름, 앵커, OBJ ot 5 플래그 0x0011) OBJ 뒤에 BIFF8 차트 부분
  스트림을 둔다. 다른 도형의 번호는 차트 뒤로 밀린다.
- **담지 않는 것**: 피벗 표·캐시, 매크로 프로젝트, 묶음 안의 차트. 쓰기 보고에 경고.

### 5.2 BIFF8 → 레거시 (읽기)

위의 거꾸로에 더해, 한셀이 `.xls` 를 열 때 붙이는 것을 만든다 (한셀이 `.xls` 61개를 연 결과):

- CONTINUE 로 나뉜 SST·STRING·TXO 를 잇고, 1바이트 글자를 UTF-16 으로. 시트 안 차트 부분 스트림은 건너뛴다.
- XFEXT 의 색 → 레거시 XF 확장 색 (무늬 배경·채우기·테두리 네 변), XFEXT 의 글자 색이 글꼴과 다르면 그 색의 FONT 를
  더 만들어 XF 가 가리키게 한다.
- FONT 의 한컴 확장: 크기 1/100 pt, 밑줄 위치 아래 + 모양 (두 줄이면 7), 취소선 실선, 외곽선 비트면 외곽선 실선, 그림자
  위치 10·10, 그림자 색 C0C0C0, 상대 크기·장평 100.
- 가로 맞춤이 일반이 아닌 셀 서식(왼쪽 맞춤은 들여쓰기가 있을 때만)에 기본 문단 모양 (줄 간격 75 betweenLines, 영문
  keepWord·한글 breakWord, 기준선, 여백 = 들여쓰기 × 1134).
- 조건부 서식: CF 의 DXFN(+ CFEX 의 XFExtNoFRT 색)으로 레거시 차등 서식 표(0x088D)를 만들어 번호를 단다 — 서식 블록이
  없는 규칙도 빈 차등 서식 (BIFF8 CF 에는 차등 서식 번호가 없다).
- 값 목록 필터: AUTOFILTER12 + CONTINUEFRT12 의 값 → 레거시 0x009F.
- 하이퍼링크의 표시 이름 → 도구 설명 (HLINKTOOLTIP 이 없을 때 — 한셀이 그렇게 읽는다).
- 표 스타일 표가 없으면 새 문서의 기본 표·피벗 스타일 (`TableStyleMedium2`, `PivotStyleLight16`).

### 5.4 차트 부분 스트림 (`src/legacy/xls_chart.rs`)

한셀의 `.xls` 차트는 레코드 몇 가지의 틀이다 (차트 문서 17개·차트 23개): BOF dt 0x20 (빌드 `BB 0D CC 07`), 빈
HEADER·FOOTER, SETUP, Chart (자리 0), SCL 1/1, PlotGrowth, 차트 영역 Frame (자동 선·흰 채우기), 계열마다 Series + BRAI 넷
(이름·값·항목·거품) + SeriesText + DataFormat (Chart3DBarShape, 선·채우기가 있으면 LineFormat·AreaFormat — 색 번호는
팔레트에서 가장 가까운 색) + SerToCrt, ShtProps, DefaultText + Text, AxesUsed, AxisParent (축마다 Axis + CatSerRange·AxcExt
또는 ValueRange + Tick + AxisLine·LineFormat, 주 눈금선이면 AxisLine 1 + LineFormat), PlotArea, ChartFormat (varyColors),
종류 레코드 (Bar 의 겹침은 모델의 `overlap` 의 부호를 바꾼 값, 누적 0x02, 가로 0x01 / Line / Area / Pie / Scatter), CrtLink,
3차원이면 Chart3d (회전 Y, X, 원근 30, 높이·깊이 100, 간격 150), 범례 (자리 0 아래, 3 오른쪽 …), 제목 Text + SeriesText +
ObjectLink 1, 값 캐시 (DIMENSIONS, SIIndex 2 의 LABEL = 항목 글, SIIndex 1 의 NUMBER = 값 — 행 = 점, 열 = 계열), 끝에
한컴 0x7EF8 (`ff ff ff ff`).

- 축 Tick: 주·보조 눈금 (없음 0, 안 1, 밖 2, 교차 3), 이름표 자리 (없음 0, 아래 1, 위 2, 옆 3). 축 선 LineFormat 의 플래그는
  보이면 5, 지운 축이면 0.
- 계열 값: 캐시가 있으면 캐시, 없으면 참조하는 칸 (항목은 칸에 보이는 글). BRAI 값의 ifmt 는 캐시 형식이 내장 형식이면
  그 번호. 참조가 깨진 계열(`#REF`)은 값 BRAI 가 토큰 없는 참조, 항목이 없으면 항목 BRAI 종류 0, 항목 캐시 SIIndex 2 를
  쓰지 않는다.
- 한셀은 차트마다 FONT 를 더 쓴다 (10pt 보통, 제목이 있으면 12pt 굵게 둘) — 어디서도 가리키지 않아 rcell 은 쓰지 않는다
  (한셀이 연 결과가 같다).

읽기는 이 부분 스트림을 한셀이 `.xls` 를 열어 XML 로 쓰는 차트의 꼴로 바꿔 XML 차트 리더로 읽는다: 차트 영역 흰 채우기 +
검정 1pt 선, 그림 영역 채우기·선 없음, 범례 흰 채우기, 축 글자 = 문서 기본 글꼴 (FONT 0 의 이름·크기), 제목 10pt,
3차원 회전은 Chart3d 와 상관없이 X 15·Y 20, 축의 눈금 표시는 늘 밖/없음 (이름표 자리만 Tick 에서), 누적 막대면 축마다
`0%` 표시 형식 (원본에 연결 안 함), 계열 선은 기본 검정 0.75pt, LineFormat 이 있으면 1pt 와 색 번호의 팔레트 색, 채우기도
색 번호의 팔레트 색, 값 캐시 형식은 값 칸의 서식 (`G/표준`, 따옴표·`\` 를 벗기고 `[빨강]`), 값 참조가 없는 계열은 버린다.
차트 도형의 잠금은 읽지 않는다.

- **캐시가 없는 계열**: 한셀은 `.cell` 의 차트 계열에 값 캐시가 없어도 저장할 때 칸 값을 쓴다 — 레거시·`.xls`·`.nxl` 쓰기는 같은
  규칙으로 계열 이름·항목·값 캐시(수 캐시는 칸 서식의 표시 형식, 점마다)를 칸에서 채운 사본으로 쓴다 (한컴 차트 0x7EF0 의 데이터 표·계열
  이름도 이 사본에서 나온다 — 한셀이 저장한 레거시 차트 15개와 Vt 아카이브가 같다).
- **넥셀 꺾은선 표식**: 계열의 자동 표식은 넥셀 차트에서 원 표식 4, 크기 140, `u16_d` 0, 색 플래그 0x20 으로 나온다 (레거시는 2, 크기
  기본). 실제 계열(`VtSeries`)만 — `chartType` 3 이고 X 축이 값 축(분산형)이 아닐 때.
- **도형 묶음 안의 차트**: 쓰지 않고 쓰기 보고에 경고한다. 말뭉치에 그런 문서가 없어 한셀의 저장 꼴을 확인하지 못했다.

### 5.3 대조

- **레코드**: 한셀 레거시 61개를 rcell 이 바꾼 것 대 한셀 `.xls`: 차트 레코드(0x1002 …)·SST 차례·EXTSST 위치를 빼면
  같다. 조건부 서식 CF 46·CF12 4·CFEX 48 모두 바이트까지 같다.
- **쓰기** (HCell(rcell `.xls`) 대 HCell(한셀 `.xls`), 원본은 같은 `.cell`): 한셀이 61개를 모두 열고 **59개가 같다**.
  차트 부분 스트림은 차트 23개 모두 한셀 `.xls` 와 바이트까지 같다. 남은 것: 차등 서식의 테마 색 밝기 1 차이 2
  (`ffb689`/`ffb589`, `b0c0ea`/`b0c1ea` — 레거시 쓰기의 색 계산과 같은 원인, 7절).
- **읽기** (rcell(한셀 `.xls`) 대 HCell(한셀 `.xls`), 61개): 한셀이 `.xls` 를 열 때 잃는 것을 rcell 도 그대로 잃게 했더니(기본 열기)
  **61/61 같다** (전에는 원본대로 읽어 31/61, 도형 글을 빼면 52/61). 차이 30개의 원인을 하나씩 가렸다:
  | 원인 | 문서 | 갈래 |
  |---|---|---|
  | 도형 글상자의 글을 비운다 (문단 하나·글 조각 없음, 줄 바꿈 자동·가로쓰기, 글 넘침 자름) | 서식 문서 24 | 한셀의 손실 |
  | 글이 없는 글상자에 회전 잠금(`noRot`)을 붙였다 (한셀은 글이 있는 글상자에만 붙인다) | odd_anchor, Sales_Analysis, Sales_Forecast_by_Market_Share, Unit_Sales_Forecast | **rcell 의 잘못 — 고침** |
  | 조건부 서식 차등 서식의 세로 맞춤·가로 분산을 잃고, 그래서 같아진 이웃 규칙은 하나로 합쳐진다 (범위도 합친다, 우선순위는 뒤의 것) | dxfprobe, dxfprobe2 | 한셀의 손실 |
  | 평균 규칙의 '아래'(below)가 '위'가 된다, 데이터 막대의 x14 확장(방향·음수 색 같음·축)을 읽지 않는다 | cfdv_x | 한셀의 손실 |
  | 자동 필터 상위·하위의 백분율을 잃는다 | filter2 | 한셀의 손실 |
  | 잃은 참조(`#REF!`) 수식은 다시 계산해 오류 값이 된다 | bigref | 한셀의 손실 |
  손실은 `legacy::lossy::hcell_xls_open` 이 적용한다. 원본대로 읽으려면 열기 선택 `rcell::OpenOptions { keep_original: true }`
  (명령줄 `--keep-original`). 한셀이 `.xls` 에서 읽지 못해 rcell 이 원본대로 남기던 것은 이 선택에서만 남는다.
- **왕복** (`tests/other_formats.rs`, 말뭉치): 한셀 레거시 48개 → `.xls` → 읽기 = 레거시 읽기 (차트·도형 앵커 밖).
  `.xls` 가 담지 못하는 것만 다르다 — 레거시 DXFN 의 안쪽 가로·세로 선, 값 목록 필터의 빈 칸, 실선이 아닌 한컴
  외곽선·윗줄, 탭 색 (팔레트 번호), 서식 없는 CF 규칙 (빈 차등 서식), HLINK 표시 이름 (도구 설명이 된다). 한셀의
  `.xls` 도 같은 것을 잃는다. 그리기 앵커의 dx·dy 는 1/32 로 줄어 1 픽셀까지 어긋난다.

Excel 이 쓴 `.xls` 와의 대조는 하지 못했다 (Excel 이 없다). 표준과 다른 한셀의 꼴(차등 서식 맞춤 번호, HLINK 표시
이름의 쓰임)은 한셀이 쓴 `.xls` 를 기준으로 했다.

## 6. 넥셀 `.nxl` (`xls::to_nxl`, `legacy::write_nxl`, `src/legacy/vbs.rs`)

한셀의 넥셀 저장(-2003)은 **BIFF8 틀(BOF 0x0600, 16비트 행, 플래그가 있는 문자열)에 한컴 꼴을 섞은 것**이다: FONT 는
BIFF8 FONT + 한컴 확장 플래그 0 (확장 없음), XF 는 레거시와 같은 한컴 확장(54바이트 이상), 문단 모양(0xA001·0xA011)과
0x0900·COUNTRY 가 있고 XFCRC·표 스타일·PLV·DXF·CF12·CFEX 가 없다. BOF 의 빌드·연도는 `01 01 D8 07` (플래그 없음). 그
밖에 레거시와 같은 것: FONT·XF 의 한컴 확장(FONT 의 이름 플래그만 1), SETUP, 머리글·바닥글 (글 플래그만 1), WINDOW2 의
머리글 색 0·꼬리 0x80000000, 탭 색 COLORREF. 차트는 레거시와 같은 한컴 0x7EF0 (CONTINUE 로 나눔) — 앵커와 수식의 행이
16비트, 앵커 dx·dy 는 1/32, 예약 11바이트의 끝 바이트 1.

- **하이퍼링크**: Ref8U + CLSID + 2 뒤에 종류 u32 (1 URL, 2 문서 안 위치, 3 메일, 5 파일), u32 3, 주소와 도구 설명 (u32 글자
  수 + 플래그 + 글자). 문서 안 위치는 주소가 비어 있다 (넥셀은 위치를 담지 않는다).
- **매크로** `/_VBS_PROJECT`: 머리 256바이트는 `_W` 와 같고, 글은 길이 (0xFF + u16) + 코드 페이지 949, 줄 끝 CRLF,
  `CLASS 이름` 줄의 글과 `End Class` 줄이 없고 앞에 빈 글이 하나 더 있다 (한셀은 되읽을 때 `CLASS CLS_GM_MODULE` 을 붙인다 —
  표본 하나).
- **조건부 서식 (CF 0x01B1)**: 넥셀 CF 는 레코드 머리(ct, cp, cce1, cce2) 뒤에 BIFF8 DXFN 대신 **플래그 6바이트(모두 0) + 있는 블록만 차례로**
  (글꼴 118 → 테두리 8 → 무늬 4) + 수식 이다. 블록은 규칙의 차등 서식에 그 속성이 있으면 (BIFF8 DXFN 플래그 0x04000000·
  0x10000000·0x20000000) 있고, 표시 형식·맞춤·보호는 담지 않는다 (아무것도 없으면 길이 8 = 머리 + 수식). CONDFMT 의 nID 칸은 1,
  한셀도 넥셀 CF 를 읽으면 규칙 종류를 잃는다 (모두 cellIs lessThan). 한셀 -2003 저장 36개(`dxfprobe`·`dxfprobe2`)를 BIFF8 쪽과 바이트
  대조해 얻은 규칙 (블록 안 위치는 블록 시작이 0):
  - **무늬 4바이트**: BIFF8 DXFN 의 무늬와 같다. **테두리 8바이트**: 선 종류 u16 은 같고, 색 칸은 BIFF8 의 자동(0x40)을 한셀 기본 테두리
    색으로 바꾼다 — 안 정한 왼쪽·오른쪽·아래는 검정(8), 위는 자동 0x40 그대로, 대각선 색 0 (정한 변은 팔레트 번호 그대로).
  - **글꼴 118바이트**: 이름 칸·높이(0–3, 64–67)는 0, 기울임 @68 은 BIFF8 의 값(0x02), **굵기** @72 는 그대로, @71 = 0x08, @80 은 색 번호(없으면
    0x40, 있으면 BIFF8 의 값), **@84–87 색 RGB** (없으면 `ff ff ff ff`, 자동이면 `ff ff ff df`, 있으면 R·G·B·0), @88 (BIFF8 tsNinch)은 0x82,
    취소선이면 0x02, @68 의 취소선 비트는 지운다. 밑줄이면 @74 |= 1 (색이면 |= 4), @76 = 밑줄 종류 (1 한 줄, 2 두 줄, 0x21·0x22 회계), @77 =
    한 줄·두 줄이면 1 (회계는 0), @78 = 한 줄 1·두 줄 8·회계 0, @96 = 밑줄이 없거나 두 줄이면 1. BIFF8 쪽의 "바꾸지 않음" 표시(@92·@96·@100
    의 1, @112–116 의 `ff ff ff 7f 01`)는 모두 0.
  rcell 은 이 꼴로 쓴다 (`xls::cf_to_nexcel`): 글꼴 색 RGB 는 BIFF8 DXFN 에 없어 레거시의 차등 서식 표(0x088D)의 글꼴 색 속성에서
  가져오고, 한 CONDFMT 의 규칙(CF)은 **거꾸로**(우선순위 내림차순) 쓰며, CONDFMT 의 nID 는 늘 1, 규칙 수 ccf 는 CF 로 쓰지 않는 색 막대·
  데이터 막대·아이콘 집합까지 센 값 (CF 가 하나도 없는 묶음은 CONDFMT 가 없고 CONDFMT12·CF12·CFEX 는 쓰지 않는다), 상위·하위
  규칙의 CF 종류는 5, 무늬 없이 배경색만 있는 채우기는 무늬 블록 첫 바이트 0x13. 한셀 -2003 저장과 레코드가 바이트까지 같다 —
  조건부 서식 문서 3개(`dxfprobe`·`dxfprobe2`·`cfdv_x`, 규칙 36개 + 12개). 또 레거시에서 읽은 글상자의 `noRot` 잠금(읽기가 더한 것)은 넥셀에는 쓰지 않는다.

대조 (한셀이 말뭉치 61개를 `.nxl` 로 저장한 것): **읽기** rcell 대 한셀 **30/61**, 도형 글을 빼면 49/61 (남은 것은 `.xls`
와 같은 한셀의 읽기 손실). **쓰기** HCell(rcell `.nxl`) 대 HCell(한셀 `.nxl`) **61/61** (엄격한 비교, 문서마다 입력 둘 중 맞는 쪽: 한셀 XML 저장 `.cell`
은 외부 연결 이름을 경로 꼴 `'[C:/…xls]시트'` 로 써 rcell 이 부호화하지 못하고, 한셀의 레거시 저장은 하이퍼링크 표시 글·분산형
표식 같은 것을 잃는다 — 외부 연결이 있는 문서는 레거시 입력, 나머지는 XML 입력). 하이퍼링크 종류 실험 다섯 가지는 읽기·쓰기 모두 한셀과 바이트까지 같다.
`.nxt`·`.nxk`·`.nav` 는 대화 상자 목록의 같은 계열 확장자다 (따로 대조하지 않았다).

## 7. 테마 색 밝기(tint) — 풀지 못한 것

레거시 쓰기는 테마 색 + 밝기를 RGB 로 바꿔 차등 서식(0x088D)·확장 색에 쓴다. 한셀의 계산과 같게 하려고 테마 색 10가지 ×
밝기 22가지 = 220개를 한셀이 레거시로 저장한 RGB 와 맞대 보았다 (차등 서식 22개짜리 실험 문서 10개): ECMA-376 의 HLS 실수
계산 그대로면 181개가 같고, 밝기를 32비트 실수로 다루면 회색 44개가 모두 맞는다 (`0.9 × 255` 가 229 — 한셀은 밝기를
f32 로 들고 있다). 남은 38개는 채도 있는 색의 한 채널이 1 다르다 (`FAF3DB` +0.05 → 한셀 `faf3dc`, 실수 계산 `faf4dd`).
HLS 정수 단계(240·255·256), 반올림·내림 조합을 찾아보았지만 220개를 모두 맞추는 식은 찾지 못했다 (가장 많이 189개).
rcell 은 지금의 실수 계산을 그대로 둔다 — `.xls` 쓰기 대조의 남은 2개가 이것이다.

3차 시도 (같은 220개 표본):
- Windows shlwapi 의 `ColorAdjustLuma`(밝기 ±n/1000, 상대) 는 64–65개, `ColorRGBToHLS`→L 을 tint 로 고쳐 `ColorHLSToRGB`
  (HLSMAX 240) 는 74개만 맞는다 — 한셀의 식이 아니다.
- 32비트·64비트 실수 × HSL 식(채도 식·크로마 식) × 반올림(사사오입·버림·반올림 짝수) × 255 배율(255·255.0001·254.9999)
  조합은 가장 많이 184개 (tint 와 L 을 f32 로 두고 매 단계 f32). 틀리는 채널은 한셀이 −0.5~−1.5 쪽으로 어긋난다 —
  단계 사이 정수 반올림이 있는 정수 HLS (HLSMAX 255 의 H·L·S 를 정수로 두고 RGB 로 되돌리는 방식)가 아닐까 하지만 색마다
  따로 맞춘 값이 22개 tint 모두를 만족하지 못했다 (색 하나의 22개를 맞추는 정수 HLS 상수가 없다).
4차 시도 (정수 HLS): MS 고전 `RGBtoHLS`·`HLStoRGB` (정수 나눗셈·반올림 `+HLSMAX/2`) 를 HLSMAX 100·240·255·256·360·1000·1024·4096·65535 로, 명암은 L 만 바꾸고 (`L×(1+t)` / `L×(1−t)+HLSMAX×t` 와 `L+(HLSMAX−L)t`) 반올림 4가지·tint f32 여부를 모두 돌려 보면 가장 많이 163개 (HLSMAX 65535) — 실수 HSL 의 181개보다 못하다. 실수 HSL 에 H·S·L 을 각각 정수 단계(100·240·255·256·360·1000·10000·65535)로 양자화 (변환 직후·명암 뒤, 반올림 3×3) 해도 최대 189개. 정수 HLS 쪽이 아니다.
- 결론: 정확히 맞는 식이 없어 레거시 쓰기는 그대로. 한셀의 이 계산은 정수 HLS 라이브러리 호출일 가능성이 크다 (실행 파일을
  풀어 보지 않는 클린룸 원칙이라 확인하지 않았다).

## 8. ODF `.ods` (`src/ods.rs`)

한셀의 `.ods` 저장(60)은 `content.xml`·`styles.xml`·`meta.xml`·`settings.xml`·매니페스트로 `mimetype` 이 없다. 수식은
`of:=` 뒤에 A1 참조를 그대로 (ODF 표준의 `[.A1]` 꼴이 아니다), 인수 구분 `;`, 다른 시트 참조는 `#REF.` 로 잃는다. 표시
형식이 빈 글인 수식 칸(값 `""` 이나 0 을 감추는 형식)은 쓰지 않는다. 한셀의 `.ods` 읽기는 논리값 칸을 `ISLOGICAL(값)`
수식(값은 늘 TRUE)으로, 참조의 `$` 를 버리고, `시트.A1` 의 시트를 버린다.

### 8.1 한셀이 쓰는 칸 서식 (한셀 .ods 56개를 읽어 정리)

- 칸 스타일(`ceN`, 부모 `Default`): 칸 속성 `style:vertical-align`(대부분 `middle` — 아래 맞춤도 가운데로 쓴다),
  `fo:background-color`, 테두리 네 변 `fo:border-top|bottom|left|right` = `너비 모양 색` (너비는 굵기만 말한다: 0.002cm 가는
  선, 0.088cm 굵은 선, 0.039cm 이중선 — 점선·파선·중간 굵기는 실선으로 잃는다), 줄 바꿈 `fo:wrap-option`; 문단 속성
  `fo:text-align`(start·center·end), 들여쓰기는 `fo:margin-left/right` 단계 × 0.353cm; 글자 속성 색·글꼴 이름(동아시아·복합 문자
  포함)·크기·굵게·기울임·밑줄(종류 single/double)·취소선·첨자(`style:text-position` 58%). **표시 형식(`number:*`)은 쓰지 않는다**
  — 한셀은 읽을 때는 안다 (표시 형식 스타일 `number:number-style`·`percentage`·`currency`·`date`·`time` 와 `style:map` 조건을 서식
  문자열로 읽는다).
- 열 `co`(너비 cm), 행 `ro`(높이 cm, `use-optimal-row-height`), 표 스타일 `ta`(마스터 쪽, `table:display`, `tableooo:tab-color`),
  쪽 모양 `pagelayout`(A4 21.001×29.7cm 또는 레터, 여백, `style:scale-to`·`scale-to-X/Y`, 가운데 맞춤, 머리글·바닥글 높이
  0.751cm·간격 0.25cm — 한셀은 문서의 위·아래 여백을 머리글 여백으로 두고 이 높이를 더해 쓴다), 머리글·바닥글 `&[SHEET]`
  `&[PAGE NUMBER]`, 이름 정의 `table:named-range`, `settings.xml` 의 커서 위치·활성 시트·확대율·머리글 표시.

### 8.2 읽기 (한셀이 같은 .ods 를 연 결과에 맞춘 것)

칸 스타일 → 서식 (글꼴 확장: 밑줄·취소선 모양 `solid`/`doubleslim`·색 = 글자 색; 가로 맞춤이 `general` 이 아니고 왼쪽 맞춤·
들여쓰기 0 도 아닌 칸에 기본 문단 모양 — 줄 간격 75 betweenLines, 영문 keepWord·한글 breakWord, 기준선, 들여쓰기 단계 × 1134 를
왼쪽(오른쪽 맞춤이면 오른쪽) 여백으로 — `.xls` 와 같다), 열 너비 `글자 = (96dpi px − 5) / 숫자폭 − 0.772342` 를 1/256 로 버림
(숫자폭: 11pt 7px, 10pt 6px — 한셀이 `.ods` 에 쓴 cm 와 다시 연 글자 수 22쌍 중 20쌍이 맞는다), 모든 열이 너비를 정한
열, 행 높이는 pt 정수로 버리고 0 이면 숨김, 쪽 모양 (용지는 쪽의 (높이, 너비) 를 세운 용지의 (너비, 높이) 와 맞대 보고 모르면

읽기도 한셀이 읽는 대로 읽는다 (`rcell::OpenOptions { keep_original: true }` 이면 원본대로): 논리값 칸은 `ISLOGICAL(값)` 수식(값은 늘 TRUE), 열 너비는 단정밀도

## 9. 웹 페이지 `.htm`·`.mht` (`src/webpage.rs`)

한셀의 웹 저장(44·45)을 한셀 COM `SaveAs` 로 말뭉치 12개와 실험 문서 둘(표시 형식 65가지, 맞춤·글꼴·줄 바꿈·특수 글자)에 해 보고 글자
단위로 맞췄다.

### 9.1 파일 구성

- `이름.htm` 은 프레임 묶음: `<meta name="Excel Workbook Frameset"/>`, `<!--[if gte mso 9]>` 안의 `x:ExcelWorkbook` 에 시트마다
  `x:Name`·`x:WorksheetSource HRef="이름.files\sheetNNN.htm"`(숨긴 시트도 목록에 있지만 쪽 파일은 없다), `x:ActiveSheet`(0부터),
  그리고 `<frameset rows="*,50">` 의 두 프레임 `frame_sheet`(활성 시트 쪽)·`frame_tabs`(`tabs.htm`). 줄 끝은 `\n`, 글은 UTF-8.
- `이름.files/sheetNNN.htm`: 시트 번호는 숨긴 시트도 세는 3자리. `tabs.htm`: 보이는 시트마다 `<div class="tab_btn">` 과
  `<a href=".\sheetNNN.htm" target="frame_sheet">이름</a>`. 그림은 `imgN.png` — 도형·차트·그림 모두 PNG (9.5절).
- `.mht`: `Mime-Version:1.0`·`X-Document-Type:workbook`·`multipart/related; boundary="----=_NextPart_XXXXXXXX.XXXXXXXX"`, 부분은
  묶음 쪽 → 그림 → 시트 쪽 → 탭 순서이고 부분마다 `Content-Location:file:///C:\GUID\파일`. 쪽의 `<head>` 다음 줄에
  `<![if IE]><base href="Content-Location"><![endif]>` 를 더하고 쪽 안의 `이름.files` 는 `0000xxxxxxxx.files` 로 바뀐다.
  본문 quoted-printable 은 `=` → `=3D` 만 막고 **유니코드 글자 73개(`=3D` 는 3개)가 차면 `=\r\n`** 으로 접는다 (한글은 그대로, 줄 바꿈
  `\n` 은 그대로 — 한셀 mht 본문 36개와 바이트까지 같다). 그림은 base64 72글자 줄(`\n`, 마지막 줄 `\r\n`). 부분 끝마다 `\r\n`.
  GUID·파일 이름·경계는 한셀이 쓸 때마다 무작위, rcell 은 문서 내용에서 정해 같은 문서는 같은 파일이 된다.

### 9.2 시트 쪽

`<style>` 에 쓰인 서식마다 `.hcxN { 속성 }` 을 이어 쓰고 (줄 바꿈 없이, 번호 오름차순, 맨 뒤에 `.hcx_t_s { display: table-cell; }body { margin:0;
padding:0;}`), 속성 차례는 `color`·`font-size`(`11.00pt`)·`font-weight`(400/700)·`font-style`·`text-decoration`(밑줄이면
`underline;text-underline-style:single|double;text-underline-color`)·`font-family`·`mso-number-format`·테두리(위·왼쪽·아래·오른쪽)·
`background-color`(단색만)·`text-align`(general·left·center·right·justify·center-across·fill, 균등 분산은 general)·`vertical-align`
(top·middle·bottom)·`white-space`(줄 바꿈이거나 세로 양쪽·균등이면 normal)·`mso-text-control:wrap`. 테두리 가는 선 `.5pt solid`, 중간
`1.0pt solid`, 굵은 선 `2.0pt solid`, 이중선 `2.0pt double`, 점선 `.5pt dotted`, 파선 `.5pt dashed`, `dot-dash`·`dot-dot-dash`·`dot-dash-slanted`
(색이 없으면 `#000000`). 글꼴 색·채우기는 `#rrggbb` 소문자, 자동 색은 `#000000`.

`<table class="hcxN" width=… cellspacing="0" cellpadding="0" border="0" style='border-collapse:collapse; table-layout:fixed'>` 의
클래스는 **첫 열의 서식**(없으면 15), 너비는 열 너비를 **트윕(1/15 px) 정수로 내린 값의 합 ÷ 15 를 버린 값** (한셀 웹 저장 52시트가 모두 맞는다 — 정수 px 로 내린 합과 다르다). `<col span width>` 줄은 열 너비가 서로 다르거나
숨긴 열이 있을 때만, 열 정보(min–max) 하나가 한 줄이고 열 정보 없는 이어진 열은 한 줄이다 (숨김은 `width="0" style='display:none'`) — 값이 있는 칸·
병합과 너비를 정한 열 정보의 끝 열까지만. `<tr height>` 는 **내림(pt × 4/3) + 1** (12.75pt → 18, 19.5pt → 27, 17.25pt → 24)이고 행 서식이 있으면 `<tr class="hcxN" …>`, 숨긴 행은 `height="0" style='display:none'` 이고 칸의 높이는
그대로. 병합은 `colspan`·`rowspan` 과 합친 너비(트윕 합)·높이(행 pt 합 × 4/3 의 내림 + 1)이고 덮인 칸은 쓰지 않는다. 칸은 `<td class width height>` + 줄바꿈 + 글 +
`        </td>`, 글은 보이는 글(표시 형식 적용)을 앞뒤 공백을 떼고 줄마다 `<font class="hclfontN">…</font>`(줄 바꿈은 `<br/>\n` 을
앞 글 끝에), 취소선·위첨자·아래첨자는 `<s>`·`<sup>`·`<sub>` 로 감싼다. **글자를 이스케이프하지 않는다** (`<`·`&` 가 그대로 나온다 — 한셀이
그렇다). 표시 형식에 색(`[Red]`)이 있으면 `<font color="#ff0000" class=…>`. 부분 서식 글은 조각마다 `hclfontN` 이고 그 글꼴의
`.hclfontN` 규칙이 `.hcxN` 앞에 온다. `hclfontN` 의 N 은 한셀 글꼴 표의 번호 — 표는 **기본 글꼴(맑은 고딕 11pt 검정) 하나로 시작하고(0)** 문서의 글꼴 목록이 차례로 더해진다 (같은 글꼴은 합쳐진다). `hcxN` 의 N 은 기본 서식(0) 15, 그 밖은
20 + 스타일 서식 수 + 서식 번호이고, **병합 시작 칸은 모든 서식 뒤의 파생 번호** (9.4절). 메모는 표 뒤 `<hr align="left" width="300" size="1"></hr>` 다음 `<a class="memoa" href="#_hncmemo_N">[N]</a>` 와
글 (메모마다 `.hcx1`, `.hcx2` …, `.memoa` 규칙). 하이퍼링크는 `<a>` 가 아니라 파란 밑줄 서식으로만 나온다.

### 9.3 표시 형식 `mso-number-format`

한셀 안의 서식 문자열(글자 사이 문자를 `\` 로 막은 꼴)을 CSS 로 이스케이프한다. 첫 단계: 숫자 서식은 `:`, 날짜·시간 서식은 `/` 도 `\` 로 막고
(`AM/PM` 의 `/` 는 그대로), 공백·`- + = < > & ' ! ~ ^ | { } $ ( )` 도 `\`, 따옴표 글·`[…]`·`_x`·`*x`·`E+` 는 그대로, 따옴표 없는 `₩` 는 `"₩"`, 그 밖의 기호는
`\기호`, `%` 는 첫 것만 그대로. 둘째 단계: `# , . ; [ ] ( ) @ /` 와 `\` 앞에 `\`, `"` 는 `\0022`, 글자가 아닌 비 ASCII 는 `\20A9`(₩) 꼴 4자리 16진수.
`[>100]0` 처럼 조건 하나뿐이면 `;General` 을 붙인다. (표시 형식 65가지 가운데 61가지가 같고 남은 것은 깨진 서식·`0%%`)

### 9.4 번호·크기 규칙 (한셀 서식 문서 28개를 문서마다 새 한셀 프로세스로 웹 저장해 대조)

- **병합 파생 클래스**: 병합 시작 칸은 그 서식 자신이 아니라 **모든 서식 뒤(20 + 스타일 서식 수 + 서식 수)부터 새로 매긴 번호**를 쓴다. 번호는 시트 차례로,
  시트 안에서는 병합 목록 차례로, 범위 안에서는 행 우선으로 **처음 나온 서식마다 하나씩** (범위 안 덮인 칸의 서식도 센다; 서식이 같으면 같은 번호). 병합 199곳이 모두
  맞는다. 파생 클래스의 CSS 는 시작 칸 서식과 같되 **오른쪽 테두리는 병합 범위 오른쪽 위 칸, 아래쪽 테두리는 왼쪽 아래 칸의 것**이다.
- **열 서식·행 서식 클래스**: 열 정보의 서식은 그 열에 칸이 없어도 `.hcxN` 을 정의한다 (열 줄에 드는 열 정보까지). 행 서식이 있는 행은 `<tr class="hcxN" height>`.
- **글꼴 번호 `hclfontN`**: 위 9.2. 한셀 프로세스 하나가 문서를 여러 개 열면 번호가 문서 사이에 이어서 쌓인다 (한 프로세스에서 28문서를 이어 저장하면 번호가 커진다) —
  그래서 문서마다 새 프로세스로 대조해야 한다. 병합 파생 칸의 글도 같은 글꼴 표를 쓴다.
- **그림 칸 크기·여백**: `<span style='position:absolute; margin-top; margin-left; width; height'>` 은 시작 칸(앵커 `from`; 앵커 형식이 `absolute` 면 첫 칸, 여백 1·1) 안에 쓴다.
  화면 크기는 개체 크기(`xfrm` 의 ext, px)에 **활성 시트의 확대 비율(`zoomScale`)** 을 곱해 반올림한 값이다 (활성 시트 90% 문서는 0.9배, 80%·110% 도 같다 —
  한셀은 이 배율을 도형·차트·그림에만 곱하고 칸 크기에는 곱하지 않는다). 여백이 `xfrm` 위치 × 배율을 반올림한 값과 같은 것은 103곳 가운데 가로·세로 모두 23곳이다
  (첫 열에서 시작하는 개체의 가로 여백만 보면 35곳 가운데 34곳). 나머지(두 번째 열 이후에서 시작하는 글 상자 등)는 문서마다 다른 값 — 시작 칸의 글 맞춤·칸 안 글자 자리에서
  브라우저의 인라인 시작 위치를 빼는 듯하나 규칙을 찾지 못했다.

### 9.5 도형·차트·그림 PNG (`src/print/webpng.rs`)

한셀은 도형·차트를 RGBA PNG(투명 바탕)로 그려 넣는다. rcell 은 **인쇄가 차트를 비트맵으로 그릴 때 쓰는 래스터라이저 `print::raster::render`(zeno, 256단계 안티앨리어싱) 하나를 같이 쓴다**:
`webpng` 는 그 앞뒤 — 그리기 목록(장치 단위 1px = 6.25)을 픽셀 단위로 줄이고, `Raster` 묶음을 풀고, 밑줄·취소선을 선으로, 그림(PNG·BMP)을 이중선형으로 얹고, 결과를 RGBA PNG 로 쓴다.

- 그림 크기: 개체 크기를 **반올림**한 px, **테두리선이 있거나 바깥 그림자가 있거나 차트 영역 선을 정하지 않았거나(기본 회색 틀) 보이는 선이면 가로·세로 한 줄씩 더**
  (그림자 있는 사각형 681×389, 글 상자 624×33, 틀 없는 차트 725×447, 기본 틀 차트 505×331). 그림(사진)은 화면 크기와 같다 (PNG·BMP·JPEG 모두 다시 그린다 — JPEG 은 `src/jpeg.rs` 의 기본·점진 허프만 풀개, 줄일 때는 원본 칸 넓이 평균. 점진 JPEG 사진(2736×1539 → 206×193)은 한셀 PNG 와 평균 오차 1.25/255 (가장자리 최대 30 — 한셀의 줄이기 필터가 다르다), PNG 사진은 0.10).
- 그림자: 같은 모양을 (`dist`·`dir` 의 정수 이동 — 한셀은 1px) 옮겨 그림자 색 한 가지로 먼저 깐다. 숨긴 텍스트 상자는 투명한 23×27 그림.
- 대조 (28문서의 그림 146개): 크기 145개 일치, **픽셀까지 같은 것 62개** (그림자 있는 바탕 사각형은 전부 — 449,480 + 1,340 + 2 픽셀 꼴까지). 글이 든 상자·차트는 같은 자리에 비슷하게 그려지나
  글자 모양이 다르다 (한셀은 글 상자의 본문 글자를 안티앨리어싱 없이 두 색으로 그리고, 제목 글자는 안티앨리어싱한다. rcell 도 글 상자 도형의 작은 글자(16px 이하)는 두 색으로 그려 같은 픽셀 비율이 91.9% → 95.7%). 사진 PNG 는 평균 오차 0.33/255 (최대 3).
- 못 한 것: 앵커와 `xfrm` 이 어긋난 문서의 차트 크기 몇 곳, 높이 1px 차트 (한셀은 흰색 한 줄).

### 9.6 대조 결과

서식 문서 28개(시트 쪽 108개)를 문서마다 새 한셀 프로세스로 저장해 대조: **81개가 바이트까지 같다** (병합·글꼴 번호·행 높이·열 너비 규칙을 넣기 전 57개, 이번 라운드 전 76개). 남은 27개는 모두 **그림 칸 여백** 하나다 (9.4 — 서식 문서 소개 시트의 둘째 개체 24쪽, 시트 깊은 곳 차트 3쪽). 이번에 고친 것: 한 칸에 개체가 여럿이면 채움 글 조각(`hcx_t_s`)은 개체를 모두 쓴 뒤 하나만, 개체 여백은 적어도 1, 표 클래스는 마지막 열 정보의 서식, 16384 열까지 이어지는 너비 없는 끝 열 정보는 `<col>` 로 쓰지 않는다, 글이 있는 메모 칸에 메모 표지 `<a class="memoa" href="#_hncmemo_N">[N]</a>`.
그림 칸 여백 규칙 다시 시도 (새 가설 `여백 = 개체의 칸 안 x 오프셋 − 그 행에서 앞 칸·개체가 이미 쓴 너비`): 서식 문서 개체 104곳(`spans.jsonl`)에 맞대 보니 **맞지 않는다**. 첫 열(0·1)에서 시작하는 개체는 `margin-left = 개체의 시트 안 x` (시작 칸의 왼쪽 가장자리를 0 으로 본 정적 위치 0 — 28곳)이지만, 둘째 열 이후(소개 시트의 C 열 개체)는 정적 위치가 문서마다 다르다 (X − margin-left = 161, 98, 215, 114, 158, 90, 95, 106 … — 같은 문서 안에서는 같은 열의 모든 개체가 같고, 앞 칸 너비 합(60)·앞 개체 너비(680·624)·칸 너비(630)·확대율로는 설명되지 않는다). 세로도 같은 꼴 (Y − margin-top = 45, 67, 40, 27 …). 시트 깊은 곳의 차트는 `margin-top` 이 칸 안 오프셋 근처의 작은 값(1·11·3)이라 절대 위치가 아니다.
말뭉치 12개 36개 중 29개는 그대로 같다 (한 프로세스에서 이어 저장한 것 — 글꼴 번호는 그 프로세스의 누적이라 새 프로세스 기준과 다르다). `.mht` 는 이름·GUID 를 뺀 7개 중 6개 (나머지는 그림 바이트).
같지 않은 것 하나 더: 칸 수가 4,000,000 을 넘는 시트는 앞부분만 쓴다 (한셀은 `bigref` 같은 문서를 저장하다 멈춘다).

## 11. 암호 저장·열기

한셀 `SaveAs(…, Password)` 와 `Workbooks.Open(…, Password)` 를 형식마다 해 보았다 (`ps/hcell-enc.ps1`).

- **표준 암호화** — XML `.cell`·바이너리 `.cell`·`.hcdt`·`.hcbk`·`.xlsx`·`.xlsm`·`.xlsb`: OLE2 안에 `EncryptionInfo`·`EncryptedPackage` (AES-128 ECB, SHA-1, 반복 50,000번, 소금 16바이트).
  rcell 은 읽고 쓴다 (`rcell::open_with_password`, `save_as_encrypted`, CLI `convert … --out-password`). 암호를 주지 않으면 보호만 걸린 문서의 기본 암호로 열고, 틀린 암호는 오류.
- **`/HCellCrypto`** — 레거시 `.cell`·`.nxl`: 평문과 같은 OLE2 의 `/Workbook` 스트림을 표준 암호화와 **같은 키 유도**(소금·SHA-1·50,000번·AES-128 ECB)로 통째로 암호화하고,
  `/HCellCrypto` 스트림(소금·검증값·검증 해시)을 더한다. 암호를 주면 풀고 쓴다. 한셀이 rcell 이 만든 두 형식의 암호 문서를 맞는 암호로 연다.
- **암호를 무시하는 형식** — `.xls`·`.ods`·CSV·텍스트: 한셀은 `SaveAs` 의 암호를 받아도 쓰지 않고 (평문 저장), 열 때 암호를 줘도 상관없다. rcell 은 이 형식에 암호 저장을 거절한다.
- **`.hca`** (자동 저장): 한셀 `SaveAs` 가 PATHNOTFOUND 로 실패해 만들지 못한다. 바이너리 `.cell` 은 한셀 COM `Open` 이 `.bin.cell` 이름으로는 서버 오류를 내므로 `.xlsb` 이름의 사본으로 연다: 한셀이 만든 암호 바이너리 `.cell` 과 rcell 이 만든 것 모두 맞는 암호로 열린다 (틀린 암호·암호 없음은 암호 대화 상자가 떠 COM 이 멈춘다).

### 15.1 텍스트 가져오기 선택 (`Workbooks.OpenText`, `rcell convert --delimiters --text-columns --start-row`)

- **구분 문자**: 고른 문자 모두로 나눈다 (탭·세미콜론·쉼표·공백, 그 밖의 문자는 **첫 글자만**). 아무것도 고르지 않으면 확장자의 기본 (`.csv` 쉼표, 그 밖은 탭). 따옴표(`"`) 싸기는 늘 켜져 있다 (끄는 선택(−4142)은 무시, 작은따옴표를 고르면 큰따옴표는 일반 글자). **`.csv` 이름이면 COM 은 구분 문자 선택을 무시하고 쉼표로 읽는다** (rcell 은 선택을 따른다). 연속 구분 문자 합치기는 무시된다.
- **열 서식(`FieldInfo`)**: 글(2) 은 값 해석 없이 글 + 글자 서식 `@` (앞의 `'` 는 벗긴다). 건너뛰기(9)는 무시되고 (열이 그대로 남는다), 날짜 순서(3·4·5)는 그 열에 `yyyy-mm-dd` 서식을 붙일 뿐 값 해석은 일반과 같다.
- **인코딩 선택(`Origin`)**: 무시된다 — BOM(UTF-8·UTF-16) → 없으면 파일 전체가 올바른 UTF-8 이면 UTF-8, 아니면 949 (3.2절) 를 늘 자동으로 고른다.
- **시작 행(`StartRow`)**: 줄을 버리지 않고 그만큼 아래 행부터 놓는다.
- 함수 인수가 아닌 자리의 쉼표(합집합)는 양쪽이 참조일 때만 수식이다: `-1,0` `+1,2` `=1,2` `-1,2,3` `-(1,2)` 은 글, `-A1,B1` 은 수식 (`#VALUE!`), `-SUM(1,2)` 는 수식 (−3).

## 16. .xls·레거시의 도형 묶음 (한셀 저장과 바이트 대조)

묶음 안에 차트와 사각형이 든 문서를 한셀이 `.xls`(56)·레거시(-2005)·넥셀(-2003)로 저장한 것과 rcell 이 쓴 것의 MSODRAWING 레코드가 **바이트까지 같다**:
묶음은 SpgrContainer 안의 SpgrContainer (묶음 SpContainer + 자식들) — Spgr 사각형은 자식 좌표 범위(`a:chOff`·`a:chExt`, EMU), 묶음 SP 플래그 `0x0201`, 잠금 `0x007F = 0x011E011E`·`0x033F = 0x00080008`, 시트 칸 앵커 (ClientAnchor).
자식은 플래그 `0x0A02` 의 SP 와 **ChildAnchor(0xF00F)** — 묶음 안 좌표의 (왼쪽, 위, 오른쪽, 아래) EMU. 묶음 안 차트 자식은 종류 0, 잠금 `0x031E031E`, `0x0304 = 0`, `0x033F = 0x00080008`, 이름, OBJ ot 5 (플래그 `0x0011`)이고
차트 부분 스트림(BOF … EOF)이 그 OBJ 뒤에 이어진다. 차트 부분 스트림의 차례는 **시트 바로 아래 차트가 먼저, 묶음 안 차트가 그다음**이다 (그리기 차례).
rcell 이 전에는 묶음을 평평하게 써서 (자식이 묶음 밖 도형이 됨) 묶음 안 차트를 잃었고, 읽기는 최상위 차트에만 차트 내용을 붙였다 — 둘 다 고쳤다 (읽기는 묶음 안 도형의 자식 앵커와 묶음의 자식 좌표 범위를 `xfrm` 으로 둔다).
그림 영역 모양에 선 속성(두께·끝·꺾임 …)이 있는 차트는 `1032 FRAME(플래그 3)` + 자동 `1007` 틀을 `1035 PLOTAREA` 뒤에 쓴다. 남은 차이: 한셀은 차트 글자 글꼴을 통합 문서 글꼴 표(FONT 레코드)에 더한다 (서식 문서 차트에서 FONT 1–13개).

## 17. ODS 의 도형·그림·차트 (`src/ods_draw.rs`, `src/ods_geom.rs`)

한셀 `.ods`(60) 저장 관찰을 그대로 읽고 쓴다. 한셀 저장 40개 문서(서식 문서·차트 17·그림·묶음)의 개체 부분(`draw:frame`·`draw:g`·스타일·차트 하위
문서)이 **글자까지 같은 것 38개**다 (남은 둘은 서식 문서 차트의 차트 틀 스타일 — `Chart7`·`Chart8`).
- 도형은 시작 칸 안의 `<draw:frame draw:name draw:style-name="grN" svg:width svg:height svg:x svg:y draw:id="drawingN.xml-ID" table:end-cell-address table:end-x table:end-y>` + `<draw:text-box>` (사각형도 텍스트 상자로). `svg:x`·`svg:y` 는 시작 칸 안의 오프셋, `table:end-*` 는 끝 칸과 칸 안 오프셋. 타원·둥근 사각형·삼각형·마름모·화살표·별·육각형·평행사변형·사다리꼴·순서도 처리는 `draw:custom-shape` + `draw:enhanced-geometry` (한셀이 쓴 요소 글을 표로, `ods_geom.rs`), 연결선은 `draw:connector` (시트 안 절대 좌표 `svg:x1…y2`, 화살표는 `draw:marker-end`).
- 도형 서식은 `style:family="graphic"` 자동 스타일 `grN` (그리기 차례 번호). **한셀은 원본 개체가 가진 속성만 쓴다**: 스타일 참조(`xdr:style`)가 있는 도형은 전부(선 없음이면 기본 선 0.5pt `#263E5B`·`fo:min-width="3.5cm" fo:min-height="3.95cm"`·`draw:auto-grow-height`·`fo:wrap-option`·안쪽 여백·채우기 색 `#4F81BD` 기본), 글 상자(`txBox`)는 `auto-grow-height`·`style:shrink-to-fit="false"`, 그 밖은 선·채우기·줄 바꿈만, 경로가 없는 사용자 정의 도형(`a:custGeom` 빈 경로)은 스타일(`draw:stroke="solid" … draw:fill="solid"`)만 쓰고 개체는 쓰지 않는다. 그림자 거리 2만 EMU 이하는 간격 0cm, 점선 이름은 `Dashed`·`LongDash`·`DashDot`·`LongDashDot`·`LongDashDotDot`·`SysDash`·`SysDot` (`draw:stroke-dash` 정의는 `styles.xml`). 회전·뒤집기는 쓰지 않는다.
- 글은 문단 `P{n}`(`fo:text-align`: 지정 없으면 글 상자는 가운데, 그 밖은 시작)과 글 조각 `T{n}`(`fo:color` 또는 `style:use-window-font-color`, 글꼴 이름·크기·기울임·밑줄·굵게; 테마 글꼴 `+mn-ea` 는 테마 제목 글꼴의 영문 이름).
- 묶음은 `<draw:g svg:y table:end-cell-address …>` 안에 `draw:frame` 들 (자식의 `svg:x`·`svg:y` 는 시트 안 좌표). 묶음 안 차트도 그대로 든다.
- 차트는 별도 하위 문서 `Object N/content.xml`·`styles.xml` (`chart:class`: bar·line·area·circle·ring·scatter·radar·bubble·stock, 3차원은 `dr3d:*`, 범례 `end`/`bottom`/`start`/`top`, 항목 축 `chart:categories`, 계열 `chart:label-cell-address`, 막대·꺾은선·원형은 값을 쓰지 않고 영역·분산형만 `values-cell-range-address` 와 지역 표에 값을 쓴다)이고 `content.xml` 에는 `<draw:frame><draw:object xlink:href="Object N/"/></draw:frame>`. 영문 시트 이름은 `local-table.$C$1`, 그 밖은 `시트!$B$33` 꼴. **한셀은 제목이 있는 차트(24개)와 글자 이름의 계열을 쓰지 못한다** — 같은 문서의 `.ods` 에서 사라진다.
- 그림은 `Pictures/imageN.png|jpeg` + `draw:frame` 의 `draw:image` (크기는 두 칸 앵커의 칸 사이 크기 — `xfrm` 이 아니라 앵커가 정한다).
- 읽기는 같은 꼴을 도형 모델(앵커·`xfrm`·채우기·선·그림자·글 상자 속성·글)과 차트 모델(종류·범례·항목 범위·계열·색)로 읽고, 그림은 `xl/media/odsN.*` 로 옮긴다.

- **테마 색 밝기(tint) 반올림**: 220개 표본에 맞는 식을 찾지 못했다 (7절). 정수 HLS 탐색 최선 163/220, 양자화한 실수 HSL 189/220.
