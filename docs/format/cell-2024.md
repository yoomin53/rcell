# 한셀 2024 `.cell` 파일 형식

> 작성: yoomin53 · 대상 버전: 한컴오피스 2024 한셀 (HCell.exe 13.0.0.711)
>
> 이 문서는 한셀이 저장한 파일과 공개 표준(ECMA-376)을 대조해 얻은 관찰 결과다.
> 확인 수준을 항목마다 표시한다.
>
> - **관측**: 한셀이 저장한 실제 파일에서 확인
> - **문자열**: `HncOOXML.dll` 의 문자열 테이블에 이름만 존재. 의미는 미확인
> - **심볼**: `HncOOXML.dll` 이 export 하는 C++ 인터페이스 이름·인자 타입에서 확인. 의미는 이름 기준
> - **바이너리**: REA/Ghidra 로 `HncOOXML.dll` 의 요소 등록표·열거형 변환표에서 확인한 이름과 값
> - **추정**: 이름이나 맥락으로 짐작. 검증 필요

## 1. 컨테이너

| 세대 | 컨테이너 | 시그니처 | rcell 지원 |
|---|---|---|---|
| 한셀 2014 이후 (2024 포함) | ZIP / OPC | `50 4B 03 04` | ✅ 읽기 |
| 한셀 2010 이하 | OLE2 복합 문서 | `D0 CF 11 E0 A1 B1 1A E1` | ✅ 읽기 ([레거시](cell-legacy.md)) |
| 암호 설정 문서 | OLE2: `EncryptionInfo` + `EncryptedPackage` (ECMA-376 표준 암호화 3.2/4.2, AES-128 ECB, SHA-1 50,000회) | `D0 CF 11 E0 …` | ✅ 읽기 (표준 암호화, Agile 은 아직) |

보호(시트·통합 문서 보호)가 걸린 문서를 한셀이 바이너리·레거시로 저장하면 패키지를 기본 암호
`VelvetSweatshop` 으로 암호화한다 (관측). rcell 은 암호를 주지 않으면 이 기본 암호로 연다.

한셀 2024 의 `.cell` 은 **xlsx 와 같은 OOXML SpreadsheetML 패키지**다. 파트 구성도 xlsx 와 같다.

```

xl/_rels/workbook.xml.rels

xl/styles.xml

xl/worksheets/sheetN.xml
xl/worksheets/_rels/sheetN.xml.rels
xl/drawings/drawing0.xml    ← Excel 은 drawing1 부터, 한셀은 0 부터 번호를 매긴다 (관측)
```

### 2.1 한셀의 `.cell` 과 `.xlsx` 는 같은 형식이다

같은 내용을 한셀 2024 에서 `.cell` 과 `.xlsx` 로 저장해 파트별로 비교했다 (관측).
파트 구성이 같고 `.xlsx` 에도 `hs:` 확장과 `mc:AlternateContent` 가 그대로 들어간다.
구조상 차이는 **통합 문서 파트의 콘텐츠 타입 하나**다.

| 저장 형식 | `/xl/workbook.xml` 콘텐츠 타입 |
|---|---|
| `.cell` | `application/vnd.ms-excel.sheet.macroEnabled.main+xml` |
| `.xlsx` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet.main+xml` |

나머지 차이는 공유 문자열 순서(위 표)와 `absPath` 경로뿐이었다. 따라서 rcell 의 `.cell`
파서는 한셀이 만든 `.xlsx` 도 그대로 읽는다. 쓰기를 구현할 때는 개인정보 보호를 위해
`absPath` 를 기록하지 않는다.

**호환성 함정:** 접두사가 붙은 요소를 처리하지 못하는 단순 파서는 한셀 파일을 읽지 못한다.
rcell 은 모든 요소를 네임스페이스 URI 로 비교한다 (`src/xml.rs`).

## 4. `mc:AlternateContent` 로 감싼 스타일 (중요)

한셀은 `styles.xml` 의 `x:font`, `x:xf`, `x:dxf` 중 한컴 확장이 있는 항목을
**`mc:AlternateContent` 로 감싸서** 확장판(`mc:Choice Requires="hs"`)과
표준판(`mc:Fallback`)을 함께 저장한다 (관측).

```xml
<x:fonts>
  <x:font>…</x:font>                                  <!-- 글꼴 0 -->
  <mc:AlternateContent>                               <!-- 글꼴 1 -->
    <mc:Choice Requires="hs">
      <x:font hs:extension="1">
        <x:name val="맑은 고딕"/><x:sz val="10"/><x:u/>
        <hs:underlineShape val="solid"/>
        <hs:size val="100"/><hs:ratio val="100"/><hs:spacing val="0"/><hs:offset val="0"/>
      </x:font>
    </mc:Choice>
    <mc:Fallback>
      <x:font><x:name val="맑은 고딕"/><x:sz val="10"/><x:u/></x:font>
    </mc:Fallback>
  </mc:AlternateContent>
  <x:font>…</x:font>                                  <!-- 글꼴 2 -->
</x:fonts>
```

`mc:AlternateContent` 하나가 **항목 하나**로 세어진다. 이 래퍼를 건너뛰는 파서는
그 뒤의 모든 `fontId` / `s`(셀 서식 번호) 가 하나씩 밀려 엉뚱한 서식을 적용한다.
rcell 은 ECMA-376 Part 3 규칙대로 이해 가능한 첫 `mc:Choice` 를 고르고,
없으면 `mc:Fallback` 을 고른다 (`xml::resolve_alternate_content`).

## 5. 글꼴 확장 — `x:font hs:extension="1"`

한글 워드프로세서의 '글자 모양' 속성을 셀 글꼴에 더한 것으로 보인다.
값은 모두 자식 요소의 `val` 속성(색은 `rgb`)이다.

| 요소 | rcell 필드 | 의미 | 관측값 | 확인 |
|---|---|---|---|---|
| `hs:size` | `size` | 상대 크기 (%) | 100, 0(dxf) | 관측 |
| `hs:ratio` | `ratio` | 장평 (%) | 100, 0(dxf) | 관측 |
| `hs:spacing` | `spacing` | 자간 (%) | 0 | 관측 |
| `hs:offset` | `offset` | 글자 위치 (%) | 0 | 관측 |
| `hs:underlineType` | `underline_type` | 밑줄 위치 (1 = 아래로 추정) | 1 | 관측 |
| `hs:underlineShape` | `underline_shape` | 밑줄 모양 | `solid`(한 줄), `doubleslim`(두 줄) | 관측 |
| `hs:underlineColor` | `underline_color` | 밑줄 색 | rgb | 관측 |
| `hs:useFontSpace` | `use_font_space` | 글꼴에 어울리는 빈칸 | 0 | 관측 |
| `hs:strikeoutType` | `strikeout_type` | 취소선 종류 | 1 | 관측 |
| `hs:strikeoutShape` | `strikeout_shape` | 취소선 모양 | `solid` | 관측 |
| `hs:strikeoutColor` | `strikeout_color` | 취소선 색 | `ff000000` | 관측 |
| `hs:outlineType` | `outline_type` | 외곽선 | `solid` | 관측 |
| `hs:shadowType` | `shadow_type` | 그림자 종류 | `drop` | 관측 |
| `hs:shadowColor` | `shadow_color` | 그림자 색 | `ffc0c0c0` (기본) | 관측 |
| `hs:shadowOffsetX` / `Y` | `shadow_offset_*` | 그림자 거리 (%) | 10 / 10 (기본) | 관측 |
| `hs:shadeColor` | `shade_color` | 음영 색 | — | 문자열 |
| `hs:emboss` / `hs:engrave` | `emboss` / `engrave` | 양각 / 음각 | — | 문자열 |
| `hs:superscript` / `hs:subscript` | | 위첨자 / 아래첨자 (`x:vertAlign` 과 함께 기록) | 1 | 관측 |
| `hs:useKerning` | `use_kerning` | 커닝 | — | 문자열 |
| `hs:diacsymMark` | `diacsym_mark` | 강조점 | — | 문자열 |

조건부 서식의 `x:dxf` 안 글꼴에서는 `hs:size`/`hs:ratio` 가 `0` 으로 관측되었다.
'지정 안 함'을 뜻하는 것으로 **추정**한다.

한셀은 필요한 확장 요소만 쓴다 (관측). 그림자·외곽선·취소선·첨자만 설정한 글꼴에는
해당 요소만 있고 `hs:size`/`hs:ratio`/`hs:spacing`/`hs:offset` 이 없다. 밑줄을 설정한
글꼴에는 네 요소가 모두 기본값(100/100/0/0)으로 함께 기록되었다.

### 5.1 차분 실험 (COM 자동화)

한셀 COM 자동화(`HCell.Application`, Excel 호환 객체 모델)로 셀마다 Excel 표준 글꼴 속성을
하나씩 설정하고 `.cell` 로 저장해 비교했다 (한셀 13.0.0.711).

| Excel 속성 | 표준 요소 | 한컴 확장 |
|---|---|---|
| `Font.Shadow` | — | `shadowType=drop`, `shadowColor=ffc0c0c0`, `shadowOffsetX=10`, `shadowOffsetY=10` |
| `Font.OutlineFont` | — | `outlineType=solid` |
| `Font.Strikethrough` | `x:strike` | `strikeoutType=1`, `strikeoutShape=solid`, `strikeoutColor=ff000000` |
| `Font.Superscript` | `x:vertAlign=superscript` | `superscript=1` |
| `Font.Subscript` | `x:vertAlign=subscript` | `subscript=1` |
| `Font.Underline = 한 줄` | `x:u` | `underlineType=1`, `underlineShape=solid` |
| `Font.Underline = 두 줄` | `x:u val=double` | `underlineType=1`, `underlineShape=doubleslim` |
| `Font.Underline = 회계용 한 줄/두 줄` | `x:u` / `x:u val=double` | 일반 한 줄/두 줄과 같음 → **회계용 구분이 저장되지 않음** |

밑줄·취소선 모양 이름(`solid`, `doubleslim`)은 한글 문서(OWPML) 선 종류와 같은 계열이다.
`HncOOXML.dll` 문자열에 `dashdot`, `dashdotdot`, `longdash`, `slimthick`, `thickslim`,
`slimthickslim` 이 있어 나머지 모양도 같은 이름을 쓰는 것으로 **추정**한다.

## 6. 셀 서식 확장 — `x:xf hs:applyExtension="1"` / `hs:parashape`

```xml
<x:xf numFmtId="0" fontId="0" fillId="0" borderId="0" xfId="0" applyAlignment="1" hs:applyExtension="1">
  <x:alignment horizontal="center" vertical="center"/>
  <hs:parashape hs:lineSpacingType="betweenLines" hs:lineSpacing="75"
                hs:breakNonLatinWord="breakWord" hs:breakLatinWord="keepWord"
                hs:condense="0" hs:textAlignment="baseLine"/>
</x:xf>
```

값 타입은 `HncOOXML.dll` 이 export 하는 C++ 인터페이스 이름
(`OOXML::SPREADSHEET::CParashape::Get<속성>`)의 인자 타입에서 확인했다 (**심볼**).

| 속성 | 의미 | 타입 (심볼) | 관측값 | 확인 |
|---|---|---|---|---|
| `hs:lineSpacingType` | 줄 간격 종류 | 열거 `ST_LineSpacing` | `betweenLines` (후보 `atLeast`) | 관측 |
| `hs:lineSpacing` | 줄 간격 값 | `unsigned int` | 74, 75 | 관측 |
| `hs:prevSpacing` / `hs:nextSpacing` | 문단 위/아래 간격 | `unsigned int` | — | 심볼 |
| `hs:breakLatinWord` | 영어 단어 나눔 | 열거 `ST_LineBreak` | `keepWord` | 관측 |
| `hs:breakNonLatinWord` | 한글 단어 나눔 | 열거 `ST_LineBreak` | `breakWord` | 관측 |
| `hs:condense` | 최소 공백 (%) | `unsigned int` | 0 | 관측 |
| `hs:textAlignment` | 세로 정렬 기준 | 열거 `ST_TextAlignment` | `baseLine` | 관측 |
| `hs:fontLineHeight` | 글꼴에 어울리는 줄 높이 | `bool` | — | 심볼 |
| `hs:leftMargin` | 왼쪽 여백 | `unsigned int` | 들여쓰기 n단계 → `1134 × n` | 관측 |
| `hs:rightMargin` | 오른쪽 여백 | `unsigned int` | 오른쪽 정렬 + 들여쓰기 2 → `2268` | 관측 |
| `hs:indentation` | 첫 줄 들여쓰기(+)/내어쓰기(−) | `int` (부호 있음) | — | 심볼 |
| `hs:abstractNumId` / `hs:abstractNumType` | 문단 번호 | `unsigned int` | — | 심볼 |

여백 단위 1134 는 HWPUNIT(1/7200 인치)로 보면 정확히 4.0 mm 다. 한글 문서와 같은
HWPUNIT 를 쓰는 것으로 **추정**한다.

`x:xf` 의 자식 `hs:accountUnderline` 은 `CAccountUnderline::Getshape(ST_UnderlineValues&)` 로
보아 회계용 밑줄 모양을 담는다 (**심볼**). 단, COM 으로 회계용 밑줄을 설정했을 때는 기록되지 않았다.

`x:dxf` 에도 `hs:applyExtension="1"` 이 붙는다 (관측).

### 6.1 `hs:parashape` 가 기록되는 조건 (COM 차분 실험)

| Excel 정렬 속성 | 표준 `x:alignment` | `hs:parashape` |
|---|---|---|
| 기본 | `horizontal="general" vertical="center"` | 없음 |
| 가로 균등 분할 (`xlDistributed`) | `horizontal="distributed"` | 있음 |
| 가로 양쪽 맞춤 (`xlJustify`) | `horizontal="justify"` | 있음 |
| 들여쓰기 (`IndentLevel`) | `indent="n"` | 있음 + `leftMargin`/`rightMargin` |
| 오른쪽에서 왼쪽 (`ReadingOrder`) | `readingOrder="1"` | 있음 |
| 선택 영역 가운데, 세로 균등/양쪽, 회전, 세로 쓰기, 축소, 줄 바꿈 | 표준 속성만 | 없음 |

**한셀의 기본 세로 정렬은 `center`** 다 (Excel 은 `bottom`). 렌더러는 `vertical` 속성이
없을 때의 기본값을 작성 프로그램에 따라 달리 해야 한다.
`spreadsheet/9.0/Alignment` 네임스페이스는 이 실험들에서도 나타나지 않았다.

## 6.2 export 심볼로 확인한 한컴 확장 클래스

`HncOOXML.dll` 은 C++ 클래스 인터페이스를 이름으로 export 한다. 함수 본문이 아니라
**이름과 인자 타입만** 사용했다 (`OOXML::SPREADSHEET` 네임스페이스).

| 클래스 | 대응 요소 (추정) | 값 타입 |
|---|---|---|
| `CParashape` | `hs:parashape` | 위 표 |
| `CUnderlineProperty` | `hs:underlineType` | `ST_UnderlineValues` |
| `CUnderlineExProperty` | `hs:underlineShape` / `hs:strikeoutShape` | `ST_UnderlineShape` |
| `COutlineProperty` | `hs:outlineType` | `ST_OutlineType` |
| `CShadowProperty` | `hs:shadowType` | `ST_ShadowType` |
| `CDiacsymProperty` | `hs:diacsymMark` | `ST_DiacsymMark` |
| `CAccountUnderline` | `hs:accountUnderline` | `shape: ST_UnderlineValues` |
| `CHCLWordshop` | 글맵시(워드아트) 개체 | `text`, `fontName`, `fontSize`, `b`, `i`, `shapeIndex`, `templateIndex`, `macro` |
| `CExtension::SetLicense` | `hs:license` | — |
| `CCalcPr::GethclCalcId` | `calcPr/@hs:hclCalcId` | `unsigned int` |
| `CFont`, `CRPrElt` | 셀 글꼴, **공유 문자열 런 글꼴(`x:rPr`)** | `ratio`, `spacing`, `size`, `offset`, `shadow*`, `strikeout*`, `underline*`, `outlineType`, `emboss`, `engrave`, `superscript`, `subscript`, `useFontSpace`, `useKerning`, `shadeColor`, `diacsymMark` |

`CRPrElt` 에도 같은 setter 가 있으므로 **서식 있는 텍스트의 런마다 한컴 글꼴 확장이 붙을 수 있다**.
rcell 은 런 글꼴(`x:rPr`)도 같은 파서로 읽는다.

## 7. 기타 확장

### 7.1 통합 문서 창과 코드 이름 (통합 문서 창 대조 실험)

`x:bookViews/x:workbookView` 의 값을 바꾼 XML 을 한셀로 열어 세 형식으로 저장하고 다시 읽었다 (관측).

| 속성 | XML | 바이너리 BrtBookView | 레거시 WINDOW1 |
|---|---|---|---|
| `xWindow`/`yWindow` (1/20 pt, 음수 가능) | 지킨다 | `xWn`/`yWn` i32 | i16 |
| `windowWidth`/`windowHeight` | 지킨다 (원본에 없으면 0) | `dxWn`/`dyWn` | u16 |
| `tabRatio` (1/1000, 기본 600 은 쓰지 않는다) | 지킨다 | `iTabRatio` (오프셋 16) | `wTabRatio` |
| `firstSheet` / `activeTab` (기본 0 은 쓰지 않는다) | 지킨다 | `itabFirst` / `itabCur` | `itabFirst` / `itabCur` |
| `showHorizontalScroll` / `showVerticalScroll` | 지킨다 | 플래그 0x08 / 0x10 | **잃는다** (grbit 0x08·0x10 을 늘 켠다) |
| `showSheetTabs` | 지킨다 | 플래그 0x20 | grbit 0x20 |
| `autoFilterDateGrouping="0"` | 버린다 | | |

한셀은 끄기로 한 표시 속성을 위치 속성보다 앞에 쓴다 (`<x:workbookView showSheetTabs="0" xWindow=… tabRatio=…/>`).
`x:workbookPr/@codeName` 은 세 형식 모두 지킨다 (바이너리 BrtWbProp 의 이름, 레거시 전역 CODENAME). 원본에 없으면
`ThisWorkbook` 을 채운다. `workbookPr` 의 다른 값(`backupFile="1"`, `saveExternalLinkValues="0"`, `filterPrivacy="1"`)은
저장하지 않고 기본값을 쓴다.

### 7.2 자동 필터의 값 (필터 값 대조 실험)

`dynamicFilter` 의 `val`·`maxVal`(평균 위/아래의 평균값, 기간의 시작·끝 날짜 일련번호)은 한셀이 다시 계산하지 않고
파일 값을 그대로 쓴다 — 값이 없는 문서를 열어 저장하면 평균·오늘·올해 누계 같은 종류에 `val="0"` 을 쓰고 분기·달 종류에는
아무것도 쓰지 않는다. 세 형식 모두 지킨다 (바이너리 `BrtDynamicFilter`, 레거시 ContinueFrt12). `top10/@filterVal` 은 한셀이
필터를 적용할 때 계산해 넣는 경계값이라 같은 문서의 저장본에 있기도 없기도 하다. XML 저장은 있는 값만 쓰고, 바이너리 저장은
없으면 데이터로 셈해 쓴다 ([cell-binary.md](cell-binary.md) 4.7절). 레거시에도 있지만 (AUTOFILTER 의 DOPER 1) 한셀은 레거시를
읽을 때 버린다.

### 7.3 문서 속성 파트 (편집 시간 대조 실험)

`docProps/app.xml` 에서 한셀이 지키는 값은 `TotalTime`(편집 시간, 분)뿐이다 — XML·바이너리는 app.xml 그대로,
레거시는 SummaryInformation PID 0x0A. 한셀은 저장할 때 시간을 더하지 않고 원본 값을 쓴다 (서식 파일 51·77·134·979,
조작한 1234·70000 이 세 형식을 거쳐 그대로). `Company`·`Manager`·`HyperlinkBase` 와 `docProps/custom.xml`(사용자 정의
속성), core.xml 의 `dc:language`·`dc:identifier` 는 버린다. 한셀은 core.xml 에 `cp:version`(`1300.0100.01`)을 쓴다.

`CFont::InitMap` 이 등록하는 글꼴 자식 요소 전체 (등록 순서):

```
x:name x:charset x:family x:b x:i x:strike x:dstrike x:outline x:shadow x:condense
x:extend x:color x:sz x:u x:vertAlign x:scheme
hs:emboss hs:engrave hs:superscript hs:subscript hs:shadeColor hs:shadowColor
hs:underlineColor hs:strikeoutColor hs:underlineType hs:underlineShape hs:strikeoutType
hs:strikeoutShape hs:shadowType hs:shadowOffsetX hs:shadowOffsetY hs:outlineType
hs:diacsymMark hs:useFontSpace hs:useKerning hs:size hs:ratio hs:spacing hs:offset
```

한컴 글꼴 확장은 이 21개가 전부이며, rcell 모델(`HancomFontExt`)이 모두 다룬다.

### 7.4 조건부 서식의 x14 확장 (x14 조건부 서식 실험)

Excel 2010 의 확장 그대로다: 본 규칙 `x:cfRule` 의 `x:extLst/x:ext uri="{B025F937-C7B1-47D3-B67F-A62EFF666E3E}"` 에
`x14:id`, 시트 끝 `x:extLst/x:ext uri="{78C0D931-6437-407d-A8EE-F0AAD7539E65}"` 의 `x14:conditionalFormattings` 에 같은 id 의
`x14:cfRule` 과 `xm:sqref`. 조작한 XML(데이터 막대 13개, x14 아이콘 집합 7개, 수식 규칙 1개)을 한셀로 저장하고 다시 저장해
대조했다 (관측).

| 항목 | 한셀 |
|---|---|
| 데이터 막대 | 막대마다 늘 x14 확장을 쓴다. 확장이 없는 막대를 읽으면 `direction="leftToRight"`, 기준 값은 본 규칙 것(`min`/`max`)으로 만든다 |
| `x14:dataBar` 속성 | `minLength maxLength showValue border gradient direction negativeBarColorSameAsPositive negativeBarBorderColorSameAsPositive axisPosition` 순서, 기본값(10, 90, 1, 0, 1, `context`, 0, 1, `automatic`)은 쓰지 않는다 |
| 하나의 막대 | 길이·값 표시·기준 값은 x14 쪽이 이긴다. 본 규칙에도 같은 길이와 값 표시를 쓰고, 본 규칙의 기준 값은 x14 것에서 `autoMin`→`min`, `autoMax`→`max` 로 바꿔 쓴다 (`<xm:f>5</xm:f>` → `<x:cfvo type="percent" val="5"/>`) |
| 색 | `borderColor`·`negativeFillColor`·`negativeBorderColor`·`axisColor` 를 속성과 상관없이 있는 그대로 쓴다 (`border="0"` 인데 테두리 색, `negativeBarColorSameAsPositive="1"` 인데 음수 색도). `x14:fillColor` 는 버린다 (막대 색은 본 규칙의 `x:color`). 테마 색은 RGB 로, `indexed="10"`·`indexed="64"`·`auto="1"` 은 그대로 |
| 아이콘 집합 | x14 구역에서 읽은 아이콘 집합과 Excel 2010 집합(3Stars, 3Triangles, 5Boxes — 본 구역에 있어도)은 x14 구역에 `custom="1"` 을 붙여 쓴다. 사용자 지정 아이콘 `x14:cfIcon iconSet iconId` (`NoIcons` 포함)을 지킨다. 값은 `xm:f` |
| 그 밖의 x14 규칙 | 시트 이름을 붙인 수식 규칙(`<xm:f>Sheet1!$A$1&gt;0</xm:f>` + 규칙 안 `x14:dxf`)은 처음 저장에서 x14 구역에 id 없이 쓰고 차등 서식 표 끝에 서식을 더한다. 그것을 다시 저장하면 본 구역의 `dxfId` 규칙이 된다 |

rcell 은 x14 확장을 `DataBar::ext`(`DataBarExt`), 사용자 지정 아이콘을 `IconSet::custom_icons`, x14 구역 규칙을 `CfRule::x14` 로
읽고 같은 꼴로 쓴다 (id 는 시트 번호와 규칙 순번으로 만든다 — 한셀은 읽은 id 를 그대로 다시 쓴다). 수식 규칙은 본 구역 규칙으로 읽는다.
레거시·바이너리의 대응은 [cell-legacy.md](cell-legacy.md) 6.3절, [cell-binary.md](cell-binary.md) 2.3절.

### 7.5 메모 상자와 작성자 (메모 대조 실험)

VML 메모 도형의 값을 바꾼 XML(메모 12개)을 한셀로 저장하고 다시 저장해 대조했다 (관측). 한셀이 쓰는 꼴:

```xml
<v:shape id="메모 1" style="position:absolute;visibility:hidden;z-index:0" o:spid="_x0000_s1" o:hralign="left"
         o:insetmode="auto" stroked="t" strokecolor="#000000" strokeweight="0.75pt" filled="t" fillcolor="#ffffe1"
         o:connectortype="straight" type="#_x0000_t202">
  <v:stroke weight="0.75pt" color="#000000" joinstyle="miter" filltype="solid"/>
  <v:shadow on="t" obscured="t" color="#000000"/>            <!-- 그림자가 있을 때만 -->
  <v:path o:connecttype="none"/><v:textbox style="mso-direction-alt:auto"/>
  <x:ClientData ObjectType="Note"><x:MoveWithCells></x:MoveWithCells><x:SizeWithCells></x:SizeWithCells>
    <x:Anchor>0, 14, 7, 10, 1, 70, 11, 1</x:Anchor><x:AutoFill>False</x:AutoFill>
    <x:TextHAlign>Center</x:TextHAlign><x:TextVAlign>Center</x:TextVAlign><x:Row>9</x:Row><x:Column>0</x:Column>
    <x:Visible></x:Visible><x:ShapeUri>{…}</x:ShapeUri></x:ClientData>
</v:shape>
```

| 값 | 한셀 |
|---|---|
| `x:Anchor` (열, px, 행, px × 2) | 지킨다 — 메모 상자의 자리와 크기. `style` 의 `margin-left`·`width` 등은 버리고 `z-index` 는 0부터 새로 매긴다 |
| `fillcolor`, `strokecolor`, `strokeweight` | 지킨다. 선 두께가 1 pt(VML 기본값)이면 `strokeweight` 를 쓰지 않고, 두께가 없는 메모는 0.75 pt 로 읽는다 — 1 pt 는 한 번 더 저장하면 0.75 pt 가 된다 |
| `v:shadow on="t"` | 있고 없음을 지킨다 |
| `x:MoveWithCells` / `x:SizeWithCells` | 있고 없음을 지킨다 (있으면 셀에 고정 — 이름과 반대). 한셀의 새 메모는 둘 다 있다 |
| `x:TextHAlign` / `x:TextVAlign` | 지킨다 (`Right`, `Bottom`, `Justify`, `Distributed` …) |
| `x:AutoFill` | 늘 `False` 를 쓴다 |
| `stroked="f"`·`filled="f"` | 선 `#2e3e67` 1.5 pt, 흰색 채우기가 된다 |

**작성자**: 한셀은 `x:authors` 를 쓰이는 이름만 정렬해서 쓰지만 `authorId` 는 메모 순서로 처음 나온 작성자의 번호
(0, 1, …)를 쓴다 — 둘이 어긋나 메모의 작성자가 바뀐다 (`Zeta, Unused, Alpha, ""` 의 메모 다섯 개 → 목록 `"", Alpha, Zeta`,
`Zeta` 의 메모가 `""` 가 된다). 바이너리 `BrtCommentAuthor`·`iauthor` 도 같고, 레거시 NOTE 는 이름을 직접 담아 바르다.
처음 나온 순서가 정렬 순서와 같아지면 더 바뀌지 않는다. rcell 은 메모 순서와 작성자 이름을 그대로 지키므로 한셀이 다시
저장한 결과가 같다.

rcell 은 상자를 `Comment::shape`(`CommentShape`)로 읽고 위의 꼴로 쓴다. 레거시는 [cell-legacy.md](cell-legacy.md) 6.2절.

### 7.6 배열 수식·데이터 표·이름 (수식 대조 실험)

| 항목 | 한셀 |
|---|---|
| 배열 수식 | 표준 그대로: 범위의 왼쪽 위 셀에 `<x:f t="array" ref="A1:A3">B1:B3*2</x:f>`, 범위 안 다른 셀은 값만. 한 칸 범위도 `ref="C1:C1"` 로 쓴다 |
| 데이터 표 | 왼쪽 위 셀에 `<x:f t="dataTable" ref="F3:F5" r1="D1"/>`, 다른 셀은 값만. 속성 순서 `ref dt2D dtr r1 r2`, 기본값(0)은 쓰지 않는다. 2변수 표(`dt2D="1"`, `r1` 행 입력·`r2` 열 입력)에는 `dtr` 을 쓰지 않는다. `del1`·`del2` 는 버린다. 행 입력 표(`dtr="1"`)의 값을 다시 계산해 0 으로 쓰기도 한다 |
| 이름 | `localSheetId`(시트 범위, 두 시트에 같은 이름 가능)·`hidden`·`comment`(설명) 를 지킨다. 다른 시트 범위의 이름은 수식에 `Sheet1!L` 로 쓴다 |

rcell 은 `Formula::kind`·`range`·`data_table`(`DataTableInput`), `DefinedName::comment` 로 읽고 같은 꼴로 쓴다.
`rcell diff` 는 배열 수식의 범위, 데이터 표의 범위·입력, 이름의 범위·숨김·설명까지 본다 (공유 수식은 저장 방식이라 원문만).

### 7.8 하이퍼링크의 화면 설명 (하이퍼링크 대조 실험)

하이퍼링크 7개(외부 주소·메일·파일+위치·시트 안 위치·범위, 화면 설명 `tooltip` 과 표시 글 `display`)를 한셀로 저장하고
다시 저장해 대조했다 (관측). 한셀은 `ref` 를 늘 범위로 쓰고(`A1:A1`), `tooltip` 을 지키며 `display` 는 버린다. `tooltip` 의 줄
바꿈(`&#10;`)은 속성에 그대로 써서 다시 읽으면 빈칸이 된다. 바이너리 `BrtHLink` 는 설명을 지키지만 관계 ID·위치가 없는 링크에
앞 링크의 값을 남기고([cell-binary.md](cell-binary.md) 2절), **레거시는 설명을 저장하지 않는다** — 한셀은 레거시를 읽을 때
주소(대상, 없으면 위치)를 설명으로 채운다. `rcell diff` 는 주소를 되풀이한 설명을 설명 없음으로 본다.

### 7.9 도형의 그림자·잠금·선 (도형 대조 실험)

도형 25개(그림자·잠금 11종·`clientData`·선 끝/겹선/이음/화살표·글 넘침·연결선·`mc:AlternateContent`)를 한셀로 저장하고 다시
저장해 대조했다 (관측). XML 에서 한셀은 `a:effectLst/a:outerShdw`(blurRad·dist·dir·algn·rotWithShape·alpha), `a:spLocks` 의 모든 속성
(순서만 바꾼다), `xdr:clientData` 의 `fLocksWithSheet`·`fPrintsWithSheet`, `a:ln` 의 `cap`·`cmpd`·이음(`a:miter` 의 `lim` 은 버린다)·
`a:headEnd`/`a:tailEnd`, `a:bodyPr` 의 `vertOverflow`·`horzOverflow` 를 지킨다. `mc:AlternateContent` 로 감싼 앵커는 알아듣는 분기
(`Requires="a14"`)를 풀어 보통 앵커로 쓴다. 레거시가 담는 것과 잃는 것은 [cell-legacy.md](cell-legacy.md) 6.2절.

rcell 은 XML·바이너리의 그리기 파트를 앵커째 원문으로 다시 쓰므로(모르는 개체를 담은 앵커와 `mc:AlternateContent` 도 그대로)
이 값들을 모두 지킨다. 모델(`Shape::shadow`·`locks`·`locks_with_sheet`·`prints_with_sheet`, `Outline::cap`·`compound`·`join`·`head`·
`tail`, `TextBody::vert_overflow`·`horz_overflow`)은 비교와 레거시 도형의 저장에 쓴다.

### 7.10 패키지 파트 (패키지 파트 실험)

한셀 저장본에 표·프린터 설정·사용자 지정 XML·연결과 쿼리 표·피벗(캐시·레코드·표)·매크로 프로젝트를 넣어 세 형식으로 저장하고
다시 저장해 대조했다 (관측).

| 파트 | 관계 (종류 끝부분) | 한셀 |
|---|---|---|
| 표 `xl/tables/tableN.xml` | 시트 → `table`, 시트의 `x:tableParts` | 지킨다 (세 형식). 다시 쓸 때 파트 번호를 새로 매기고 `totalsRowBorderDxfId="0"` 을 늘 쓴다. 계산 열 수식(`calculatedColumnFormula`)과 표 설명(`comment`)은 버리고, 요약 행 사용자 수식(`totalsRowFormula`)은 지킨다. 셀의 구조적 참조는 글을 다시 만든다 (`Table1` → `Table1[]`, `[[#Headers],[#Data],[열]]` → `[[#Data],[#Headers],[열]]` — [cell-binary.md](cell-binary.md) 2절). 데이터 영역의 차등 서식(`dataDxfId`)은 셀 테두리의 색에서 다시 만든다 — 선 종류 없는 테두리 색을 버린 문서를 읽으면 `dataDxfId` 가 사라지고 남은 차등 서식이 하나로 합쳐진다 |
| 피벗 `xl/pivotTables/pivotTableN.xml` → `xl/pivotCache/pivotCacheDefinitionN.xml` → `pivotCacheRecordsN.xml` | 시트 → `pivotTable`, 통합 문서 → `pivotCacheDefinition` + `x:pivotCaches`(`cacheId`) | 지킨다 (세 형식). 기본값 속성을 모두 쓰고(`subtotal="sum"` …), 레코드의 숫자를 공유 항목(`x:n`)으로 옮겨 `x:x` 로 가리킨다 |
| 프린터 설정 `xl/printerSettings/printerSettingsN.bin` | 시트 → `printerSettings`, `pageSetup r:id` | 버린다 |
| 사용자 지정 XML `customXml/itemN.xml` + `itemPropsN.xml` | 통합 문서 → `customXml` | 버린다 |
| 연결 `xl/connections.xml`, 쿼리 표 `xl/queryTables/queryTableN.xml` | 통합 문서 → `connections`, 시트 → `queryTable` | 버린다 (외부 데이터 이름은 남는다) |
| 매크로 프로젝트 `xl/vbsProject.bin` | 통합 문서 → `http://schemas.hancom.com/office/relationships/vbsProject`, 콘텐츠 타입 `application/vnd.hancom-office.vbsProject` | 지킨다. 파트는 OLE2 복합 문서이고 스트림 `_VBS_PROJECT_W` 하나를 담는다. 바이너리도 같은 파트, 레거시는 OLE 루트의 같은 이름 스트림 — 세 형식에서 스트림 바이트가 같다. 스트림: 머리 0x104 바이트(`01 01 01 00 00 01 20 02`, 나머지 0), 글자 수 `u32`, UTF-16 글(`CLASS CLS_GM_MODULE` … `End Class` 꼴의 모듈 글). 파트가 복합 문서가 아니면 한셀은 문서를 열지 못한다 |

COM 으로 매크로를 넣으려면 `Workbook.SetCurrentBookScript(글, True)` 를 쓴다 (`ScriptObjects.Add` 는 아무것도 만들지 않는다).
한셀은 매크로가 든 바이너리(xlCellb) 저장본을 다시 열다 멈췄다 (RPC_E_SERVERFAULT).

rcell 은 XML 원본의 이 파트들을 관계가 가리키는 파트까지 그대로 옮겨 쓰고(`Workbook::part_links`·`Sheet::part_links`, 표는
`Sheet::tables` 모델로도 읽는다), 참조 요소(`x:tableParts`, `x:pivotCaches`, `pageSetup r:id`)를 새 관계 ID 로 쓴다. 바이너리
원본에서는 형식이 같은 파트(매크로 프로젝트·사용자 지정 XML·프린터 설정)만 옮긴다. 바이너리 표 파트·레거시 표 레코드(0xB005…)와 구조적 참조(PtgList)는 모델로 읽어 표 파트를 새로 쓴다 — 바이너리·레거시의 피벗은 아직 읽지 않는다. 레거시의 `_VBS_PROJECT_W` 는 스트림 하나짜리
복합 문서로 싸서 `xl/vbsProject.bin` 에 쓴다 (`src/cfb_write.rs`). Excel 형식(`.xlsx`)에는 매크로 프로젝트를 쓰지 않는다. 셀
테두리는 선 종류가 없어도 색을 쓴다 (위 표의 `dataDxfId`). `rcell diff` 는 표(차등 서식은 번호가 아니라 내용으로), 피벗 표(위치·
캐시 원본·필드 축·데이터 필드), 옮긴 파트의 관계 종류, 매크로 스트림을 비교한다.

### 7.11 표시 형식 (표시 형식 대조 실험)

한셀 COM 으로 셀에 값과 서식 코드를 넣고 `Range.Text` 를 읽어 대조했다 (`tools/probe/numfmt-oracle.ps1` 과 추가 실험,
4818 칸 — 관측). 서식 코드는 파일에 쓴 그대로 읽히지만 표시가 Excel 과 다른 것:

| 서식 | 한셀 표시 |
|---|---|
| 일반 | 1 이상은 유효숫자 10자리, 1 보다 작으면 9자리 (`1234567.891`, `3.141592654`, `0.333333333`, `0.000123456789`). 정수부가 12자리 이상이면 지수 (가수 유효숫자 6자리 `1.23457E+11`). 0.0001 보다 작은 수는 소수 7자리 안에 들면 그대로 (`0.0000123`, `0.0000001`), 아니면 지수 — 음의 지수는 0 을 채우지 않는다 (`1.234E-5`, `1E-9`) |
| `@` 의 숫자 | 유효숫자 15자리 (`3.14159265358979`, `123456789012`, `0.000000001`) |
| `[DBNum1]` | 한자 숫자 `０一二三四五六七八九` — 0 은 전각 ０, **六 은 호환 한자 U+F9D1** |
| `[DBNum2]` | 갖은자 `零壹貳參四伍六七八九` (零 U+F9B2, 參 U+F96B, 六 U+F9D1 — 四·七·八·九 는 보통 한자), 자리 이름 拾(U+F973)·百·阡·萬·億·兆 |
| `[DBNum3]` | 전각 숫자 `０１２…９`, 자리 이름은 DBNum1 과 같다 (十·百·千·万·億·兆) |
| `[DBNum4]` | 한글 `영일이삼사오육칠팔구`, 자리 이름 십·백·천·만·억·조 |
| `[DBNum]` 일반 서식 | 정수부는 자릿값 읽기, 네 자리마다 万·億·兆. 0 인 자리는 건너뛰고, DBNum1·3 은 十·百·千 앞의 1 을 쓰지 않는다 (`12` → 十二, `105` → 百五, `11000` → 一万千, `20` → ２十), DBNum2·4 는 쓴다 (壹拾貳, 일만일천). 소수점 뒤는 숫자마다, 지수까지 (`1.5E+20` → 一.五E+二０; 소수점이 없으면 지수는 그대로 `1E+15` → 一E+15). 유효숫자 15자리, 1E+15 부터·0.0001 보다 작으면 지수 |
| `[DBNum]` 자리 표시자 서식 | 숫자마다 (`105` → 一０五, `#,##0` → 一,二三五), 쉼표·소수점·`E+`·따옴표 안 글자(`0"1"` → 二一1)는 그대로 |
| `[DBNum]` 날짜 | 연도는 숫자마다 (二０二六), 월·일·시·분·초는 자릿값 (十, 十九, 三十七 — 두 자리 꼴의 한 자리 값은 앞에 0: `mm` 7 → ０七). DBNum3 은 모두 숫자마다 (１０월) |
| `[DBNum]` 범위 | 그 구역에만 (`[DBNum1][>100]0;0.0` 의 10 → `10.0`) |
| `G/표준` | 일반 서식이 아니다: `G` 는 연호(한국어에서 빈칸)라 `/표준` 이 보이고 음수는 `#` — COM 으로 넣으면 `g/표준` 으로 바뀐다. 파일에서 읽어도 같다 |
| 조건 구역 | `[<0]` 구역만 음수 부호를 뺀다. 다른 조건(`[<=0]`, `[<-5]`, `[<=9999999]`, 둘째 구역의 `[<-100]`)은 음수에 `-` 를 붙인다 (`[<=9999999]###-####` 의 -1 → `--1`) |
| 분수 | 분모가 고정된 분수(`# ?/8`)도 분수다 (`1234 5/8`, 분자가 0 이면 `1 `). 정수 자리가 없는 고정 분모(`?/4`)는 정수부를 버린다 (4385.5 → `2/4`, 정수 → 빈칸). 정수부 0 은 자리 표시자가 `0` 일 때만 (`0 ?/2` → `0 1/2`) |
| 공학 표기 | `##0.0E+0`: 값을 (정수 자리 표시자 + 소수 자리) 유효숫자로 반올림한 뒤 가수의 소수를 자른다 (1999 → `1.9E+3`, 32874.25 → `32.8E+3`, 987654 → `987.7E+3`). 지수가 음수면 3 의 배수로 맞추지 않는다 |
| `[$-412]` | AM/PM·A/P 모두 오전/오후 (`h:mm AM/PM` → `4:00 오후`) |
| `[$-F800]`, `[$-F400]` | 시스템 긴 날짜·시간: 구역의 나머지와 상관없이 `2026년 10월 19일 월요일`, `오후 1:37:38`. 시간은 원래 구역에 초가 없으면 초를 자른다 (`[$-F400]h` 의 8.64초 → `오전 12:00:08`) |
| `[$-411]` | 일본 연호: `g` 머리글자(M·T·S·H·R), `gg` 첫 한자(明…), `ggg` 이름(明治… — 해가 없는 구역에서는 빈칸), `e`·`ee` 연호의 해 (0 을 채우지 않는다) |
| `[$-804]` | `aaaa` 는 `星期六` |
| `[$-409]`, `[NatNum1]`, `[빨강]` | `[$-409]` 는 영어 그대로. `[NatNum1]` 과 한국어 색 이름(`[빨강]`)은 COM 으로 넣으면 서식으로 받지 않는다 (일반 서식이 남는다) |

rcell 의 표시 형식 엔진(`src/numfmt.rs`)이 이 결과를 그대로 낸다 (`tests/numfmt_oracle.rs` 로 대조: 불일치 0).

## 8. 열거형 값 (바이너리 — 변환표)

`HncOOXML.dll` 은 열거형을 `{wchar_t* 이름, int 값}` 쌍 배열로 갖고,
`{타입 이름, 개수, 배열}` 등록부에서 타입 이름(`L"ST_ShadowType"`)으로 찾는다.
아래는 한셀 스프레드시트 등록부의 배열을 그대로 옮긴 값 목록이다. 정수는 배열 위치와 같다.
rcell 은 이 목록을 `src/vocab.rs` 에 두고 `rcell scan` 에서 목록 밖의 값을 경고한다.

| XML | 타입 | 값 (0부터) |
|---|---|---|
| `hs:lineSpacingType` | `ST_LineSpacing` | `percent`, `fixed`, `betweenLines`, `atLeast` |
| `hs:breakLatinWord`, `hs:breakNonLatinWord` | `ST_LineBreak` | `keepWord`, `breakWord` |
| `hs:textAlignment` | `ST_TextAlignment` | `baseLine`, `top`, `center`, `bottom` |
| `hs:underlineShape`, `hs:strikeoutShape` | `ST_UnderlineShape` | `solid`, `dash`, `dot`, `dashdot`, `dashdotdot`, `longdash`, `circle`, `doubleslim`, `slimthick`, `thickslim`, `slimthickslim` |
| `hs:shadowType` | `ST_ShadowType` | `none`, `drop`(비연속), `continuous`(연속) |
| `hs:outlineType` | `ST_OutlineType` | `none`, `solid`, `dot`, `thick`, `dash`, `dashdot`, `dashdotdt` ← 철자 원문 그대로 |
| `hs:diacsymMark` | `ST_DiacsymMark` | `none`, `dot_above`, `ring_above`, `tilde`, `caron`, `sideout`, `colon`, `grave_accent`, `acute_accent`, `circumflex_accent`, `macron`, `hook_above`, `dot_below` |
| `hs:accountUnderline/@shape` | `ST_UnderlineValues` | `single`, `double`, `singleAccounting`, `doubleAccounting`, `none` |

`hs:underlineType`, `hs:strikeoutType` 은 문자열 열거가 아니라 **정수**로 기록된다 (관측값 `1`).
`ST_LineSpacing` 네 값은 한글 '문단 모양'의 줄 간격 종류(글자에 따라 / 고정 값 / 여백만 지정 /
최소)와 순서가 같아 `percent`=글자에 따라, `betweenLines`=여백만 지정으로 **추정**한다.
이 경우 관측값 `lineSpacing="75"` 는 줄 사이 여백이며 단위는 미확인이다.

분석 근거: REA 6.7.0 + Ghidra 12.1.4 (`trace`/`xrefs`, Evidence `ev_fe0742dc…`),
`HncOOXML.dll` SHA-256 `8a5fb336…46c7`. 분석 산출물은 저장소에 넣지 않았다.

## 9. 한셀이 XML 을 읽고 다시 저장할 때 스스로 바꾸는 것 (관측)

같은 XML 문서를 한셀로 열어 그대로 다시 저장하면(`Workbook.Saved = False` 후 `SaveAs`, 아래 첫 항목) 다음이 바뀐다.
rcell 의 저장 검증은 이 변화를 빼기 위해 HCell(원본) 과 HCell(rcell(원본)) 을 비교한다
([reverse-engineering.md](../reverse-engineering.md) 7절).

| 대상 | 바뀌는 것 |
|---|---|
| 같은 형식 `SaveAs` | 바뀐 것이 없는 문서면 **다시 쓰지 않고 파일을 그대로 복사**한다 |
| 여백 (`pageMargins`) | 읽을 때 HWPUNIT(1/7200 인치)로 **자른다** — 정수 단위 바로 아래 값(f32 를 거친 `0.51152777…` = 3682.99… 단위)은 한 단위를 잃는다. 머리글·바닥글 여백은 저장할 때마다 한 단위씩 계속 줄어든다 (0.511805 → 0.511666 → 0.511527 …). rcell 은 그런 값을 0.01 단위 위로 쓴다 |
| 차등 서식 (`x:dxf`) | 테마·색인 색을 RGB 로 바꾸고, 표시 형식 번호를 4294967295 로 쓰고, 위/아래 첨자·들여쓰기·글꼴 이름·외곽선·그림자·대각선 테두리와 보호 값(`<x:protection/>` 만 남는다)을 버린다. 이중 회계 밑줄을 단일 회계로 쓰고(바이너리·레거시는 지킨다), 글꼴 크기를 정수 pt 로 자른다. 한컴 확장이 붙은 글꼴은 표준 자식이 없어도 남기고, 확장 없는 빈 글꼴은 버린다 |
| 셀 스타일 | 셀 서식이 쓰는 스타일과 표준 스타일만 쓴다 |
| 표 스타일 | 요소를 종류 번호 순으로 정렬하고 `size`·`pivot`·`table` 을 늘 쓴다. 사용자 정의 스타일이 없어도 `tableStyles` 를 쓴다 (`TableStyleMedium2`·`PivotStyleLight16`) |
| 문단 번호 | `x:abstractNums` 를 문단 모양에서 새로 만든다: 번호가 있는 문단 모양이 있으면 하나 (`abstractNumType="1" abstractNumId="0" startNum="0" lvlText="%5e1."`), 문단 모양은 모두 그 번호를 가리킨다 |
| 글꼴 외곽선 | `hs:outlineType` 이 있으면 `x:outline` 을 켠다 (그림자 종류는 `x:shadow` 를 켜지 않는다) |
| 줄 간격 | `hs:lineSpacingType="atLeast"` → `betweenLines` |
| 취소선 | 취소선 모양(`hs:soShape`)이 있으면 표준 취소선(`x:strike`)을 켠다 |
| 개요 | `outlinePr summaryRight="0"` 을 잃는다 (요약 행 위치는 남는다) |
| 인쇄 | `pageSetUpPr autoPageBreaks="0"` 을 잃는다. 머리글·바닥글에서 글꼴 코드가 없는 구역에 기본 글꼴(`&"맑은 고딕,Regular"`)을 넣는다 |
| 틀 | 나눈 창(고정 아님)의 활성 창 `bottomLeft` → `topLeft` |
| 그리기 | 앵커를 내부 절대 좌표에서 다시 계산해 오프셋이 1px 안팎 바뀌기도 한다 |
| 외부 연결 | 어떤 수식·이름도 쓰지 않는 연결을 버린다. 갱신 오류(`refreshError="1"`)인 연결을 가리키는 이름 참조 `[n]시트` 를 `[경로/파일]시트` 로 펼친다. 경로 없는 연결(`xlPathMissing`)과 갱신 오류 여부에 따라 `'[n]시트'!` 의 따옴표를 붙이거나 뗀다 |
| 문서 속성 | `lastModifiedBy`·`revision`·`modified` 를 새로 쓴다 |

## 11. 차트 파트 (`xl/charts/chartN.xml`)

DrawingML Chart (`c:chartSpace`). 근거는 한셀이 쓴 차트 파트다: 레거시 차트를 읽어 XML 로 쓴 것 77개
(`craft-charts`·`craft-charts2`·`templates` 의 `*.legacy.as.cell`), XML 원본을 읽어 쓴 것 92개
(`X.cell`, `hs/X.hs.cell`), 그리고 이것들과 rcell 이 쓴 차트를 한셀로 다시 저장한 결과 (관측).
구현: 모델 `Chart` (`src/model.rs`), 읽기 `src/parser/chart.rs`, 쓰기 `src/chart_xml.rs`, 검증 `tests/chart_xml.rs`.

**요소의 있고 없음을 지킨다.** 한셀이 쓴 XML 차트를 한셀로 다시 저장하면 차트 파트가 거의 그대로다
(`X.cell` 대 `hs/X.hs.cell`): `craft-charts` 15개 중 14개는 바이트 일치, 남은 하나는 빈 `<c:marker/>` 에
`<c:size val="7"/>` 를 넣었다. 서식 파일의 차트 8개는 막대 계열에 없던 `<c:invertIfNegative val="0"/>` 만 생기고
`<a:ln w="9525"><a:noFill/></a:ln>` 같은 짧은 선은 그대로다. 조작한 XML 원본에 없던 계열 `spPr`, 축 `txPr`,
범례 `spPr`·`txPr` 도 한셀 저장본에 생기지 않는다 (아래). 그래서 rcell 모델은 요소마다 있음·없음을 담고(`Option`),
`chart_xml` 은 있는 것만 쓴다.

**한셀이 XML 원본을 읽을 때 채우는 것** (조작한 XML 69개 `craft-charts*-in` → 한셀 XML `X.cell` 대조): `date1904 0`,
`roundedCorners 0`, 차트 스타일, 계열 이름·항목·값의 캐시(셀 값; 값 캐시는 `formatCode` 와 점마다 `formatCode`),
막대 계열 `invertIfNegative 0`, `gapWidth 150`·`overlap 0`, 그림 영역 `spPr` (`noFill` + 11.2절 꼴의 선 없음 9525),
축 `majorTickMark out`·`minorTickMark none`·`tickLblPos nextTo`·`crosses autoZero`, 항목 축 `auto 1`·`lblAlgn ctr`·
`lblOffset 100`·`tickMarkSkip 1`·`noMultiLvlLbl 0`, 값 축 `numFmt formatCode="G/표준" sourceLinked="1"`·
`crossBetween between`, 범례 빈 `c:layout`, `dispBlanksAs gap`, `hncChartStyle -1 -1 -1`. 제목의 글 상자는 위의 꼴로 바꾼다.

**한셀로 다시 저장하면** (레거시 읽기 결과 70개 문서): 차트 77개 중 69개는 차트 파트가 바이트까지 그대로다.
남은 8개는 모두 `lineChart` 이고, 계열 `c:dLbls` 에 `<c:dLblPos val="r"/>` 가 생긴다 (`line3DChart`·영역·방사형은 그대로).
한셀의 레거시 읽기와 XML 읽기가 꺾은선 데이터 레이블의 위치를 다르게 채우는 것이다. 그래서 레거시 문서에서
HCell(원본) 과 HCell(rcell(원본)) 은 꺾은선 계열의 이 요소 하나가 늘 다르다 — rcell 이 레거시 읽기 꼴로 쓰면 한셀이
`dLblPos` 를 넣고, 넣어서 쓰면 HCell(원본) 에 없다. `rcell diff` 의 차트 비교에는 들어가지 않는 값이다.

**모델로 만든 차트를 한셀이 읽는다** (모델 차트 실험: 코퍼스 차트를 모델에서 고치거나 처음부터 만들어 `chart_xml`
로 쓰고 한셀로 다시 저장): 제목 추가, 계열 색·선·범례 위치·값 축 숨김·간격, 데이터 레이블, 원형 쪼개기·첫 조각 각도·
백분율 레이블, 3차원 보기, 값 축 범위·거꾸로·주 단위·표시 형식, 한셀 꼴 생성자로만 처음부터 만든 막대 차트 — 7개 모두
한셀 저장본의 차트 파트가 rcell 이 쓴 것과 바이트까지 같다. 꺾은선의 표식·부드러운 선 실험은 위의 `dLblPos` 만 생겼다.

### 11.3 검증

`tests/chart_xml.rs` (`RCELL_CORPUS`): 차트 파트를 모델로 읽고 `chart_xml` 로 다시 써서 원본과 XML 트리
(요소 이름·순서, 속성, 글; 숫자는 값으로)로 비교한다. 레거시 읽기 결과 77개 모두 일치(바이트까지), 한셀의 XML 차트 92개
(`templates/hs` 8, `craft-charts` 15, `craft-charts2` 54, `craft-charts/hs` 15)도 모두 바이트까지 일치한다. 코퍼스 전체에서
한셀이 쓴 차트 파트 446개가 바이트까지 같게 다시 써지고, 남은 69개는 조작한 XML 원본(`*-in`, 한셀이 쓴 것이 아님)이다.
요약 필드(`title`, 계열의 이름·참조·값)는 새 파서에서도 515개 모두 이전과 같다.
