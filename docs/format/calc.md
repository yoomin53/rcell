# 한셀의 수식 계산 규칙

> 작성: yoomin53 · 대상: 한컴오피스 2024 한셀 (HCell.exe 13.0.0.711) · 구현: `src/calc/`
>
> 한셀에 수식을 넣어 다시 계산시키고 저장된 값을 읽어 얻은 관찰 결과다 (아래 "확인 방법").
> 한셀 프로그램 코드는 보지 않았다. 엑셀과 다른 점 위주로 적는다. 표의 예는 모두 한셀 값이다.

## 1. 구성

| 부분 | 파일 | 하는 일 |
|---|---|---|
| 구문 분석 | `parser.rs`, `ast.rs` | OOXML 수식 글 → 구문 트리. 참조(`$`, 따옴표 시트, 행·열 전체, 3차원, `[n]Sheet!A1` 외부), 이름(통합 문서·시트 범위), 배열 상수, 모든 연산자(범위 `:`, 합집합 `,`, 교집합 공백), `_xlfn.`·`_xlws.`·`_xlpm.` 접두사 |
| 값 | `value.rs`, `date.rs`, `collate.rs`, `cp949.rs` | 값과 형 변환, 글↔숫자, 1900/1904 날짜, 글 비교 순서, 코드 페이지 949 |
| 계산 | `eval.rs` | 연산자·암묵 교차·배열 계산·오류 전파, 인수 분류(값·참조·배열) |
| 엔진 | `engine.rs`, `mod.rs` | 의존 그래프, 계산 순서, 순환 참조, `recalculate(&mut Workbook)` |
| 함수 | `functions/*.rs` | 분류별 함수 표 (`FNS`), 이름으로 찾는 등록부 (`functions/mod.rs`) |
| 초월 함수 | `hcmath.rs`, `fm.rs` | 한셀(32비트 C 런타임)과 같은 exp·ln·pow·sin… (순수 Rust, 2장) |

CLI: `rcell calc 문서.cell [--diff]` — 다시 계산해 저장하거나, `--diff` 면 파일에 있던 값과 다른 칸만 보인다.

## 2. 확인 방법

- **말뭉치** (`tests/calc_corpus.rs`): 한셀이 저장한 문서의 수식 칸마다 rcell 계산값과 파일의 캐시 값을 비교한다.
- **함수 대조 실험** (`examples/calc_oracle_gen`, `tools/probe/calc-oracle.ps1`, `tests/calc_oracle.rs`):
  생성기가 함수 × 인수 경우를 수식으로 담은 문서(캐시 값 `<v>0</v>`)를 만들고, 한셀이 열어
  `Application.CalculateFull()` 로 다시 계산해 XML `.cell` 로 저장한다. 저장본의 값이 정답이다.
  - 한셀은 문서를 열거나 저장할 때 다시 계산하지 않는다 (파일의 캐시 값을 그대로 쓴다). `Calculate` 는
    바뀐 칸이 없으면 아무것도 하지 않고 `CalculateFull` 만 모든 수식을 계산한다.
  - 바뀐 것이 없으면 `SaveAs` 가 원본을 그대로 복사하므로 `Saved = $false` 로 만든 뒤 저장한다.
  - 캐시 값이 없는 수식 칸이 있으면 바이너리 저장이 실패한다 — 생성기는 `<v>0</v>` 를 넣는다.
- 한셀은 저장할 때 수식 글을 다시 쓴다: 모르는 함수의 `_xlfn.` 을 떼고, 읽지 못하는 수식(`_xlws.FILTER`,
  `LET(_xlpm.x…)`, 인수 개수가 틀린 것)은 버리며, 한 칸짜리 배열 수식 범위를 `B1:B1` 로 쓰고, 16자리 이상의
  숫자 상수를 15자리로 바꿔 쓴다 (`123456789012345678` → `123456789012344000`, 계산은 원래 상수로 한 값이라
  다시 열어 계산하면 값이 바뀔 수 있다).

- 생성기의 `--list` 파일은 한 줄에 수식 하나, `@3x2 수식` 은 3행 2열 배열 수식, `#1904` 줄은 1904 날짜 체계.
  엑셀 2010 이후 함수는 `_xlfn.` 을 붙여 써야 한셀이 그 함수로 읽는다 (FILTER·SORT 는 `_xlfn._xlws.`).
- 한셀이 XML 에 숫자를 쓸 때 %.17g 꼴 17자리로 쓰지만 [1E-6, 0.1) 의 수 가운데 0.2% 쯤을 1 ulp 틀리게 적는다
  (몫 6000 개 실험: `105474/39681724` → `2.6579994357100014E-3`, 참값 …001E-3). 셀 상수도 같다. 대조 실험은 상대
  1E-12 로 비교하므로 영향이 없지만, 끝자리를 재는 실험은 입력 문서의 값을 써야 한다.

### 기본 초월 함수 (검은 상자)

한셀의 EXP·LN·LOG10·POWER(`^`)·SIN·COS·TAN·ATAN·ASIN·ACOS 값은 32비트 윈도 C 런타임(`ucrtbase.dll`, 한셀이 싣는
그것)의 함수 값과 같다. 32비트 PowerShell 에서 P/Invoke 로 C 런타임 함수를 부른 값과 한셀 1만 1천 경우(무작위 입력,
정규 적분점, t 밀도의 밑)를 비교하면 모두 같다 — 다른 8 경우는 위의 XML 인쇄 오차다. SQRT 도 같다. SINH·COSH·TANH 는
C 런타임이 아니라 pow(e, x) 정의식이다 (아래 수학 표).

C 런타임 함수는 거의 정확히 반올림한 값을 낸다 (무작위 입력에서 참값을 반올림한 값과 같은 비율: exp 99.46%, pow 99.89%,
sin 99.89%, tan 99.77%, atan 99.61%, asin 99.83%, log 99.8–100%, 다를 때 오차 0.6 ulp 아래). rcell 의 `hcmath.rs`:

| 함수 | 방법 | C 런타임과 같은 비율 (10만 개) |
|---|---|---|
| exp | C 런타임과 같은 꼴: x·64/ln2 를 1.5·2^52 더하기로 반올림한 m, y = (x − m·L1) − m·L2 (ln2/64 앞 32비트·나머지), 2^(j/64) 표(hi, lo/hi), p = y + y²(c2 + y(c3 + y(c4 + y·c5))), hi + hi·(p + lo/hi). 계수는 C 런타임 값 수백만 개에 맞췄다 | 99.83% (`libm` 90.8%) |
| ln·log10·pow·sin·cos·tan·atan·asin·acos·sinh·cosh·tanh | 2배 정밀(double-double)로 계산해 한 번 반올림 = 정확한 반올림 | 99.6–99.99% (`libm` 90–97%, log10 은 99.99%) |

sin·cos·tan 은 큰 인수를 정확히 줄이지 않는다: 몫 k = round(x·2/π) 가 sin·cos 은 2^16, tan 은 2^13 이상이면 66비트로
자른 π/2 (x87 의 π, 참값보다 2.0223E-21 작다)로 줄인 값의 정확한 sin — 그 위 구간에서 C 런타임 값과 모두 같다
(`SIN(1E8)` 근처의 오차가 3만 ulp 를 넘는다). rcell 도 같은 π/2 조각으로 줄인다 (구간을 넘나드는 1E3–1E5 무작위 4000 개에서
sin·cos 99.1%, tan 99.9%, 1E5–1E8 에서 97.7%).

남은 0.1–0.4% 는 C 런타임이 정확한 반올림에서 벗어나는 경우다 (`SIN(2.5)` = 0.59847214410395644, 정확한 값
…655 — IMEXP("-2.5j") 의 15자리가 달라진다). exp 를 뺀 함수의 C 런타임 계산 꼴은 아직 맞추지 않았다.

GAMMALN 도 C 런타임 `lgamma` 와 같다 (한셀 906 경우 모두, 대조 실험 g6·lg). 끝자리 꼴: x ≥ 54 는 fdlibm 꼴
(x − ½)(ln x − 1) + w0 + z(w1 + y(w2 + … w6)) (z = 1/x, y = z², ln 은 C 런타임 log), x ≥ 2^58 은 x(ln x − 1).
그 아래는 정확한 반올림과 70–76% 같고 오차 2 ulp 안 (계산 꼴은 모른다; 정수는 (n−1)! 의 곱의 ln 과 가깝다).
rcell 의 `hcmath::lgamma` 는 반정수 k/2 (k ≤ 400) 는 한셀에서 잰 값의 표, x ≥ 54 는 위 꼴, 그 사이는 2배 정밀
스털링(30 이상으로 올려 베르누이 10항)을 한 번 반올림한다. T.DIST.2T·T.DIST.RT 의 상수가 반정수의 ln Γ 만 쓰므로
그 값은 모두 같다.

한셀을 죽이거나 멈추게 하는 수식 (실험 목록에서 뺐다):

| 수식 | 결과 |
|---|---|
| `ISOWEEKNUM(1)` (1900-01-01), `ISOWEEKNUM(-1)`, `WEEKNUM(-0.5,21)` | 자동화 서버가 RPC 오류로 끝난다 |
| `GAMMAINV(1,…)` | 죽는다 |
| `TTEST(…,…,…,1)` 에서 짝지은 차이가 모두 같을 때 (분산 0) | 죽는다 |
| `WORKDAY.INTL(…, 0 아닌 일수, "1111111")` | 끝나지 않는다 (rcell 은 #NUM!) |

## 3. 수와 글

### 숫자 상수와 글 → 숫자

- 수식 안의 숫자 상수와 글을 숫자로 바꿀 때 **유효숫자 15자리 뒤를 버린다** (반올림 아님):
  `1234567890123456` → 1234567890123450, `VALUE("0.99999999999999999")` = 0.999999999999999.
- 글 → 숫자 문법 (VALUE, 암묵 변환): 앞뒤 공백·탭·전각 공백 무시, 전각 숫자, 앞 부호, 통화 기호(`$ ₩ \ ￦`)
  앞이나 뒤, 괄호 음수 `(5)`, 쉼표는 뒤에 숫자 세 자리 이상일 때만, `%` 하나, 지수. 통화 기호와 `%` 는 함께 못 쓴다.
  대분수 `1 1/2`, 날짜·시각 글(한국어 `2024년 1월 2일`, 달 이름, `오전/오후`). `"TRUE"`·`"FALSE"` 는 1·0.
- 지수: 쓴 지수가 −309 보다 작으면 글로 남는다 (`VALUE("1E-310")`·`"100E-310"`·`"0E-400"` = #VALUE!, `"10E-309"` = 0,
  `"0.1E+309"` = 1E+308, 넘치면 #VALUE!). 비정규 수가 되면 0 (`"2.2250738585072E-308"` = 0) — `%` 는 그 뒤라
  `"1E-306%"` = 1E-308. 수식 계산의 비정규 수는 0 으로 바꾸지 않는다 (`1E-300*1E-10` = 1E-310).
- 한국어 시각 `H시 M분`·`H시 M분 S초`: 시 0–23, 분·초 < 60, 초는 소수 가능, 사이 공백 하나 이상, 앞 공백은 안 되고
  뒤 공백·전각 숫자는 된다 (`"9시 30분 15초"` = 0.39600694). `"9시"`·`"9시30분"`·`"오전 9시"`·`"24시 0분"`·
  `"2024년 1월 2일 9시 30분"` 은 #VALUE!.

### 글은 UTF-16

글 함수는 UTF-16 단위로 센다: `LEN("😀a")` = 3, `LEFT("😀a",2)` = "😀", `MID("😀a",2,1)` 은 짝 없는 대리 반쪽
(`UNICODE` 는 56832, 파일에는 U+FFFD 로 쓴다), `UNICHAR(55357)` 도 반쪽 그대로. 바이트 함수에서 대리 반쪽은
2바이트 (`LENB("😀a")` = 5, `REPLACEB("😀a",2,2,"X")` = " X a"). rcell 은 반쪽을 U+10F000 + (코드 − D800) 자리
글자로 담고 셀 값으로 낼 때 U+FFFD 로 바꾼다.

### 숫자 → 글 (`&`, 글 함수)

| 경우 | 규칙 | 예 |
|---|---|---|
| 1E+15 미만 | 유효숫자 15자리로 반올림 | 2/3 → `0.666666666666667` |
| 1E+15 이상 | 17자리로 반올림한 뒤 15자리 뒤를 버린다 | 2^60 → `1152921504606840000`, 12345678901234500000(실제 값 …499584) → `12345678901234500000` |
| 그대로 쓰는 범위 | 부호를 뺀 꼴이 20자 이내: 정수 20자리, 소수 18자리까지 | `99000000000000000000`, `0.000000000000000001`, `0.000123456789012345` |
| 지수 꼴 | 그 밖. 지수 자리는 채우지 않는다 | `1E+20`, `1E-19`, `3.33333333333333E-6` |
| 경계 | 자릿수를 log10 으로 재는 듯: log10(9.99999999999999E+19) 이 20.0 으로 반올림되어 지수 꼴 | `9.99999999999999E+19` |

복소수 글(COMPLEX, IM…)은 큰 수도 15자리로 반올림한다 (`123456789012345678` → `123456789012345000`).

### 글 비교

비교 연산자·정렬·MATCH 의 글 순서는 윈도 언어 정렬과 비슷하다 (`collate.rs`): 기호 < 숫자 < 라틴 < 그리스
< 키릴 < 기타 < 가나 < 한글 < 한자. 대소문자·악센트·전각은 뒤 순위 키, `-`·`'` 는 무시, ß=ss, æ=ae.

## 4. 연산자와 계산

| 항목 | 한셀 |
|---|---|
| `0^0` | 1 |
| `0^음수` | #NUM! |
| 음수^소수 | #NUM! |
| 다른 시트끼리의 범위 연산 `Sheet1!A1:Sheet2!B2` | #NULL! |
| 거꾸로 된 3차원 범위 `S3:S1!A1` | 빈 범위 |
| TRANSPOSE (배열 수식이 아닐 때) | 인수를 암묵 교차한 값 하나: `INDEX(TRANSPOSE(A1:A3),1,2)` = #VALUE! |
| MODE.MULT | 배열이 아니라 값 하나 (가장 많이 나온 값들 가운데 차례상 마지막 칸) |
| N | 범위는 왼쪽 위 칸, 배열 수식에서도 원소마다 계산하지 않는다 |
| 순환 참조 | 반복 계산이 꺼져 있으면 CalculateFull 이 끝나지 않는다 (경고 창으로 보인다) — rcell 은 순환 안의 칸이 파일 값을 읽는다. `calcPr iterate="1"` 이면 순환에 든 수식과 그것에 기대는 수식을 파일 값에서 시작해 2×iterateCount 번, 행 차례로 계산한다: 한 바퀴에서 앞 행은 이번 값, 뒤 행은 지난 바퀴 값을 읽는다 (`B3 = B3+1` 은 파일 값 + 2·4·6·20 (횟수 1·2·3·10), `B1 = B2+1`·`B2 = B1*0.5` 는 횟수 1 에서 1.5·0.75, `B1 = B3*2`·`B2 = B1+1`·`B3 = B2+1` 은 4·5·6, 뒤 행 순환을 읽는 앞 행 `B4 = B6*10` 은 한 바퀴 앞 값). iterateDelta 0.5 는 결과를 바꾸지 않았다 (멈추지 않는 칸이 있는 실험). 대조 실험 circ 98 경우 모두 같다. calcPr 의 속성은 그대로 저장한다 |

### 무작위 수식 차분 시험에서 찾은 규칙

`examples/calc_oracle_gen --random N --seed S` (`rand.rs`) 는 함수·인수 종류(숫자·글·논리·날짜·범위·배열·오류·빈 칸)·연산자를
깊이 3 까지 겹쳐 무작위 수식을 만든다 (같은 시드는 같은 목록, `--emit` 로 글 목록을 남긴다). 한셀에서 작은 묶음(20 개씩)으로
돌려 rcell 과 견줬다 — 처음 3000 개 가운데 120 가 달랐고, 아래 규칙을 고친 뒤 3–5/500, 4 차(7500 여 개, 인수 종류 확장 포함)에서는 알려진 잔여만 남았다
(`lists/*.txt` 는 규칙마다 좁혀 본 목록: 모두 한셀 출력 없이 수식만). 한셀이 멈추거나 죽는 수식은 `POISSON.DIST(1E5,1E5,TRUE)` 와 `NUMBERSTRING(1E300,1)` 이 더 있다.

| 규칙 | 한셀 |
|---|---|
| 참조가 필요한 인수에 값·배열 | COUNTIF·SUMIF·SUMIFS·COUNTIFS·MAXIFS 의 범위 `{1,2,3}`·`5` 는 #VALUE!. COUNTBLANK 는 #NAME? (오류 값도). ROW·COLUMN 은 #REF!, ROWS("a") 는 #VALUE! (ROWS(5) = 1), SHEETS·CELL 은 #N/A, MATCH(5,5,0) 은 #N/A, RANK 의 범위가 낱값이면 #N/A |
| RANK | 범위 안에 오류가 있으면 첫 번째 오류 그대로 (`RANK(1,Data!H1:H3)` = #N/A, 두 번째 칸이 #N/A 이므로; `RANK(5,Data!H5:H7)` = #VALUE!) |
| IF·NOT·IFS 의 글 | "TRUE"/"FALSE" 와 숫자로 읽히는 글 (`IF("0",1,2)` = 2, `NOT("5")` = FALSE, `IF("12:00",1,2)` = 1, `NOT(" 0")`·`"0%"`·`"$0"`) — 그 밖은 #VALUE! |
| SWITCH | 식이 오류여도 멈추지 않고 같은 오류인 값과 맞는다 (`SWITCH(#N/A,#N/A,1,2)` = 1), 맞는 것이 없으면 기본값 (`SWITCH(Data!A1:A10,10,"x","d")` 의 암묵 교차 오류 → "d") |
| BIT·DEC2BIN | BITAND 만 (−1, 0) 의 음수 소수를 0 으로 받는다 (`BITAND(-0.5,1)` = 0); BITOR·BITXOR·BITLSHIFT·BITRSHIFT 는 소수를 버리기 전에 0 보다 작으면 #NUM! (`BITXOR(1023,-0.69)`). 조건 (COUNTIF·SUMIF·…IFS):

- 숫자 조건은 숫자로 읽히는 글 칸에도 맞는다 (`COUNTIF(…,5)` 가 글 "5" 를 센다, `">0"` 도).
