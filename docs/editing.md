# 편집 규칙

> 작성: yoomin53

rcell 의 편집 — 라이브러리 `rcell::edit`, 명령 `rcell edit`, 웹 편집기 — 은 한셀 2024 에서 같은 편집을 한 결과와 같은
문서를 만드는 것을 목표로 한다. 아래 규칙은 모두 한셀 COM 자동화로 같은 편집을 실행해 저장한 결과와 비교해 정했다
(10절). 한컴 파일은 저장소에 넣지 않는다 — 단위 시험은 실험 문서와 같은 모양의 문서를 코드로 만든다.

## 1. 편집 명령

편집 하나는 JSON 객체 하나다 (`rcell::edit::Edit` — 필드 이름은 camelCase: `toSheet`, `matchCase` …). 행은 1부터(한셀 화면과 같다), 열은 이름(`C`), 셀·범위는 A1
표기(`A1:C3`, `A:C`, `2:5`). `sheet` 는 시트 이름 또는 0부터 센 번호이고, 빼면 첫 시트다.

```bash
rcell edit 문서.cell 대본.json 결과.cell        # {"edits": [...]} 를 차례로 실행하고 다시 계산해 저장
rcell edit 문서.cell 대본.json 결과.xlsx --no-recalc   # 계산하지 않고 (형식은 확장자 또는 --format cell|xlsx|bin)
```

실패한 편집(보호된 칸, 병합의 일부 옮기기 …)은 건너뛰고 이유를 알린다 (`편집 #3 실패: …`). 라이브러리에서는 `edit::apply(&mut wb, &edit)` 또는 `set_input`,
`insert_rows`, `border`, `merge`, `copy`/`paste` … 를 직접 부른 뒤 `calc::recalculate` 로 다시 계산한다.

## 2. 셀 입력

입력 대조 실험: 표시 형식이 다른 칸 14종에 글 94가지를 `Range.Value2` 로 넣고 저장한 값과 형식을 비교했다
(`src/edit/input.rs`).

- `=` 로 시작하면 수식 (`=` 하나만이면 글). 함수 이름·참조·논리값·오류는 대문자로, 시트·이름은 문서의 표기로 고르고,
  교차 연산이 아닌 공백을 지우고 닫는 괄호를 채운다 (`= sum(a1:a3` → `SUM(A1:A3)`). 문법이 틀리면 입력하지 않는다.
- 작은따옴표로 시작하면 글 + 글자 접두(`quotePrefix`). `+A1`·`@SUM(A1)` 은 글이다.
- `TRUE`/`FALSE`(대소문자 무시)는 논리값, `#N/A` 같은 오류 글은 오류 값.
- 숫자 꼴(`1,234`, `(5)`, `$1,000`, `10%`, `1.5E3`, 앞뒤 공백), 시각(`12:30`, `9:05 AM`, `25:00`), 날짜(`2024-01-15`,
  `1/15`, `15-Jan`, `2024년 1월 15일`), 날짜+시각, 대분수(`1 1/4`)를 값으로 읽는다.
- 일반 서식 칸에는 입력 꼴의 형식을 붙인다: `1,234` → `#,##0`(3), `1,234.5` → 4, `10%` → `0%`(9), `10.5%` → 10,
  `1.5E3` → 11, 날짜 → 14 (`d-mmm` 16, `mmm-yy` 17, `mm-dd` 58, 한글 날짜 31), 시각 → 18–21 (24시간 넘으면 46),
  날짜+시각 → 22, 대분수 → 12·13.
- 다른 서식 칸은 서식 종류마다 다르다: 백분율 칸은 `%` 없는 숫자를 100 으로 나누고, 날짜 칸에 `1,234`·`10%`·`1.5E3`
  을 넣으면 그 꼴의 형식으로 바뀌고, 숫자·통화·지수·시간 칸은 형식을 그대로 둔다. 글자(`@`) 칸은 모두 글.
- `1/2` 는 일반·날짜·시간 칸에서는 날짜(올해 1월 2일), 숫자·지수·분수·백분율 칸에서는 분수 0.5.
- 대분수 `0 1/2` 는 일반 칸에서 글이 되고 형식만 `# ?/?` 로 바뀐다 (한셀의 동작 그대로).
- 일반 서식 칸에 수식을 넣으면 결과 형식을 붙인다: `TODAY`·`DATE` → 14, `NOW` → 22, `TIME` → 18, `PMT` `NPV` `FV`
  `PV` `IPMT` `PPMT` → 8, 그 밖에는 처음 참조한 칸의 형식 (더하기·빼기·부호·괄호·`SUM` `MAX` `MIN` `AVERAGE` `ROUND`
  를 거쳐서. 곱하기·나누기·거듭제곱은 숫자·백분율 형식을 버리고 통화·날짜·시각·지수·분수는 남긴다. 같은 형식끼리면
  백분율·지수·분수만 남는다. `SUM` 은 날짜 범위의 형식을 버린다).
- 줄 바꿈(`\n`)이 든 글을 넣으면 칸 서식의 자동 줄 바꿈이 켜진다 (`'` 앞붙임·`\r\n` 도 같고 수식 결과는 아니다 — 실험 6가지).
- 배열 수식 범위의 일부는 바꿀 수 없다. 공유 수식 묶음의 칸을 바꾸면 묶음을 일반 수식으로 푼다.

## 3. 행·열 삽입·삭제와 참조 조정

참조 대조 실험: 값·수식 40종·이름·병합·조건부 서식·유효성·메모·링크·차트가 있는 문서에 행·열 삽입·삭제 18가지를
실행했다 (`src/edit/refs.rs`, `structure.rs`).

- 삽입: 삽입 위치 이후를 가리키는 참조는 밀리고, 범위 안에 삽입하면 범위가 넓어진다. 시트 끝을 넘는 참조는 끝에
  머문다 (`A1048576` 은 그대로). 열 전체·행 전체 참조(`A:A`, `5:5`)도 같은 규칙.
- 삭제: 지운 칸만 가리키는 참조는 `#REF!` (시트 이름은 남는다: `Sheet1!#REF!`), 범위는 남은 칸으로 줄어든다
  (`A6:A7` 에서 5–6행 삭제 → `A5:A5`), 범위 전체를 지우면 `#REF!`.
- 3차원 참조(`Sheet1:Sheet2!A5`)와 외부 문서 참조는 바꾸지 않는다. 문자열 안의 글(`INDIRECT("A5")`)도 그대로.
- 문서 전체에 반영한다: 모든 시트의 수식(다른 시트를 가리키는 참조 포함), 이름, 병합(한 칸만 남으면 없앤다),
  조건부 서식·유효성(범위와 수식 — 범위가 삽입 위치 바로 위·왼쪽에서 끝나도 넓어진다, 맨 앞 행을 지우면 수식의 기준
  칸을 새 첫 칸으로), 하이퍼링크, 메모(상자 자리 포함), 도형·차트 앵커(원본 그리기 XML 도), 차트 계열 참조(원본 차트
  파트도), 표·자동 필터 범위, 행·열 정보, 틀 고정, 페이지 나누기, 배열 수식·데이터 표 범위.
- 삽입한 행·열은 바로 위 행(왼쪽 열)의 서식을 물려받는다 (서식 물려받기 대조 실험): 행 정보(높이·행 서식, 숨김·접힘은
  빼고)를 복사하고 앞 행의 셀마다 서식을 빈 칸으로 복사한다. 테두리 변은 맞은편 칸(삽입 위치에 있던 칸)에도 같은 선이
  있을 때만 받는다 — 아래 선이 있는 B2 아래에 행을 넣으면 옛 B3 에도 같은 아래 선이 있을 때만 새 B3 이 그 선을 받고,
  받지 않은 변은 기본 테두리의 그 변이 된다. 새 칸이 셀 없이도 그 서식으로 보이면(행 서식 → 열 서식) 셀을 만들지 않는다.
- 삽입한 열은 왼쪽 열의 열 정보를 너비를 명시해(`customWidth`) 따로 받는다 (왼쪽 열 정보를 넓히지 않고, 숨김·접힘은
  빼고). 삽입 위치를 품은 열 정보는 둘로 나뉘고, 왼쪽 열 정보가 없거나 A 열 앞에 넣으면 기본 너비를 명시한 열 정보를
  만든다.
- 열 삽입·삭제와 행 서식 (열 삽입·삭제 대조 실험): 한셀은 마지막 셀이 있는 행까지(지울 열의 셀은 빼고) 행 서식이 있는
  행마다, 열 정보가 옮겨지는 칸에 옮기기 전 그 칸의 열 서식(열 정보가 없으면 0)으로 셀을 만든다 — 삽입은 삽입
  위치부터 열 정보가 있는 열과 그 n 칸 앞 열, 삭제는 지운 범위 뒤의 열 정보가 있는 열과 그 n 칸 뒤 열 (E:J 열 서식에
  C 열 삽입 → 옛 D:J, C:D 삭제 → 옛 E:L). 행 서식과 같은 서식이거나 셀이 이미 있으면 만들지 않는다. 그래서 그 칸들은
  옮긴 뒤에도 행 서식이 아니라 옮기기 전의 열 서식으로 보인다.
- 병합이 줄 때 (병합 대조 실험 — B2:C2 같은 병합에서 행·열 하나를 지우는 경우들): 한 칸만 남으면 그 칸은 왼쪽 위
  칸의 값과 서식을 받고, 열을 지웠으면 왼쪽·위·아래 변, 행을 지웠으면 위·왼쪽·오른쪽 변을 다시 적는다. 적는 선은 후보
  (왼쪽 위 칸이 남으면 그 칸의 선·이웃의 맞닿은 선, 지웠으면 이웃의 맞닿은 선·남는 칸의 선) 가운데 가장 굵은 것이다 —
  그래서 병합 칸에 보이던 위 선(위 칸의 아래 선)이 남은 칸의 위 선으로도 적힌다. 왼쪽 위 칸을 지우고 여러 칸이 남으면
  값은 남는 첫 칸으로 가고, 칸 서식은 병합의 처음부터 남는 칸 수만큼 그 자리에 남으며 둘레 변을 같은 규칙으로 적는다.
- 메모 상자 (메모 상자 대조 실험 cb1–cb3): 칸이 옮겨진 메모의 상자는 메모 칸의 열 + 14px, **보이는** 두 행 위(숨긴 행은 세지 않고 건너뛴다) + 10px 에 다시 두고
  크기(px)는 그대로 둔다 — 기본 자리(오른쪽 열, 한 행 위)의 상자는 처음 옮길 때 한 열 왼쪽·한 행 위로 간다. 끝 열이 열 경계에 닿으면 앞 열의
  끝(`2, 70`)으로 적는다. 한셀 VML 앵커의 열 px 는 화면 너비보다 1 작다 (72px 열이 71). 옛 상자 왼쪽이 A 열에 있으면 그 왼쪽을 A 열 너비 − 1px 만큼
  오른쪽에서 재고, **A 열에서 시작한 상자의 끝은 새 시작 열의 오른쪽 가장자리 − 1px 를 넘지 못해** (옛 끝이 69 든 70 이든 옮기면 `70`, 다시 옮기면 `0`) 칸이 옮겨질
  때마다 좁아진다. 행·열을 숨기거나 보이면 상자는 화면 자리(절대 px)를 지킨다 (숨김 4가지 같음). **화면 배율이 100 이 아니면 한셀은 1px 씩 다르게
  낸다** (끝 열 오프셋이 배율 90 ↓·110 에서, 시작 오프셋이 80 ↓·110 에서 달라진다 — rcell 은 배율 100 일 때만 맞다). A 열 메모가 열 삽입·셀 오른쪽 밀기로
  B 열 이상으로 가면 한셀은 상자를 오른쪽 열 + 107px 쯤에 두는데 그 이유는 모른다 (실험 5가지).
- 틀 고정: 고정한 행·열 안에 넣거나 지우면 고정 범위가 늘거나 준다. 오른쪽 아래 첫 칸(`topLeftCell`)은 그대로 둔다.
- 페이지 나누기 (페이지 나누기 대조 실험): 여러 행·열을 넣거나 지우면 범위의 첫 자리와 끝 자리의 나누기는 그대로 두고
  (E:G 삭제 → E·G 앞 나누기는 그대로, F 앞 나누기는 없어진다) 나머지는 하나일 때와 같이 옮긴다. 차례를 바꾸거나 겹친
  것을 합치지 않는다 (한셀이 다시 열면 정리한다).
- 자동 필터 (필터 대조 실험): 필터 범위의 첫 칸(머리글)이 옮겨지면(1행·A 열 삽입 …) 필터를 다시 적용한다 — 데이터 행마다
  열 조건(값 목록·빈 칸, 사용자 지정 조건, 상위/하위, 평균 위/아래)을 모두 만족하면 보이고 아니면 숨긴다. 범위 안의 행
  삽입·삭제에서는 다시 적용하지 않는다. 상위/하위·평균의 경계값은 한셀이 문서를 열 때 계산해 두고 다시 계산하지 않으므로
  rcell 도 편집 앞 데이터로 채운다 (마지막 데이터 행을 지워도 상위 3 경계값은 연 때의 값).

## 4. 서식

### 4.1 글꼴·채우기·맞춤·표시 형식

- 칸의 서식을 복사해 바꾼 뒤 같은 서식이 이미 있으면 그 번호를 쓴다 (글꼴·채우기·테두리·표시 형식도).
- 채우기 색: 무늬 채우기는 무늬를 두고 바탕색만 바꾼다 (`Interior.Color`).
- 표시 형식 코드: 한셀 내장 번호(문서가 다시 정의하지 않은 것) → 문서의 사용자 형식 → 새 번호(164 이상).
- 건너뛰는 칸: 조건이 있는 자동 필터 범위 안의 숨긴 행, 범위 밖으로 걸친 병합의 칸. 필터가 없거나 조건이 없으면 숨긴
  행·개요로 접은 행·열도 바꾸고, 숨긴 열은 언제나 바꾼다 (서식 대조 실험).

### 4.2 테두리

테두리 대조 실험(`Borders(묶음).LineStyle`/`Weight`, 실험 문서의 경우 17가지와 서식 파일)에서 확인한 규칙:

- 범위의 선은 여섯 묶음으로 다룬다: 왼쪽·위·아래·오른쪽 가장자리, 안쪽 세로·가로.
- 색을 주지 않으면 묶음마다 첫 칸의 그 변 색을 묶음 전체에 쓴다 — 칸 사이에 선이 있으면(이웃 칸의 맞닿은 선 포함)
  그 선의 색, 없으면 칸 서식에 남은 색. 한셀 문서의 기본 테두리는 선 없이 왼쪽·오른쪽·아래 검정, 위 자동 색을 담고
  있어서, 보통은 위 가장자리만 자동 색이고 나머지는 검정이다.
- 안쪽 세로선: 첫 행(범위 밖으로 걸친 병합이 없는 첫 행)의 첫 칸 사이에 선이 있고 그 행의 칸 사이(끝 칸의 오른쪽 변까지)에
  있는 선(선 없는 칸 사이는 빼고)이 모두 같은 색이면 그 색, 아니면 그 행 끝 칸의 왼쪽 변 색 (`H10` 오른쪽만 빨강 → 빨강, `I10` 오른쪽만
  빨강 → 검정). 안쪽 가로선: 그 행 끝 칸의 서식에 남은 아래 변 색 (아래 선이 빨강·파랑·초록이면 초록, 끝 칸에 선이
  없으면 기본 검정 — 안쪽 선 대조 실험 15가지 모두 같음).
- 묶음의 칸 사이가 모두 이미 같은 선(종류·색)이면 그 묶음은 바꾸지 않는다.
- 가장자리 선을 그으면 범위 밖 이웃 칸의 맞닿은 선은 새 선과 다르면 지우고, 같으면 둔다 (한셀은 칸 사이 선을 하나로
  다룬다 — B10 위 선을 그으면 B9 의 아래 선이 없어진다).

### 4.3 병합

- 겹치는 병합은 먼저 푼다. 배열 수식이 있는 칸은 병합하지 않는다.
- 왼쪽 위 칸이 비었으면 처음 만나는 값(행 우선)을 왼쪽 위 칸으로 옮긴다. 그 칸의 글꼴·채우기·맞춤·표시 형식도
  오지만 테두리는 왼쪽 위 칸의 것을 둔다. 나머지 칸의 값은 지우고 서식은 둔다.
- 병합 안쪽의 칸 사이 선(바깥 가장자리가 아닌 변)은 지운다.
- `center` 면 병합한 칸 모두를 가운데 맞춤.
- 행 높이: 자동 높이가 적힌 행(높이가 있고 `customHeight` 가 없는 행)이면 첫 행은 그 높이를 고정 높이로 적고 나머지
  행은 높이를 지운다. 고정 높이 행은 그대로 둔다.

### 4.4 열 너비·행 높이

- 열 너비: 한셀 COM `ColumnWidth`(글자 수) → 저장 값은 1/256 로 자르고 199/256 을 더한다 — 글꼴과 상관없다
  (20 → 20.77734375, 8.43 → 9.20703125). 웹 편집기에서 끈 너비는 화면 px 를 글자 수로 바꾼다. 0 이면 숨긴다.
- 바뀐 칸 안의 도형 표지 오프셋은 px 로 올린 뒤 (1px 보다 작은 EMU 오프셋도 1px) (칸 px − 1) 의 비율로 옮기고 px 로
  반올림한다 — 28px 열을 131px 로 넓히면 25px 표지가 25 × 130/27 → 120px, 40px 행을 60px 로 높이면 25px 표지가 38px
  (열 너비·행 높이 대조 실험).
- `editAs="oneCell"` 그림은 크기를 지키도록 끝 표지를 다시 정하고, 메모 상자는 화면 자리를 지킨다.

## 5. 복사·잘라 붙이기·채우기

- 복사해 붙인 수식의 상대 참조는 옮긴 만큼 바뀐다 (시트 밖으로 나가면 `#REF!`). 서식·병합·조건부 서식·유효성도 함께
  간다. 붙일 범위가 복사한 크기의 배수면 되풀이해 채운다.
- 행·열 서식만 있는 칸도 그 서식으로 복사한다 (칸 기록이 없어도).
- 수식이 쓰는 통합 문서 이름은 붙인 시트의 시트 범위 이름으로 하나 더 만든다 (한셀의 동작 — `SUM(MyRange)` 를 같은
  시트에 붙이면 시트 범위 `MyRange` 가 생긴다). 채우기에서는 만들지 않는다.
- 잘라 붙이기(셀 옮기기): 옮긴 칸을 가리키던 참조가 모두 새 자리를 따라간다 — 원본 범위 안에 모두 든 참조만
  (`SUM(A1:A10)` 은 그대로, `SUM(A5:A6)` 은 `SUM(Q5:Q6)`). 조건부 서식은 옮긴 칸의 몫을 떼어 새 자리에 두고 남은 몫의
  수식은 남은 범위의 왼쪽 위 칸에 맞춘다. 유효성은 같은 규칙의 범위를 옮긴다 (`B1:B10` 에서 B5:B6 을 옮기면
  `B1:B4 B7:B10` + `R5:R6`). 병합의 일부만 옮길 수는 없다 ("병합된 셀의 일부를 바꿀 수 없습니다"). 다른 시트로 옮긴
  수식의 접두 없는 참조에는 원래 시트 이름을 붙인다.
- 조건부 서식의 우선순위 (조건부 서식 대조 실험 — 규칙 종류 12가지 × 복사·채우기·옮기기, 여러 규칙 묶음 8가지,
  `src/edit/cfpaste.rs`):
  - 붙인 규칙은 맨 위 우선순위(1부터, 한 번에 붙인 규칙끼리는 원래 차례)를 받고 시트의 다른 규칙은 그만큼 내려간다.
    데이터 막대가 든 묶음과 서식(dxf) 없는 고유 값·중복 값 규칙이 든 묶음은 한 번 더 붙는다 (같은 묶음 둘 — 그
    우선순위는 첫 묶음들 다음). 서식 없는 고유·중복 값 규칙은 복사할 때(값만 붙이기도) 시트 전체에서 빈 서식을 받고
    둘째 묶음도 빈 서식을 받는다 — 첫 묶음은 원본 그대로이고, 앞선 복사로 붙은 첫 묶음은 다음 복사에서 고치지 않는다
    (서식 없는 규칙 대조 실험 11가지 모두 같음). 채우기는 고치지 않는다.
  - 채우기는 채울 줄마다, 줄 안에서는 묶음·우선순위 차례로 규칙 하나씩 맨 위에 넣는다. 규칙 하나뿐인 묶음(데이터 막대
    빼고)은 원래 규칙의 범위를 넓혀 목록 끝으로 가고, 데이터 막대와 다른 규칙이 함께 든 묶음은 줄마다 따로, 그 밖에는
    채운 줄 전체를 한 묶음으로 둔다 (우선순위는 마지막 줄의 것 — 나머지 번호는 비어 남는다).
  - 옮기기는 옮긴 규칙에 맨 위 우선순위를 준다. 데이터 막대가 없고 규칙마다 서식이 있는 묶음은 옮긴 몫을 원래 묶음에
    합친다 (범위는 붙은 것끼리 합쳐 행 차례로). 범위에 따라 결과가 달라지지 않는 규칙(중복·상위·평균·색조·막대·아이콘이
    아닌 것)만 든 묶음은 같은 규칙의 다른 묶음과도 합치고, 그때 수식은 옮긴 몫의 왼쪽 위 칸에 맞춘다.
- 유효성: 붙이기·채우기·옮기기를 하면 한셀은 시트의 유효성마다 범위 목록의 차례를 뒤집는다 (`M1:M5 O2` 는 한 번에
  `O2 M1:M5`, 두 번이면 그대로). 붙인 범위는 목록 끝에 더한 뒤 뒤집으므로 맨 앞에 온다. 같은 시트 안에서 옮긴 유효성은
  목록 끝에 둔다.
- 아래로·오른쪽으로 채우기는 첫 행(열)을 나머지에 복사한다.
- 다른 프로그램에서 복사한 글(TSV)은 칸마다 2절의 입력 규칙으로 붙인다. 앱 안 복사는 클립보드에도 TSV 를 넣는다.

## 6. 시트

- 추가: 이름이 없으면 쓰지 않은 가장 작은 `SheetN`. 인쇄 설정은 한셀 새 시트의 기본값(여백 19·25·13 mm, A4 세로).
  한셀 자동화(`Worksheets.Add`)는 새 시트를 선택하지 않는다 — 활성 시트는 그대로다.
- 코드 이름: 한셀은 문서를 열 때 코드 이름이 없는 워크시트에 차례로 `SheetN` 을 준다. 그래서 시트를 더하거나 지우거나
  옮기기 전에 같은 이름을 주고, 새 시트는 쓰지 않은 가장 작은 `SheetN` 을 받는다 (코드 이름 없는 문서에 시트를 더해
  앞으로 옮기면 원래 시트가 `Sheet1`, 새 시트가 `Sheet2`).
- 이름 규칙: 1–31자, `: \ / ? * [ ]` 없이, 작은따옴표로 시작·끝나지 않고, 대소문자를 무시하고 겹치지 않게.
- 이름 바꾸기: 모든 수식·이름·조건부 서식·유효성·차트 계열 참조의 시트 이름을 바꾼다 (필요하면 작은따옴표).
- 삭제: 그 시트를 가리키는 참조는 `#REF!`, 3차원 참조의 끝 시트를 지우면 그 자리에 오는 시트로 바꾼다. 그 시트의 시트
  범위 이름은 지운다. 마지막 보이는 시트는 지울 수 없다.
- 옮기기: 시트 번호를 쓰는 곳(시트 범위 이름, 활성 탭)을 고친다. 옮긴 시트를 선택한다 (활성 시트도 그 시트).

## 7. 보호

보호 대조 실험: 시트 보호(설정 조합 여러 가지, 필터·개요가 있는 시트)와 통합 문서 구조 보호 문서에 대본을 한셀 COM 으로
실행해 저장한 결과와, 같은 문서를 한셀 화면으로 열어 도구 상자 단추·메뉴가 켜져 있는지(UI 자동화 `IsEnabled`)를 읽은
결과를 비교했다.

- 보호된 시트의 잠긴 칸은 바꿀 수 없다: "변경하려는 셀은 보호되어 있으므로 읽기 전용입니다 (시트 보호)". 잠김은 셀
  기록 → 행 서식 → 열 서식(열 정보가 없으면 기본 서식) 차례로 본다.
- 보호 설정이 막은 동작(서식, 행·열 삽입·삭제, 행 높이 …)은 할 수 없다. 행·열 삭제는 설정이 허용해도 지울 행·열에
  잠긴 칸이 있으면 할 수 없다 (잠금을 푼 행 서식의 빈 행은 지울 수 있다).
- 통합 문서 구조 보호는 시트 옮기기를 막는다.
- 데이터 도구는 다르다 (18절): 한셀 자동화의 중복 항목 제거·텍스트 나누기·통합은 보호된 시트의 잠긴 칸도 덮어쓰고, 부분합은 보호된 시트에서 서버 오류로
  멈춘다 (rcell 은 오류).
- 한셀 자동화와 한셀 화면이 다르다. 자동화(COM)는 보호된 시트의 열 너비(`ColumnWidth` — `formatColumns` 가 막혀도)와
  구조가 보호된 통합 문서의 시트 추가·이름 바꾸기·삭제를 그대로 한다. 화면은 보호 설정에 따라 단추·메뉴를 끈다 — 서식
  단추(`formatCells`), 행·열 추가·지우기, 열 너비, 구조가 보호되면 시트 탭의 추가·이름 바꾸기·삭제.
- rcell 은 두 가지를 나눠 둔다. `edit::apply`(명령 `rcell edit`)는 한셀 자동화와 같은 결과를 낸다 — 문서에 적힌 보호
  설정은 그대로 지키고 바꾸지 않으며, 한셀 자동화가 저장하는 것과 같은 문서를 만든다. `edit::check_ui`·`apply_ui` 는
  화면에서만 막히는 편집(열 너비, 시트 추가·이름 바꾸기·삭제)도 막는다. 웹 편집기는 `apply_ui` 를 쓰고, 렌더 결과의
  `blocked`(막힌 보호 설정)와 `structure` 로 한셀 화면처럼 단추를 끄고 머리글 경계 끌기·시트 탭 메뉴를 막는다.

## 8. 다시 계산과 되돌리기

- 편집마다 계산 엔진(`rcell::calc`)으로 모든 수식을 다시 계산한다. 엔진은 수식을 한 번씩만 계산하고(되부름은 기억해
  둔 값) 서식 파일 크기의 문서는 수 ms 안에 끝나므로 의존 그래프에 따른 부분 계산은 하지 않는다.
- wasm 에는 시계가 없으므로 편집 앞에 `rcell_set_clock(Date.now(), 시간대)` 를 부른다 (`NOW()`·`TODAY()`·`RAND()`).
- 되돌리기는 편집 앞 문서의 사본을 100 단계까지 둔다 (편집하지 않는 그림·매크로 같은 이진 파트는 빼고).

## 11. 남은 차이

스무 대본(`cells rows cols format sheets sort fill replace shift paste objects data shapes addshape copysheet view page protect filter table`) × 48종의 corpus 대조에서 남은 것과 실험 문서에서 남은 차이.
이번에 닫은 것: 가나 글 차례(12절), 유효성 범위 차례(16절, 28가지 모두 같음 — 하나뿐인 유효성 포함), 그림 가로세로 비율 잠금 크기(19절), 데이터 도구의 보호된 시트(18절), 메모 상자의 숨긴 행·숨김 뒤 자리·A 열 끝 제한(3절).
**한셀이 같은 입력에서도 실행마다 다르게 내는 것을 찾았다** — 정렬·채우기의 데이터 막대 묶음(12절). 남은 것:

- 한셀이 다시 열며 바꾸는 것: 행·셀 삽입 뒤 틀 고정의 오른쪽 아래 첫 칸(한셀이 편집해 저장하면 그대로 `B3`, 다시 열면 고정 범위에 맞춘다), 도형 하나의 끝 표지 오프셋 (3 → 4px),
  보기 설정 때 창을 보이게 해서 채워지는 창 크기(대조 도구는 같다고 본다). rcell 은 한셀이 편집해 저장한 것과 같이 쓴다.
- **무작위**: 정렬·채우기의 데이터 막대 묶음(위 12절 — corpus `cf_dv`·`cfdv_x` 정렬, `cf_dv` 채우기·옮기기). 한셀 실행끼리도 달라 맞출 수 없다. 복사한 시트의 메모 상자 이름은 `메모 0` 인데 가끔 쓰레기 값(`메모 28484`)이 들어간다
  (corpus `structure` 복사 1종).
- 서식(dxf) 없는 조건부 서식을 행/열 바꿔 붙일 때 한셀이 규칙마다 빈 서식(`<dxf/>`)을 주는 것: 같은 입력에서 같은 결과가 나오는 결정적인 규칙인데(규칙 종류와 붙인 자리에 따라 번호가 1, 2, 3… 으로 이어서 붙지만 어떤
  규칙이 받는지는 종류별 묶음 차례처럼 보이다가 열마다 달라진다) 찾지 못했다 (corpus `cf_dv` 붙이기 1종, 실험 11가지 중 이어 붙이기 3가지).
- 메모 상자: 화면 배율이 100 이 아니면 한셀이 1px 씩 다르게 낸다 (corpus `view_print`: 배율 85 — 셀 삽입·삭제·행 삽입·도형 더하기에서 1px). A 열 메모가 열 삽입·셀 오른쪽 밀기로 B 열 이상으로 가면 한셀은 상자를 오른쪽 열 + 107px 쯤에 두는데
  이유를 모른다 (실험 5가지). 붙인 메모의 상자는 한셀이 시작 표지를 새 메모 자리(칸 열 + 14px, 두 행 위 + 10px)에 두고 끝 표지를 원본에 따라 다르게 — 때로 시작보다 앞에 — 정한다 (붙이기 실험 8가지, 복사
  실험 19가지). 새 메모의 기본 상자는 한셀 자동화(`AddComment`)에서 창 상태에 따라 (오른쪽 열 + 한 행 위 / 같은 열 + 두 행 위) 달라진다.
- 바꾸기: 한셀 `Range.Replace` 는 바꾼 글 안에서 다시 찾는 경우가 있다 (`SUM(` → `SUM((` 가 두 번 — 실험 1가지). 바꿔서 순환에 든 칸은 같은 고리의 칸 모두 0 으로 맞았지만, 고리에 기대는 칸 하나(`Statement_of_Net_Worth`
  H35)는 한셀의 증분 계산 차례에 달려 다르다 — 한셀이 저장한 H35 의 값은 0 인데 `OR(SUM(D33)<>0,H33)` 은 H33 이 빈 글(`""`)이면 거짓으로 계산된다 (`OR(FALSE,"")` = FALSE 확인).
- 시트 보호: 이미 있는 암호 없는 보호에 다시 걸 때 한셀이 옛 `selectLockedCells`·`selectUnlockedCells` 를 막힘으로 남기는 규칙을 모른다 (corpus `filter2` 1종).
- 자동 필터: corpus 12종에서 준 범위 `A1:F30` 보다 아래까지 데이터가 있으면 한셀이 필터 범위 끝을 사용 범위 끝으로 늘렸다 — 값 있는 문서 실험 38가지에서는 늘리지 않아 규칙을 모른다 (22절). 값 배열 조건은 한셀이 첫 값만 받는 듯하다.
- 표 만들기: 데이터 칸에 서식이 있으면 한셀이 데이터 서식(`dataDxfId`)을 그 서식(채우기·글꼴·맞춤)으로 만든다 — 서식 없는 칸의 경우만 맞다 (corpus 34종 중 서식 있는 문서). 머리글이 255자를 넘으면 줄인다.
- 부분합: 겹쳐 내는 부분합(`replace: false`, 개요 3단계)은 하지 않는다 (실험 1가지). 한셀 `Subtotal` 은 보호된 시트와 영역이 첫 행이 아닌 곳에서 시작하는 문서에서 서버 오류로 멈춰 그 경우는 확인할 수 없다 (실험 3가지).
  통합은 목적지가 원본 범위와 겹치면 한셀이 이름표 아래 글 칸을 그대로 둔다 (실험 1가지 — rcell 은 지운다).
- 열 너비 자동 맞춤: 쉼표·지수 꼴로 보이는 숫자와 소문자 몇 글자에서 1/256 – 0.6 글자 다르다 (실험 125가지 중 3가지).
- 한셀 COM 으로 확인했지만 하지 않은 편집 (19·24절): 차트 더하기·차트 데이터 범위·계열 바꾸기, 선(`AddLine`), 표 요약 행·머리글 없는 범위·크기·이름·스타일 바꾸기, 피벗 표(`CreatePivotTable` 은 `InvokeMember` 로 동작해 파트를 만든다 — 칸 배치
  계산을 하지 않았다), 값 배열 필터, 이름 붙은 스타일(`Range.Style` 은 영어 내장 이름만 받고 범위와 상관없이 첫 칸에 적용되는 듯하며 `Styles` 컬렉션은 비어 있어 `Styles.Add` 가 실패한다), 고급 필터(`AdvancedFilter` — 제자리 조건은 행을 숨기지
  않고 값이 같은 것 제외는 틀린 행을 숨기며 다른 곳으로 복사는 오류), 통합 문서 사이 시트 복사(입력 문서가 하나).
- 한셀 자동화로 확인할 수 없던 것: 행·열 그룹(`Range.Group` 없음), 탭 색 지우기, 유효성 더하기(`Validation.Add` 가 `notBetween`·빈 수식으로 만들고 선택 영역에 붙는다), 조건부 서식의 차등 서식(`FormatConditions.Add` 가 서식을
  만들지 않는다), 하이퍼링크 안 위치 — rcell 규칙으로만 둔다. 틀 고정은 한셀이 창 크기에 따라 왼쪽 위 칸을 바꿔 쓴다.

## 12. 정렬

정렬 대조 실험: 값 50가지와 무작위 글 300개를 한셀 COM `Range.Sort`(Sort 개체는 여러 열 범위에서 `Header=xlNo` 를 따르지
않아 쓰지 않는다)로 정렬한 차례, 그리고 수식·서식·메모·하이퍼링크·조건부 서식·유효성이 있는 실험 문서 30여 가지를
정렬해 저장한 결과와 비교했다 (`src/edit/sort.rs`, `collate.rs`).

- 글의 차례: 한셀은 Windows 의 한국어(ko-KR) 단어 정렬로 글을 비교한다 — 무작위 글 300개의 한셀 차례가
  `CompareStringEx("ko-KR", NORM_IGNORECASE)`(대소문자 구분이면 플래그 없이)의 안정 정렬과 모두 같았다. 그래서
  기호(공백 `!` `#` … `_` `~`) < 숫자 글 < 라틴 문자(대소문자 무시, 악센트는 다음 단계, 전각은 그다음) < 그리스 < 키릴 <
  가나 < 한글(자음 자모 `ㄱ` 은 그 자음의 음절 바로 앞, 모음 자모는 모든 음절 뒤) 이고, 작은따옴표·하이픈은 끝에서만
  따진다 (`xy` < `x-y`, `'x` < `-x` < `xy`). 가나는 정렬 키의 특수 부분에 글자마다 갈래(작은 글자·가타카나·반각)를 두어 작은 글자 < 보통 글자,
  반각 < 전각 가타카나 < 히라가나 (`ｧ ァ ぁ ｱ ア あ`, `ｱｲ アイ アい あイ あい`), 장음 기호(ー ｰ)는 앞 가나 글자의 모음을 되풀이하고
  (おー = おお 다음) 앞 글자가 없으면 맨 끝, 탁점·반탁점(ﾞ ﾟ)은 앞 글자의 발음 구별 가중치에 더한다 (`ｶﾞ ガ が`). 대소문자 구분이면 같은 글자는 소문자가 앞. rcell 은 글자 하나의 정렬
  가중치(`LCMapStringEx` 의 키를 나눈 것 — 라틴·그리스·키릴·기호·가나·한글 자모·전각 문자 3918자와 한글 음절의
  기준점 82개)를 표로 두고 같은 키 짜임(주 가중치 → 발음 구별 → 대소문자 → 건너뛴 글자)으로 비교한다.
- 값의 차례: 숫자(날짜 포함) < 글 < `FALSE` < `TRUE` < 오류(`#NULL!` `#DIV/0!` `#VALUE!` `#REF!` `#NAME?` `#NUM!` `#N/A`)
  < 빈 칸. 내림차순은 빈 칸만 끝에 두고 뒤집는다. 같은 값은 원래 차례 (오름·내림 모두 안정). 숫자 꼴 글(`'10`)은 글.
  수식 칸은 지금 값으로 비교한다 (정렬 앞에 다시 계산한다).
- 줄마다 범위 안의 값·수식·서식·메모·하이퍼링크가 옮겨진다. 수식의 상대 참조는 복사처럼 옮긴 만큼 바뀐다
  (`=B2*2` 가 10행으로 가면 `=B10*2`, 범위 밖에서 범위를 가리키는 참조는 그대로). 테두리는 자리에 남는다 — 값과 글꼴·
  채우기·표시 형식만 옮겨지고 칸의 테두리는 그 자리의 것을 둔다. 행 높이·숨김, 유효성은 그대로.
- 필터 조건이 걸린 시트에서는 숨긴 행을 그 자리에 두고 보이는 행만 정렬한다 (숨김만 있는 시트는 숨긴 행도 정렬).
- 병합된 셀이 범위에 걸치면 정렬할 수 없다 — 다만 차례가 바뀌지 않으면 오류 없이 지나간다. 배열 수식이 있는 범위도
  정렬할 수 없다. 보호된 시트는 `sort` 가 막혔으면 할 수 없고, 허용됐으면 잠긴 칸도 정렬한다 (한셀 자동화).
- 조건부 서식: 새 줄을 끝 자리부터 채우는 차례로 원본 줄에 걸친 규칙(묶음 차례, 묶음 안에서는 우선순위 차례)마다 하나씩
  센다. 범위가 그대로인 규칙은 우선순위가 센 수만큼 내려가고, 옮긴 몫이 범위 밖에 놓이는 규칙은 그 몫을 범위에 더하고
  (맞닿은 것끼리 이어 붙인다 — `D5:D6` + `D4` = `D4:D6`, 떨어진 조각은 행 차례로 뒤에) 처음 더한 때의 차례 번호를
  우선순위로 받아 목록 끝으로 간다 (같은 줄에서 넓힌 묶음끼리는 원래 차례, 나중 줄의 묶음이 앞).
  데이터 막대가 든 묶음은 넓히지 않고 그대로 두며, 정렬한 줄마다 그 줄의 몫으로 같은 규칙의 새 묶음을 하나씩 만든다
  (같은 자리에 머문 줄도 — 우선순위는 그 줄에서 센 차례 번호). **한셀은 같은 문서·같은 정렬을 두 번 돌려도 묶음 구조가 다르게 나온다** — 어떤 줄의 묶음이 빠지거나 다른 줄의
  묶음에 붙는다(한 번은 `D1` 과 `D11` 이 한 묶음, 다음엔 `D2:D12` 가 한 묶음). 한 문서 20가지 순열·n = 2–16 열 87가지에서 모두 그랬고 정렬 뒤 기다리는 시간과도
  상관이 없었다 — 그래서 맞출 수 없다 (corpus 에서 갈리는 것은 모두 이 무작위다). 채우기의 데이터 막대(`D8` 과 `D9` 가 한 묶음이 되기도 한다)도 같다.
- 메모: 칸을 따라가고, 상자는 앵커의 칸마다 한 칸 앞(숨긴 행·열은 건너뛴다)으로, 오프셋은 1px 줄여 앵커 좌표(열 너비·
  행 높이 − 1px)로 고른다 (앞 칸이 없으면 왼쪽·위는 2px, 오른쪽·아래는 첫 칸 너비 + 1px 줄인다). 옮긴 메모는 목록 끝에 새
  자리 차례로 가고, 새 자리를 위에서부터 채우며 만들 때 이름(`메모 N`)이 아직 다른 메모에 쓰이면 앞에서 준 번호 다음의
  비어 있는 가장 작은 번호를 받는다. 하이퍼링크(한 칸짜리)도 칸을 따라간다.
- 자동 필터로 정렬(`sortFilter`)은 필터 범위를 첫 행을 머리글로 두고 정렬하고 필터에 `sortState` 를 남긴다 — 한셀은
  `ref` 를 범위의 둘째 행부터, 조건의 `ref` 를 그 열의 첫 행부터 쓴다. rcell 은 시트와 자동 필터의 `sortState` 를 읽고
  쓰고 비교한다 (XML 형식).

## 13. 자동 채우기·연속 데이터

채우기 대조 실험: 씨앗 70여 가지를 `Range.AutoFill`(기본·연속·복사·서식·값·날짜 단위)과 `Range.DataSeries` 로 채운 값을
읽고, 서식·조건부 서식이 있는 실험 문서에서 채운 결과를 저장해 비교했다 (`src/edit/fill.rs`).

- 씨앗을 채울 방향으로 되풀이해 붙이고(서식·수식은 채우기 규칙 — 상대 참조가 옮겨진다), 값은 씨앗을 같은 종류끼리
  이어진 묶음으로 나눠 묶음마다 이어 간다 (`[1, a]` → `1 a 2 a 3 a`).
- 숫자: 씨앗이 한 칸뿐이면 복사(연속 데이터·값만이 아니면), 여러 칸 씨앗 안의 숫자 하나는 1씩, 둘 이상이면 최소 제곱
  직선 (`1, 2, 4` → `5.333…, 6.833…`, 씨앗은 그대로).
- 날짜: 하나면 하루씩(시각만이면 한 시간씩, 날짜+시각은 하루씩), 둘 이상이면 같은 날짜면 달·해 간격(그 달에 없는 날은
  마지막 날 — `1-31, 3-31` → `5-31, 7-31, 9-30`), 아니면 같은 날 수 간격, 간격이 고르지 않으면 복사.
- 끝에 숫자가 있는 글: 마지막 숫자를 1씩(둘 이상이면 그 간격 — 앞뒤 글이 같은 것끼리) 늘린다 (`x10y` → `x11y`,
  `가1나2` → `가1나3`). 0 앞채움 자릿수를 지키고(`'007` → `008`, `099` → `100`), 영어 서수 꼬리를 맞추고(`1st 2nd 3rd 4th`,
  `11th`, `101st`), 0 아래는 절댓값 (`항목3` 을 위로 채우면 `항목2 항목1 항목0 항목1 …`).
- 한셀 기본 목록 18가지(일·일요일·1월·일월·1사분기·일사분기·1/4 분기·1Q·First Quarter·日·1月·1四分期·Sunday·Sun·Jan·
  January·자축인묘…·갑을병정…)의 항목은 목록을 돈다. 둘 이상이면 그 간격 (`월, 수` → `금 일 화`). 영어는 대소문자 꼴을
  따른다 (`mon` → `tue`, `MONDAY` → `TUESDAY`, `First Quarter` → `Second quarter`). 목록에 없는 글(`子` `甲`)·논리값·
  오류는 복사.
- 위·왼쪽으로 채우면 거꾸로 이어 간다. 한셀은 날짜·시각 하나는 멀어질수록 늘리고, 둘 이상인 글·목록 묶음은 마지막
  항목에서 앞으로 이어 간 값을 쓴다 (`항목1, 항목3` 을 위로 → 바로 위가 `항목7`).
- 조건부 서식·유효성: 채운 칸마다 그 씨앗 칸이 든 묶음의 범위를 넓히고 씨앗이 들지 않은 묶음에서는 그 칸을 뺀다
  (우선순위·범위 목록의 차례는 그대로). 데이터 막대가 든 묶음은 건드리지 않고 그 칸도 바꾸지 않는다. 채운 칸의
  하이퍼링크는 없어진다. 씨앗이나 채울 범위에 일부만 걸친 병합이 있으면 한셀은 아무것도 하지 않는다 (오류도 없다).
- 연속 데이터(`series`): 줄마다 첫 칸에서 시작해 나머지 칸을 채운다 (둘째 씨앗도 덮는다). 선형(더하기)·급수(곱하기)·
  날짜(일·평일·월·년 — 월·년은 첫 날짜에서 센 달 수로, 마지막 날 맞춤)·자동 채우기. 끝 값을 넘는 칸은 그대로. 추세면
  처음 값들의 직선·지수 맞춤으로 처음 값까지 다시 쓴다. 숫자가 아닌 첫 칸은 채우지 않는다.

## 14. 찾기·바꾸기

바꾸기 대조 실험: 값·수식·날짜·시각·백분율·글자 접두 칸 22가지에 바꾸기 18가지를 `Range.Replace` 로 실행했다
(`src/edit/find.rs`).

- 찾는 글은 셀의 수식 글이다: 수식은 `=…`, 날짜·시각 형식의 칸(값 0 이상 2958466 미만)은 12시간 `yyyy-mm-dd hh:mm:ss
  AM/PM` — 시는 두 자리, 0시 = `12:00:00 AM`, 초는 반올림하고 자리 올림은 날짜로 (`0.99999999` → 시각만이면 `12:00:00 AM`,
  날짜가 있으면 다음 날). 시각 부분이 있는 형식(`hh:mm:ss`·`h:mm AM/PM`·`[h]:mm`·`yyyy-mm-dd hh:mm` …)은 1 미만이면 시각만, 아니면
  날짜 + 시각 (`2023-03-15 12:00:00 AM` — 정수여도 시각을 붙인다), 날짜만 있는 형식은 정수면 날짜만 (0 = `1900-01-00`,
  60 = `1900-02-29`), 소수 부분이 있으면 시각도. 그 밖의 숫자는 일반 표기 (백분율 `10%` 도 `0.1`, `1,234` 는 `1234`),
  논리값은 `TRUE` (날짜·시각 형식 8가지 × 값 20가지 모두 같음). 한셀은 와일드카드(`*` `?` `~`)를 쓰지 않고 글자
  그대로 찾는다.
- 대소문자 구분을 끄면 무시한다. "셀 전체"는 한셀에서 공백으로 나뉜 낱말 전체가 같은 것이다 (`apple pie` 의 `apple` 은
  바뀌고 `apple-pie`·`="apple"` 은 아니다).
- 바꾼 글은 칸에 다시 입력한다 (2절 — `100` 의 `1` → `2` 는 숫자 200, `2024-01-15` 의 `2024` → `2025` 는 날짜, `TRUE` →
  `yes` 는 글, 글자 접두가 있던 칸은 글, 수식은 다시 고른다, 빈 글이 되면 내용을 지운다). 백분율 칸의 숫자 글은 100 으로
  나누지 않는다 (`0.1` → `0.2`). 시각이 틀린 꼴이 되면 글 (`22:30:00 PM`).
- 바꿔서 새로 고른 수식은 처음 값이 0 이다. 순환 참조에 들면(`IF(SUM(G9:G11),…)` 가 `SUM(G9:G77)` 로 바뀌어 자기 칸을 품는 때)
  한셀은 그 칸을 계산하지 않고 0 을 둔다 — 반복 계산을 켜지 않았을 때 같은 고리에 든 칸은 모두 그렇고 (계산 엔진의 강한 연결 요소),
  고리 밖에서 읽는 칸은 그 값을 읽는다.
- `all` 이면 모든 시트, `range` 가 있으면 그 안에서만. 찾기는 라이브러리 `edit::find::find_all`(값에서 찾기는 표시된 글)과
  wasm `rcell_doc_find` 로 칸 목록을 돌려준다.

## 15. 셀 삽입·삭제, 숨기기·그룹·틀 고정·탭 색

셀 삽입·삭제 대조 실험: 값·수식 20가지·병합·조건부 서식·메모·하이퍼링크가 있는 문서에서 `Range.Insert`·`Delete` 7가지,
보기 대조 실험 16가지 (`src/edit/cells.rs`, `view.rs`).

- 셀 삽입(아래·오른쪽으로 밀기)·삭제(위·왼쪽으로 당기기)는 범위가 걸친 열(행)의 띠만 행(열) 삽입·삭제처럼 움직인다.
  수식 참조는 엇갈린 축의 범위가 띠 안에 모두 든 것만 바뀐다 (`B3:C4` 아래로 삽입: `B5` → `B7`, `SUM(B1:B10)` →
  `SUM(B1:B12)`, `SUM(A3:D6)` 은 그대로, 지운 칸만 가리키면 `#REF!`·`SUM(#REF!)`). 삽입한 칸은 위(왼쪽) 칸의 서식을 받는다.
- 셀 기록 없이 행·열 서식으로만 보이던 칸도 옮겨진다: 위아래로 옮기면 원래 행의 행 서식(없으면 기본), 좌우로 옮기면 원래
  열의 열 서식(없으면 기본)을 지닌 칸이 되고, 옮긴 자리가 셀 없이 보일 서식(위아래: 그 행의 행 서식, 좌우: 행 서식이 있는
  행이면 그것, 아니면 그 열의 열 서식)과 다를 때만 셀을 만든다. 그래서 열 서식이 끝 열까지 걸린 시트에서 행 서식 행의 칸을
  오른쪽으로 밀면 한셀은 끝 열(`XFD`)까지 열 서식 셀을 쓴다. 지울 때는 서식 있는 마지막 줄 너머에서 당겨 오는 칸도 본다.
- 병합: 띠 안에 모두 들면 함께 움직이고, 띠에 일부만 걸쳐 움직이는 자리에 있으면 풀린다 (한셀은 오류를 내지 않는다).
- 조건부 서식·유효성 범위: 삽입은 범위의 두 모서리를 칸처럼 따로 옮긴다 (그래서 `C3:D8` 에 `B3:C4` 를 오른쪽으로 넣으면
  `E3:D8` — 한셀이 그대로 쓴다). 삭제는 띠 밖의 몫은 그대로 두고 띠 안의 몫만 줄인다 (조각은 첫 행 차례: `D3:D8 C3:C6`).
  삽입에는 한셀만의 넓히기가 하나 더 있다: 아래로 넣으면 오른쪽 끝 열이 띠 첫 열 바로 왼쪽이거나 끝 행이 넣은 첫 행 바로
  위인 범위가, 오른쪽으로 넣으면 끝 행이 띠 첫 행 바로 위이거나 오른쪽 끝 열이 넣은 첫 열 바로 왼쪽인 범위가 — 띠와
  겹치지 않아도, 멀리 떨어져 있어도 — 넣은 줄 수만큼 늘어난다 (`B3:C4` 아래로: `A1:A12` → `A1:A14`, 유효성 `A1` →
  `A1:A3`, `G1:H2` → `G1:H4`; `R3:R4` 오른쪽으로: `G1:H2` → `G1:I2`, `Q5` → `Q5:R5`). 삭제에는 없다 (실험 20가지).
  조건부 서식·유효성 수식의 절대 참조는 셀 수식처럼 띠 안의 것만 옮기고 (목록 원본 `$B$1:$B$5` → `$B$1:$B$7`), 상대
  참조는 범위 전체의 왼쪽 위 칸 기준이라 그 칸이 바뀐 만큼 옮긴다 (`F1:F12 H1:H3` 의 `LEN(TRIM(F1))` 에서 D6:E6 을 왼쪽으로
  지우면 `LEN(TRIM(D1))`). 지운 뒤 범위 목록은 손대지 않은 범위가 원래 차례로 앞에 오고, 왼쪽으로 지우면 옮긴 몫 → 남은
  몫(`H1:H3 D6 F1:F5 F7:F12`), 위로 지우면 남은 몫 → 옮긴 몫(`D3:D8 C3:C6`) 차례다.
- 틀 고정 범위와 페이지 나누기: 넣을 때만 행·열을 넣은 것처럼 옮긴다 (`A10:B10` 오른쪽으로: `xSplit` 1 → 3, 왼쪽 위 칸은
  그대로 — 한셀이 다시 열면 왼쪽 위 칸을 고정 범위에 맞춘다; 행 나누기 10·20 → `B3:C4` 아래로 넣으면 12·22). 지울 때는
  그대로.
- 도형: 시작 표지가 띠 안의 움직이는 자리에 있고 끝 표지의 칸도 띠 안이면 행·열 편집처럼 옮긴다. 띠보다 넓은 도형은
  그대로 (B–E 열 그림은 `B3:C4`·`B3:D4` 아래로 넣으면 그대로, `B3:E4` 면 내려간다).
- 메모·하이퍼링크는 칸을 따라가고, 칸이 옮겨진 메모의 상자는 행·열 삽입·삭제와 같이 다시 둔다 (3절).
- 행·열 숨기기는 숨김 표시를 바꾸고 (열 정보가 없는 열은 시트 기본 너비로 만든다), 크기를 지키는 그림(`editAs="oneCell"`)의
  끝 표지를 크기에 맞춰 다시 정한다 (1–8행 그림은 3·4행을 숨기면 10행까지). 칸 첫머리에서 시작하는 그림 바로 앞 열(행)을
  숨기면 한셀은 시작 표지를 그 숨긴 열로 옮긴다 (G2 → F2+0). 보호된 시트는 행·열 서식이 허용돼야 숨길 수 있다.
- 시트 숨기기: 활성 시트를 숨기면 다음 보이는 시트(없으면 앞)가 활성·선택된다. 마지막 보이는 시트는 숨길 수 없다.
- 틀 고정: 칸의 왼쪽·위를 고정한다 (`xSplit` = 열 번호, `ySplit` = 행 번호, 오른쪽 아래 첫 칸 = 그 칸, 나뉜 칸 쪽
  `bottomRight` `bottomLeft` `topRight`). 선택은 그 칸으로. 한셀 자동화는 창이 보일 때만 틀을 고정한다.
- 탭 색: `sheetPr/tabColor`. 그룹은 개요 수준을 1 올리고(7까지) 해제는 1 내린다.

## 16. 선택하여 붙이기

선택하여 붙이기 대조 실험: 값·수식·빈 칸·서식·메모가 있는 원본을 값·서식·수식이 있는 대상에 `Range.PasteSpecial`
18가지로 붙였다 (`src/edit/special.rs`).

- 값: 수식은 계산한 값으로, 원본 빈 칸은 대상 내용을 지운다. 대상 서식은 그대로. 서식: 서식(조건부 서식·병합 포함 —
  붙이기 규칙)만. 수식: 수식(상대 참조는 복사처럼)과 값, 서식은 그대로. 값·숫자 서식 / 수식·숫자 서식은 표시 형식도.
  테두리만 빼고: 붙이기와 같고 대상의 테두리를 남긴다.
- 행/열 바꿈: 칸을 뒤집고 수식의 참조도 행·열 차이를 바꾼다 — 한셀은 절대 참조도 바꾼다 (`C2` 의 `=$A$1+1` 을 E1 에
  바꿔 붙이면 F3 에 `=$E$1+1`). 조건부 서식은 원본 칸마다(행 차례) 그 칸이 든 묶음들을 바꾼 자리 한 칸에 따로 붙인다
  (칸마다 맨 위 우선순위 — 마지막 칸의 것이 가장 위, 데이터 막대 묶음은 한 번 더). 유효성은 범위를 뒤집어 원래 개체 끝에
  더한다 (`A1` → `A1 AP1`).
- 서식만 붙이기는 유효성을 옮기지 않고 범위 차례도 뒤집지 않는다 (모두 붙이기는 유효성마다 뒤집는다 — 5절). 행/열 바꿔 모두
  붙이기는 원본 칸마다(행 차례) 붙인다: 칸이 유효성 범위 안이면 바꾼 자리의 한 칸을 목록 끝에 더하고, 범위가 둘 이상이던
  유효성은 칸마다(범위 밖 칸도) 목록 차례를 뒤집는다 — 칸이 홀수 개면 뒤집힌 채, 짝수 개면 원래 차례. 범위가 하나뿐이던 유효성은 뒤집지 않고,
  **마지막으로 범위 안이던 칸 뒤에 이어진 칸이 짝수 개(0 포함)일 때만** 끝에 한 번 뒤집는다 (더한 칸이 앞에 온다). 끝나면 더한 칸 중
  맞닿은 것을 **나중에 더한 칸의 자리**에 하나로 잇는다 (유효성 대조 실험 28가지 모두 같음).
- 빈 셀 무시: 원본의 빈 칸은 대상을 바꾸지 않는다.
- 연산: 대상 값 ∘ 원본 값 (원본 빈 칸은 0 — 곱하면 0, 나누면 `#DIV/0!`). 원본 글·논리값은 건너뛰고, 대상 글은 그대로.
  대상이나 원본이 수식이면 수식으로 `(대상 수식)∘원본`·`대상 값∘(원본 수식)`.
- 붙인 범위를 선택한다 (활성 칸 = 첫 칸).
- 복사해 붙이기(모두·테두리만 빼고·`copy` 명령)는 범위 안의 메모도 붙인다 (이번에 더함 — 한셀의 `Range.Copy`). 붙인 메모는
  쓰지 않은 다음 `메모 N` 이름을 받는다.

## 17. 메모·하이퍼링크·이름·유효성·조건부 서식·자동 맞춤

개체 대조 실험 18가지 (`src/edit/objects.rs`).

- 새 메모: 글은 `작성자:` 줄 다음에 (굴림 9pt 검정 한 조각 — 한셀 자동화는 사용자 이름을 붙인다), 상자는 메모 칸의 열
  + 14px, 두 행 위 + 10px 에 126 × 79 px, 이름은 다음 `메모 N`. 고치면 글 전체를 바꾼다 (작성자 줄 없이). 지우기는 범위.
- 하이퍼링크: 칸이 비었으면 보일 글(없으면 주소)을 넣고 글꼴을 하이퍼링크 꼴(파랑 `FF0000FF`, 밑줄, 한컴 확장의 밑줄
  모양 실선·밑줄 색)로. 지우면 링크와 그 칸의 서식을 함께 없앤다 (값은 남는다 — 한셀 `ClearHyperlinks`).
- 이름: 통합 문서 또는 시트 범위 (`local`). 이름 규칙(글자·밑줄로 시작, 셀 주소 꼴이 아닌 것, 255자까지), 같은 이름이면
  참조를 바꾼다. 시트 없는 참조에는 시트를 붙인다 — `sheet` 를 주지 않으면 한셀 `Names.Add` 처럼 활성 시트 (`$A$1:$C$4`
  → `서식!$A$1:$C$4`).
- 유효성·조건부 서식: 더하면 그 범위의 다른 유효성은 그 칸에서 빠지고, 새 조건부 서식 규칙은 맨 위 우선순위(다른 규칙은
  하나씩 내려간다)에 차등 서식(채우기·글자 색·굵게)과 함께 둔다. 지우기는 범위에서 뺀다.
- 열 너비 자동 맞춤: 열의 칸마다 표시된 글의 폭으로 너비(글자 수) = ⌊(Σ글자 폭 × (K + 0.1)/K + K + 0.085) × 256/K⌋/256 의
  가장 큰 값 (K = 숫자 폭 — 맑은 고딕 11pt 는 8). 글자 폭은 정수 px 이다: 맑은 고딕 11pt 는 같은 글자 20개 칸을 맞춘
  너비로 ASCII 95자를 모두 쟀다 (숫자·a·e 8, 한글 15, 공백 5, W·M 14, i·l 4, 마침표·쉼표 3 …, 다른 크기는 비례해 반올림),
  다른 글꼴은 렌더러의 어림을 반올림한다. 실험 125가지 중 122가지가 같다 (다른 것: 소문자 a–j 1/256, 쉼표·지수 꼴 숫자).
  행 높이 자동 맞춤은 높이를 지정하지 않은 행으로 둔다 (한셀이 문서를 열 때 맞춘다).

## 18. 데이터 도구: 중복 항목 제거·텍스트 나누기·부분합

한셀 COM `Range.RemoveDuplicates`(실험 10가지)·`TextToColumns`(14가지)·`Subtotal`(30가지 중 27가지, 나머지는 아래)로 확인했다
(`src/edit/data.rs`).

- 중복 항목 제거: 범위의 행을 고른 열의 값으로 견준다 — 글은 대소문자 무시(공백은 그대로), 수 `1` 과 글 `'1` 은 다르고, 빈 칸끼리·
  같은 논리값·같은 오류끼리는 같다. 표시 형식이 달라도 값이 같아야 같다 (1.2 가 `0` 서식으로 `1` 로 보여도 1 과 다르다).
  첫 행만 남기고 범위 안 열의 칸을 위로 당긴다 — 수식 글은 그대로이고(참조를 고치지 않는다) 서식·메모·하이퍼링크도 따라간다.
  모자란 끝 행은 내용과 서식을 지운다. 범위 밖 열, 행 높이·숨김은 그대로. 병합이 걸치면 할 수 없다.
- 텍스트 나누기: 한 열의 칸마다 표시된 글을 구분 문자(탭·세미콜론·쉼표·공백·그 밖의 한 글자)로 나눠 `dest`(없으면 그 열
  자리에 덮어쓴다)부터 오른쪽으로 넣는다. 필드는 입력 규칙대로 들어간다 (`007` → 7, `2024-01-05` → 날짜, `50%`, `=1+2` 는 수식,
  빈 필드는 그 칸의 내용을 지움). 열 형식 `text` 는 `@` 서식의 글, `skip` 은 넣지 않는다(목적지 열을 차지하지 않는다).
  큰따옴표(또는 `qualifier` 로 정한 글자)로 묶은 필드 안의 구분 문자는 글자 그대로이고 따옴표 두 개는 하나, 짝 없는 따옴표는
  끝까지가 한 필드. `consecutive` 면 이어진 구분 문자는 하나. 구분 문자가 없으면 글을 그대로 옮긴다.
- 부분합: 한셀은 고른 범위가 아니라 **그 첫 칸의 현재 영역**(빈 행·열로 둘러싸인 덩어리)에 내고, 열 번호도 영역 안 번호다.
  첫 행은 머리글. 기준 열 값이 이어진 묶음마다 끝에 행을 넣어 기준 열에 `값 합계`(굵게, 기준 값의 표시 형식), 합계 열에
  `SUBTOTAL(번호,묶음 범위)` (묶음에서 General 이 아닌 첫 칸의 표시 형식 — 없어도 `applyNumberFormat`)를 둔다. 맨 끝에는
  `총 합계`(합계만, 그 밖은 `전체 개수` …)와 전체 범위. 소계 글: 합계·개수·평균·최댓값·최솟값·곱·수치 개수·표본 표준 편차(7)·
  표준 편차(8)·표본 분산(10)·분산(11). 새 행은 위 행의 행 속성을 받고 칸 서식은 위 규칙대로만. 개요: 자료 행 2단계, 소계 행
  1단계, 전체 행 0단계, 요약 행마다(맨 바깥 요약 행 — 아래 모드는 전체 행 다음 빈 행, 위 모드는 머리글 — 에도) `collapsed`.
  `summaryBelow: false` 는 묶음 위와 머리글 바로 아래에 넣고 `sheetPr/outlinePr` 를 쓴다. `pageBreaks` 는 묶음마다(아래 모드는
  소계 행 뒤, 마지막은 전체 행 뒤 / 위 모드는 마지막을 뺀 묶음의 끝 자료 행 뒤). 기준 열이 빈 묶음은 소계 행이 없고 개요 1단계.
  `replace`(기본)는 이미 있는 `SUBTOTAL` 행을 지운 뒤 다시 낸다. 겹쳐 내는 부분합(`replace: false`, 개요 3단계)은 하지
  않는다 (실험 1가지). 한셀은 영역이 첫 행이 아닌 곳에서 시작하는 문서에서 `Subtotal` 이 서버 오류로 멈춘다 (실험 2가지 —
  확인할 수 없다).
- 통합: `sources` 범위들을 `dest` 부터 **값으로**(연결 없이) 합친다. `leftColumn` 이면 각 범위의 왼쪽 열이, `topRow` 면 위쪽 행이 이름표
  (대소문자 무시, 처음 나온 차례로 모은다)이고 없는 쪽은 칸 자리로 모은다. 이름표만 적고 숫자만 센다. 이름표는 원본 칸의 값 그대로 쓰고(숫자는 숫자) 위쪽·왼쪽 이름표 칸 모두 비어 있을 때만 쓰고
  (이미 내용이 든 이름표 칸은 그대로), 값 칸은 모두 쓴다 — 결과가 없으면(`stdev`·`var` 에 값이 하나뿐일 때 …) 그 칸을 비운다.
  함수는 부분합과 같은 열한 가지 (실험 22가지 모두 같음 — 범위가 통합 목적지와 겹치는 1가지는 한셀이 이름표 아래 글 칸을 그대로 둔다). 연결을 만드는
  통합(`createLinks`)은 하지 않는다.
- 시트 보호: 중복 항목 제거·텍스트 나누기·통합은 한셀 자동화가 시트 보호를 보지 않아 잠긴 칸(이미 값이 든 칸 포함)도 덮어쓴다 (실험
  7가지·corpus 2종). 부분합은 보호된 시트에서 한셀이 서버 오류로 멈추므로 rcell 도 보호된 칸을 건드리면 오류로 둔다.

## 19. 도형·그림·차트 옮기기·크기·지우기

한셀 COM `Shape.Left/Top/Width/Height`·`Shape.Delete` 로 도형 4개가 있는 서식 파일과 차트 문서에서 확인했다 (`src/edit/shapes.rs`,
실험 70가지 모두 같음).

- 위치·크기는 포인트(시트 왼쪽 위 기준)이고 한셀은 준 값에 **0.5pt 를 더해** 셈한 px(×96/72)를 반올림한다: `Left` 50pt → 67px, 300pt → 401px,
  `Width` 300pt → 401px (66.67+0.67 → 67, 400+0.67 → 401, 75.64pt → 102px — 정수 부분에 1 을 더하는 식과 소수 부분이 .83 이상일 때 갈린다). 새 왼쪽 위·오른쪽 아래 표지는 시트 배치(열 너비·행 높이)에서 그 px 자리의 칸과
  칸 안 오프셋(px)이다. 주지 않은 값은 그대로이고 (`Left` 만 주면 크기를 지킨다) 두 칸 앵커(`editAs="oneCell"` 그림 포함)·한 칸 앵커·
  절대 앵커 모두 같은 규칙이다. 가로세로 비율 잠금(`noChangeAspect`, 그림)은 너비를 바꾸면 높이가, 높이를 바꾸면 너비가 원래 크기 비율대로 따라 바뀐다 (한셀은 0.5pt 를 더한 포인트 실수로 이어 셈하고 끝에 px 로 반올림 — 둘 다 주면 너비 다음 높이 차례라 높이가 마지막이고 너비는 그 비율로 다시 바뀐다). 차트는 도형 차례에 들어 있다. 지우면 그 도형만 없어지고 다른 도형의 번호·이름은 그대로. 시트 보호의
  `objects` 가 막혀 있으면 할 수 없다.
- 도형 더하기(`addShape` — `rect` `diamond` `roundRect` `triangle` `ellipse` `textbox`, 한셀 `Shapes.AddShape`·`AddTextbox` 대조 30가지 모두 같음, 도형이 있는 문서·그림 문서·빈 문서): 위치·크기(포인트)는
  ×96/72 를 반올림한 px 이고 (`Left` 같은 값 설정의 +0.5pt 규칙은 없다) 오른쪽 아래는 왼쪽 위 + 크기, `a:xfrm` 도 그 px 값이다. 새 번호는 그 시트 도형 번호의 가장 큰 값 + 1
  (처음이면 2), 이름은 `<종류 이름> <번호 − 1>` (`직사각형` `다이아몬드` `모서리가 둥근 직사각형` `이등변 삼각형` `타원`, 글상자는 빈 이름). 두 칸 앵커이고 `xdr:style`(선·채우기 참조)이 붙는 한셀 기본
  모양이다 (둥근 직사각형 `adj 16667`, 삼각형 `adj 50000`). 한셀 자동화의 도형 더하기는 시트 보호를 보지 않는다. 한셀의 `Duplicate`·`Copy`/`Paste` 는 COM 에서 도형을 만들지 못한다.
- 한셀 COM 으로 확인한 것 중 하지 않은 것: 차트 더하기(`ChartObjects.Add` 는 동작하지만 차트 XML 의 많은 기본값을 맞추지 못했다), 차트 종류·데이터 범위 바꾸기(`ChartType`·`SetSourceData` 는
  동작하지만 결과를 검증하지 않았다, 계열 `Formula`·제목 글은 속성이 없다), 선(`AddLine`)·표 크기 바꾸기·이름·스타일 바꾸기·표 풀기(`Unlist` 없음), 피벗 표(`PivotCaches().Create`·`CreatePivotTable` 이
  `InvokeMember` 로는 동작해 캐시·레코드·표 파트가 만들어지지만 칸에 쓰는 배치 계산을 하지 않았다). 표 만들기는 24절. 한셀의 `CommandBars`·`ExecuteMso` 는 없고 `SendKeys` 는 화면
  초점에 달려 쓰지 않았다. 표·차트는 행·열 삽입·삭제에서 따라간다 (3절·말뭉치 대조), 피벗은 그대로 둔다.

## 20. 쪽 설정·보기 설정

한셀 COM `PageSetup`(쪽 설정 85가지)·`ActiveWindow`(보기 74가지)로 확인했다 (`src/edit/page.rs`, `view.rs`).

- 쪽 설정(`pageSetup`)은 준 것만 바꾼다. 여백은 포인트(÷72 = 인치, 한셀이 저장할 때 32비트 실수로 줄인다), 용지 번호·방향(`portrait` `landscape`),
  확대율(`zoom` → `scale`), 페이지 맞추기(`fitWide`·`fitTall`, 0 은 자동 — `fitToPage`·`autoPageBreaks` 를 켠다), 가운데 맞춤·눈금선·행/열 머리글
  인쇄, 흑백·초안, 쪽 차례(`overThenDown`), 시작 쪽 번호(0 이면 자동), 메모 인쇄(`atEnd`, `inPlace` → `asDisplayed`), 오류 인쇄(`blank` `dash` `na`).
- **페이지 맞추기의 배율**은 한셀이 맞추기를 켤 때 인쇄 배치로 셈해 `scale` 에 저장한다 (한셀 PDF 대조로 만든 `print::sheet_print` 의 `page_scale` 과
  같다 — 쪽 높이 − 위·아래 여백 대 내용 높이(행은 화면 px × 0.75), 가로는 쪽 너비 − 왼쪽·오른쪽 여백 대 열 너비, 쪽 수를 곱해 내림하고 95 를 넘으면 95). 맞추기 뒤에
  `zoom` 을 주면 `fitToPage` 가 꺼진다 (`fitToWidth`·`fitToHeight` 는 남는다, 맞추기가 켜진 채 `zoom` 100 은 받지 않는다). 쪽 수를 정한 뒤 `0`(자동)으로 되돌리면 한셀이 오류로 막는다(그 앞에서 한 것은 남는다).
  가로·세로 모두 자동이면 배율 100, **인쇄 영역이 둘 이상이면 세로 쪽 수를 정할 수 없고(오류) 배율은 셈하지 않고 100** 이다 (쪽 설정 대조 101가지 모두 같음).
- 인쇄 영역·반복 제목은 시트 범위 이름 `_xlnm.Print_Area`·`_xlnm.Print_Titles` 다 (상대 주소도 절대로, 여러 영역은 `,` 로 잇고 시트 이름을 각각 붙인다, 반복 제목은
  행 다음 열). 빈 글이면 이름을 지운다.
- 머리글/바닥글: 왼쪽·가운데·오른쪽 글을 `&L…&C…&R…` 로 잇는다. 글꼴 지정이 없는 글은 한셀의 `맑은 고딕,Regular` 를 앞에 붙이고(`&"맑은 고딕,Regular"&A 쪽` — 문서 글꼴이 Arial 이어도 같다), 지정한
  글꼴 이름은 대문자(`Arial` → `ARIAL`)로, 모양은 영어로(`굵게` → `Bold`, `기울임꼴` → `Italic`, `굵은 기울임꼴` → `Bold Italic`, `보통` → `Regular`) 바꾸고 `&B` 는 글꼴
  지정(`&"맑은 고딕,Bold"` …)으로 바꾼다. `PrintQuality`(인쇄 품질)는 저장되지 않는다. 쪽 설정 COM 은 보호된 시트에서도 된다.
- 보기 설정(`setView`)은 그 시트를 활성으로 만든다 (`activeTab`). 눈금선은 `showGridLines`, 행/열 머리글 `showRowColHeaders`, 0 표시 `showZeros`. 확대율은 12–400 (10 을 주면 12).
  한셀은 보기 방식(일반·쪽 나누기 미리 보기)마다 확대율을 따로 두는데 **저장할 때 `zoomScaleNormal` 에 미리 보기 확대율(기본 75)을, `zoomScaleSheetLayoutView` 에 일반
  확대율을 쓰고(엑셀 이름과 반대), 열 때는 일반 보기 문서면 일반 = `zoomScale`·미리 보기 = `zoomScaleSheetLayoutView`(기본 75), 미리 보기 문서면 미리 보기 = `zoomScale`·
  일반 = `zoomScaleNormal`(기본 100) 으로 읽는다** — 한셀이 저장한 문서는 다시 열 때마다 둘이 바뀐다. rcell 은 한셀이 읽는 꼴(엑셀 이름 그대로)로 쓴다. `zoomScale` 은 지금 보기의 것이고 100 이면
  쓰지 않는다. 페이지 나누기 미리 보기로 바꾸면 미리 보기 확대율(기본 75)이 된다. `pageLayout` 보기와 수식 보기(`DisplayFormulas`)는 한셀 COM 이 받지 않는다.
  창을 보이게 해야 하므로 한셀이 저장한 문서의 `windowWidth`·`windowHeight` 가 채워진다 (대조 도구는 이 차이를 같다고 본다).

## 21. 보호 걸기·풀기

한셀 COM `Worksheet.Protect`·`Unprotect`·`Workbook.Protect`·`Unprotect` 로 확인했다 (26가지 모두 같음, `src/edit/protect.rs`).

- 암호는 16비트 레거시 해시(소문자 16진 4자리 — `pw` → `cf75`, `abc` → `cc1a`)다. **글자는 코드 페이지 949 바이트로 본다** (`한글` → `c4bd`; 유니코드·UTF-8 로 셈하면 틀린다).
  빈 암호는 암호 없음.
- 시트 보호: 내용(`sheet`)·개체(`objects`)·시나리오를 막는다(기본 모두 참). 서식·행/열 삽입·삭제·하이퍼링크·정렬·필터·피벗은 `allow…` 로 허용한 것만 풀린다. 잠긴 칸·잠기지 않은 칸 선택은 막지 않는다.
- **암호가 있는 보호가 걸린 시트**에 다시 걸면 오류이고 (암호 없는 보호는 새 보호로 바뀐다 — 다만 corpus 한 문서에서 한셀은 옛 보호의 `selectLockedCells`·`selectUnlockedCells` 를 막힘으로
  남겼다: 합치는 규칙은 모른다), 풀 때 암호가 틀리면 오류(보호는 그대로), 암호 없는 보호는 암호 없이 풀린다.
- 통합 문서 보호는 **구조만** 저장한다 (`structure`) — 창 보호(`windows`)는 한셀이 걸지 않고, 문서에 이미 걸린 창 보호는 그대로 둔다 (구조가 이미 보호돼 있으면 오류). 구조를 보호한 문서를 한셀은 컴파운드 파일(OLE) 꼴로 저장한다 (rcell 은 읽는다).
  구조가 보호돼도 자동화로는 시트를 더할 수 있다 (7절).

## 22. 자동 필터

한셀 COM `Range.AutoFilter`·`ShowAllData` 로 확인했다 (31가지 중 30가지 같음, `src/edit/filter.rs`).

- `field` 없이 `range` 만 주면 자동 필터를 켠다 (`autoFilter`, 시트 `filterMode`, 숨은 이름 `_xlnm._FilterDatabase`). 이미 켜져 있으면 끄고 조건에 걸려 숨긴 행을 보인다.
  `field`(1부터)를 주면 그 열에 조건을 건다 (켜져 있지 않아도 켠다). 조건 없이 `field` 만이면 그 열 조건을 지우고, 범위 밖 열이면 오류(켠 것은 남는다).
- 조건 글: `>=50`·`<>x`·`=x`·`x` (연산자가 없으면 같음), `<>` 만이면 빈 칸이 아닌 것(값은 공백 한 글자), `=` 만이면 빈 값. 같음 조건은 **그 열의 지금 보이는 값**(머리글 제외)에 있으면 값 목록 필터
  (`filters/filter`)로, 없거나 `*`·`?` 와일드카드가 있으면 사용자 지정 조건(`customFilters`, `and`)으로 둔다 — 같은 열에 이어서 걸면 앞 조건으로 숨은 행은 값에서 빠진다. 두 조건은
  `operator`: `and`(기본)·`or`. 상위·하위(`top` `bottom` `topPercent` `bottomPercent`)는 개수·백분율과 경계값(`filterVal`)을 저장한다 (백분율은 데이터 행 수 × 비율을 내림).
- **범위**: 켜는 범위는 준 범위와 한셀 `UsedRange`(행은 행 기록이 있는 처음~끝 행, 열은 칸 기록 — 빈 서식 칸 포함 — 이 있는 처음~끝 열)의 겹침이고, 한 칸이면 그 칸의 현재 영역이다.
  겹침이 없으면 오류. 열 번호(`field`)는 줄인 범위 기준이고, 필터는 먼저 켜진 뒤 열 번호가 범위 밖이면 오류가 난다. 데이터 칸에 값이 하나도 없는 열의 조건은 행을 숨기지 않는다. (corpus 12종에서는
  준 범위 `A1:F30` 보다 아래까지 데이터가 있을 때 한셀이 범위 끝을 사용 범위 끝(`A1:E43`)으로 늘렸다 — 값 있는 문서 실험 38가지에서는 늘리지 않아 규칙을 모른다.)
- 숨기는 행은 걸린 모든 열의 조건을 함께 만족하지 못한 행이고(`reapply`), 조건을 건 뒤 칸을 고쳐도 다시 적용하지 않는다. `showAllData` 는 조건을 모두 지우고 행을 보이되 필터는 켜 둔다.
  `AutoFilterMode = False`(끄기)는 한셀 COM 에서 아무 일도 하지 않는다 — 켠 범위에 `autoFilter` 를 다시 주는 것이 끄기다. 값 배열 조건(`xlFilterValues`)은 한셀이 첫 값만 받는 듯 처리해 하지 않는다.

## 23. 시트 복사

한셀 COM `Worksheet.Copy`로 확인했다 (14가지 모두 같음, `edit::copy_sheet`).

- 복사본 이름은 `원본 (N)` (가장 작은 N ≥ 2, 이름을 주면 그 이름), 자리는 `to`(원본 목록 기준 — 그 시트 앞, 목록 끝이면 맨 뒤)이고 기본은 원본 바로 뒤. 복사본이 선택되고(`activeTab`) 새 시트 번호·코드 이름(`SheetN`)을 받는다.
- 그 시트의 지역 이름(인쇄 영역·필터 데이터베이스 포함)과 그 시트를 가리키는 전역 이름은 복사본의 지역 이름으로도 생긴다 (참조는 복사본으로). 복사본 안에서 원본을 이름(`Sheet1!A1`)으로 가리키는
  수식은 복사본을 가리키게 바뀌고 (`'Sheet1 (2)'!A1`), 다른 시트의 수식·차트·참조는 그대로(다른 시트를 복사하면 `Sheet1!A1+1` 이 그대로). 복사본의 메모 상자 이름은 `메모 0` 이 된다(한셀은 가끔 쓰레기 값을 넣는다 — corpus 1종). 구조가 보호된 통합 문서에서 한셀의 `Copy` 는 아무 일도 하지 않는다. 통합 문서 사이 복사는 입력 문서가 하나라 하지 않는다.

## 24. 표(ListObject) 만들기

한셀 COM `ListObjects.Add` 로 확인했다 (13가지 모두 같음, `src/edit/table.rs`). **`Add` 는 `[System.__ComObject].InvokeMember` 로 불러야 하고(PowerShell 직접 호출은 "메서드를 호출할 수 없음") 객체를 돌려주지 않아
`ListObjects.Item(n)` 으로 다시 얻는다** — 앞서 "`ListObjects` 가 없다" 고 쓴 것은 이 호출 방식 때문이었다.

- `addTable`: `range` 의 첫 행이 머리글이다. 이름은 `표N`(쓰지 않은 가장 작은 N), 번호는 가장 큰 번호 + 1, 스타일 `TableStyleMedium2`(줄무늬 행만, `style`·`stripes`·`firstColumn`·`lastColumn`·`columnStripes`
  로 바꾼다), 필터 범위는 표 범위와 같고 열 이름은 머리글 칸 글이다. 글이 아닌 머리글(수·논리값·수식 결과)은 보이는 글로 바뀌고 빈 머리글은 `열1`, `열2`… 가 칸에 써진다. 범위가 한 행(머리글뿐)이면 그 아래에
  빈 칸 한 행이 끼워진다 (아래 칸이 한 칸씩 밀린다, `A1` → `A1:A2`). 같은 범위의 시트 자동 필터는 표가 가져가고 겹치는 표는 만들 수 없다.
- 표 안 서식: 요약 행 테두리 `totalsRowBorderDxfId`(차등 서식 `가로 안쪽선 검정`)와 데이터 행이 둘 이상이면 열마다 `dataDxfId`(같은 모양의 둘째 차등 서식) — 문서에 이미 있으면 그 번호를 쓰고, 첫 열에 `요약`
  글(`totalsRowLabel`)이 붙는다.
- 하지 않는 것: 머리글 없는 범위(`xlNo` — 한셀은 머리글 행을 끼워 `열N` 을 쓴다)·요약 행(`ShowTotals`: 범위가 한 행 늘고 `요약` 글과 `SUBTOTAL(103,표1[열])` 이 써지며 차등 서식이 더 생긴다)·머리글 숨기기·크기 바꾸기·
  이름·스타일 바꾸기(`Unlist` 는 없다). 피벗 표는 `PivotCaches().Create` 와 `CreatePivotTable` 을 `InvokeMember` 로 부르면 만들어지고 저장하면 캐시 정의·레코드·피벗 표 파트(`location` 은 `J1:K4` 꼴)만 쓰고 시트 칸에는 아무것도 쓰지 않는다 — 칸은 한셀이 열 때 그리므로 새로 고침 표시(`refreshOnLoad`)도 없다 (rcell 은 피벗을 만들지 않고 파트를 그대로 둔다). **데이터 칸에 서식(채우기·글꼴·맞춤)이 있으면 한셀은 데이터 서식(`dataDxfId`)을 그 서식으로 만든다** — rcell 은 서식 없는 칸의 경우만 맞다 (corpus 34종 중 서식이 있는 문서가
  다르다). 머리글이 255자를 넘으면 한셀이 줄인다.
