# 편집 규칙

> 작성: yoomin53

rcell 의 편집 — 라이브러리 `rcell::edit`, 명령 `rcell edit`, 웹 편집기 — 은 한셀 2024 에서 같은 편집을 한 결과와 같은
문서를 만드는 것을 목표로 한다. 아래 규칙은 모두 한셀 COM 자동화로 같은 편집을 실행해 저장한 결과와 비교해 정했다
(10절). 한컴 파일은 저장소에 넣지 않는다 — 단위 시험은 실험 문서와 같은 모양의 문서를 코드로 만든다.

## 1. 편집 명령

편집 하나는 JSON 객체 하나다 (`rcell::edit::Edit`). 행은 1부터(한셀 화면과 같다), 열은 이름(`C`), 셀·범위는 A1
표기(`A1:C3`, `A:C`, `2:5`). `sheet` 는 시트 이름 또는 0부터 센 번호이고, 빼면 첫 시트다.

| `op` | 필드 | 동작 |
|------|------|------|
| `set` | `cell`, `input` | 셀에 입력 (2절의 입력 규칙). 빈 글이면 내용을 지운다 |
| `clear` / `clearFormats` / `clearAll` | `range` | 내용(Delete 키) / 서식 / 내용·서식·병합 지우기 |
| `insertRows` / `deleteRows` | `row`, `count` | 행 삽입·삭제 (3절) |
| `insertCols` / `deleteCols` | `col`, `count` | 열 삽입·삭제 |
| `format` | `range`, `bold` `italic` `underline` `strike` `fontName` `fontSize` `fontColor` `fill` `hAlign` `vAlign` `wrap` `numFmt` | 서식 (준 항목만 바꾼다. 색은 `RRGGBB`, 빈 글은 자동·채우기 없음) |
| `border` | `range`, `preset`(`all` `outline` `inside` `none` `left` `top` `right` `bottom`), `style`, `color` | 테두리 (4.2절) |
| `merge` / `unmerge` | `range`, `center` | 병합 (4.3절) / 풀기 |
| `colWidth` / `colWidthPx` | `col`, `count`, `width` / `px` | 열 너비 (한셀 `ColumnWidth` 글자 수 / 화면 px) |
| `rowHeight` | `row`, `count`, `height` | 행 높이 (pt) |
| `addSheet` / `renameSheet` / `deleteSheet` / `moveSheet` | `name`, `after` / `name` / — / `to` | 시트 (6절) |
| `copy` / `move` | `from`, `to`, `toSheet` | 복사해 붙이기 / 잘라 붙이기 (5절) |
| `fillDown` / `fillRight` | `range` | 아래로·오른쪽으로 채우기 |
| `pasteText` | `cell`, `text` | 탭·줄 바꿈으로 나눈 글을 칸마다 입력 규칙으로 붙인다 |

```bash
rcell edit 문서.cell 대본.json 결과.cell        # {"edits": [...]} 를 차례로 실행하고 다시 계산해 저장
rcell edit 문서.cell 대본.json 결과.xlsx --no-recalc   # 계산하지 않고 (형식은 확장자 또는 --format cell|xlsx|bin)
```

실패한 편집(보호된 칸, 병합의 일부 옮기기 …)은 건너뛰고 이유를 알린다 (`편집 #3 실패: …`). 라이브러리에서는 `edit::apply(&mut wb, &edit)` 또는 `set_input`,
`insert_rows`, `border`, `merge`, `copy`/`paste` … 를 직접 부른 뒤 `calc::recalculate` 로 다시 계산한다.

## 2. 셀 입력

입력 대조 실험: 표시 형식이 다른 칸 14종에 글 94가지를 `Range.Value2` 로 넣고 저장한 값과 형식을 비교했다
(`src/edit/input.rs`).

- `=` 로 시작하면 수식 (`=` 하나만이면 글). 함수 이름·참조·논리값·오류는 대문자로, 시트·이름은 문서의 표기로 고르고,
  교차 연산이 아닌 공백을 지우고 닫는 괄호를 채운다 (`= sum(a1:a3` → `SUM(A1:A3)`). 문법이 틀리면 입력하지 않는다.
- 작은따옴표로 시작하면 글 + 글자 접두(`quotePrefix`). `+A1`·`@SUM(A1)` 은 글이다.
- `TRUE`/`FALSE`(대소문자 무시)는 논리값, `#N/A` 같은 오류 글은 오류 값.
- 숫자 꼴(`1,234`, `(5)`, `$1,000`, `10%`, `1.5E3`, 앞뒤 공백), 시각(`12:30`, `9:05 AM`, `25:00`), 날짜(`2024-01-15`,
  `1/15`, `15-Jan`, `2024년 1월 15일`), 날짜+시각, 대분수(`1 1/4`)를 값으로 읽는다.
- 일반 서식 칸에는 입력 꼴의 형식을 붙인다: `1,234` → `#,##0`(3), `1,234.5` → 4, `10%` → `0%`(9), `10.5%` → 10,
  `1.5E3` → 11, 날짜 → 14 (`d-mmm` 16, `mmm-yy` 17, `mm-dd` 58, 한글 날짜 31), 시각 → 18–21 (24시간 넘으면 46),
  날짜+시각 → 22, 대분수 → 12·13.
- 다른 서식 칸은 서식 종류마다 다르다: 백분율 칸은 `%` 없는 숫자를 100 으로 나누고, 날짜 칸에 `1,234`·`10%`·`1.5E3`
  을 넣으면 그 꼴의 형식으로 바뀌고, 숫자·통화·지수·시간 칸은 형식을 그대로 둔다. 글자(`@`) 칸은 모두 글.
- `1/2` 는 일반·날짜·시간 칸에서는 날짜(올해 1월 2일), 숫자·지수·분수·백분율 칸에서는 분수 0.5.
- 대분수 `0 1/2` 는 일반 칸에서 글이 되고 형식만 `# ?/?` 로 바뀐다 (한셀의 동작 그대로).
- 일반 서식 칸에 수식을 넣으면 결과 형식을 붙인다: `TODAY`·`DATE` → 14, `NOW` → 22, `TIME` → 18, `PMT` `NPV` `FV`
  `PV` `IPMT` `PPMT` → 8, 그 밖에는 처음 참조한 칸의 형식 (더하기·빼기·부호·괄호·`SUM` `MAX` `MIN` `AVERAGE` `ROUND`
  를 거쳐서. 곱하기·나누기·거듭제곱은 숫자·백분율 형식을 버리고 통화·날짜·시각·지수·분수는 남긴다. 같은 형식끼리면
  백분율·지수·분수만 남는다. `SUM` 은 날짜 범위의 형식을 버린다).
- 배열 수식 범위의 일부는 바꿀 수 없다. 공유 수식 묶음의 칸을 바꾸면 묶음을 일반 수식으로 푼다.

## 3. 행·열 삽입·삭제와 참조 조정

참조 대조 실험: 값·수식 40종·이름·병합·조건부 서식·유효성·메모·링크·차트가 있는 문서에 행·열 삽입·삭제 18가지를
실행했다 (`src/edit/refs.rs`, `structure.rs`).

- 삽입: 삽입 위치 이후를 가리키는 참조는 밀리고, 범위 안에 삽입하면 범위가 넓어진다. 시트 끝을 넘는 참조는 끝에
  머문다 (`A1048576` 은 그대로). 열 전체·행 전체 참조(`A:A`, `5:5`)도 같은 규칙.
- 삭제: 지운 칸만 가리키는 참조는 `#REF!` (시트 이름은 남는다: `Sheet1!#REF!`), 범위는 남은 칸으로 줄어든다
  (`A6:A7` 에서 5–6행 삭제 → `A5:A5`), 범위 전체를 지우면 `#REF!`.
- 3차원 참조(`Sheet1:Sheet2!A5`)와 외부 문서 참조는 바꾸지 않는다. 문자열 안의 글(`INDIRECT("A5")`)도 그대로.
- 문서 전체에 반영한다: 모든 시트의 수식(다른 시트를 가리키는 참조 포함), 이름, 병합(한 칸만 남으면 없앤다),
  조건부 서식·유효성(범위와 수식 — 범위가 삽입 위치 바로 위·왼쪽에서 끝나도 넓어진다, 맨 앞 행을 지우면 수식의 기준
  칸을 새 첫 칸으로), 하이퍼링크, 메모(상자 자리 포함), 도형·차트 앵커(원본 그리기 XML 도), 차트 계열 참조(원본 차트
  파트도), 표·자동 필터 범위, 행·열 정보, 틀 고정, 페이지 나누기, 배열 수식·데이터 표 범위.
- 삽입한 행·열은 바로 위 행(왼쪽 열)의 서식을 물려받는다: 행 정보(높이·행 서식)를 복사하고 서식 있는 칸은 빈 칸으로
  복사한다. 열은 열 정보를 복사하되(없으면 기본 너비를 명시한 열 정보) 왼쪽 열에 열 서식이 있으면 행 서식이 있는 행의
  칸만 복사한다.

## 4. 서식

### 4.1 글꼴·채우기·맞춤·표시 형식

- 칸의 서식을 복사해 바꾼 뒤 같은 서식이 이미 있으면 그 번호를 쓴다 (글꼴·채우기·테두리·표시 형식도).
- 채우기 색: 무늬 채우기는 무늬를 두고 바탕색만 바꾼다 (`Interior.Color`).
- 표시 형식 코드: 한셀 내장 번호(문서가 다시 정의하지 않은 것) → 문서의 사용자 형식 → 새 번호(164 이상).
- 건너뛰는 칸: 개요를 접어 숨긴 행·열, 범위 밖으로 걸친 병합의 칸 (그냥 숨긴 행·열은 바꾼다).

### 4.2 테두리

테두리 대조 실험(`Borders(묶음).LineStyle`/`Weight`, 실험 문서의 경우 17가지와 서식 파일)에서 확인한 규칙:

- 범위의 선은 여섯 묶음으로 다룬다: 왼쪽·위·아래·오른쪽 가장자리, 안쪽 세로·가로.
- 색을 주지 않으면 묶음마다 첫 칸의 그 변 색을 묶음 전체에 쓴다 — 칸 사이에 선이 있으면(이웃 칸의 맞닿은 선 포함)
  그 선의 색, 없으면 칸 서식에 남은 색. 한셀 문서의 기본 테두리는 선 없이 왼쪽·오른쪽·아래 검정, 위 자동 색을 담고
  있어서, 보통은 위 가장자리만 자동 색이고 나머지는 검정이다.
- 안쪽 세로선: 첫 행(범위 밖으로 걸친 병합이 없는 첫 행)의 칸 사이 선이 모두 같은 색이면 그 색, 아니면 그 행 끝 칸의
  왼쪽 변 색. 안쪽 가로선: 그 행 칸들의 서식에 남은 아래 변 색이 모두 같으면 그 색, 아니면 자동.
- 묶음의 칸 사이가 모두 이미 같은 선(종류·색)이면 그 묶음은 바꾸지 않는다.
- 가장자리 선을 그으면 범위 밖 이웃 칸의 맞닿은 선은 새 선과 다르면 지우고, 같으면 둔다 (한셀은 칸 사이 선을 하나로
  다룬다 — B10 위 선을 그으면 B9 의 아래 선이 없어진다).

### 4.3 병합

- 겹치는 병합은 먼저 푼다. 배열 수식이 있는 칸은 병합하지 않는다.
- 왼쪽 위 칸이 비었으면 처음 만나는 값(행 우선)을 왼쪽 위 칸으로 옮긴다. 그 칸의 글꼴·채우기·맞춤·표시 형식도
  오지만 테두리는 왼쪽 위 칸의 것을 둔다. 나머지 칸의 값은 지우고 서식은 둔다.
- 병합 안쪽의 칸 사이 선(바깥 가장자리가 아닌 변)은 지운다.
- `center` 면 병합한 칸 모두를 가운데 맞춤.

### 4.4 열 너비·행 높이

- 열 너비: 한셀 COM `ColumnWidth`(글자 수) → 저장 값은 1/256 로 자르고 199/256 을 더한다 — 글꼴과 상관없다
  (20 → 20.77734375, 8.43 → 9.20703125). 웹 편집기에서 끈 너비는 화면 px 를 글자 수로 바꾼다. 0 이면 숨긴다.
- 바뀐 칸 안의 도형 표지 오프셋은 (칸 px − 1) 의 비율로 옮기고 px 로 반올림한다 — 28px 열을 131px 로 넓히면 25px
  표지가 25 × 130/27 → 120px, 40px 행을 60px 로 높이면 25px 표지가 38px (열 너비·행 높이 대조 실험).
- `editAs="oneCell"` 그림은 크기를 지키도록 끝 표지를 다시 정하고, 메모 상자는 화면 자리를 지킨다.

## 5. 복사·잘라 붙이기·채우기

- 복사해 붙인 수식의 상대 참조는 옮긴 만큼 바뀐다 (시트 밖으로 나가면 `#REF!`). 서식·병합·조건부 서식·유효성도 함께
  간다. 붙일 범위가 복사한 크기의 배수면 되풀이해 채운다.
- 행·열 서식만 있는 칸도 그 서식으로 복사한다 (칸 기록이 없어도).
- 수식이 쓰는 통합 문서 이름은 붙인 시트의 시트 범위 이름으로 하나 더 만든다 (한셀의 동작 — `SUM(MyRange)` 를 같은
  시트에 붙이면 시트 범위 `MyRange` 가 생긴다). 채우기에서는 만들지 않는다.
- 잘라 붙이기(셀 옮기기): 옮긴 칸을 가리키던 참조가 모두 새 자리를 따라간다 — 원본 범위 안에 모두 든 참조만
  (`SUM(A1:A10)` 은 그대로, `SUM(A5:A6)` 은 `SUM(Q5:Q6)`). 조건부 서식은 옮긴 칸의 몫을 떼어 새 자리에 새 규칙으로,
  유효성은 같은 규칙의 범위를 옮긴다 (`B1:B10` 에서 B5:B6 을 옮기면 `B1:B4 B7:B10` + `R5:R6`). 병합의 일부만 옮길 수는
  없다 ("병합된 셀의 일부를 바꿀 수 없습니다"). 다른 시트로 옮긴 수식의 접두 없는 참조에는 원래 시트 이름을 붙인다.
- 아래로·오른쪽으로 채우기는 첫 행(열)을 나머지에 복사한다.
- 다른 프로그램에서 복사한 글(TSV)은 칸마다 2절의 입력 규칙으로 붙인다. 앱 안 복사는 클립보드에도 TSV 를 넣는다.

## 6. 시트

- 추가: 이름이 없으면 쓰지 않은 가장 작은 `SheetN`. 인쇄 설정은 한셀 새 시트의 기본값(여백 19·25·13 mm, A4 세로).
  새 시트를 선택한다.
- 코드 이름: 한셀은 문서를 열 때 코드 이름이 없는 워크시트에 차례로 `SheetN` 을 준다. 그래서 시트를 더하거나 지우거나
  옮기기 전에 같은 이름을 주고, 새 시트는 쓰지 않은 가장 작은 `SheetN` 을 받는다 (코드 이름 없는 문서에 시트를 더해
  앞으로 옮기면 원래 시트가 `Sheet1`, 새 시트가 `Sheet2`).
- 이름 규칙: 1–31자, `: \ / ? * [ ]` 없이, 작은따옴표로 시작·끝나지 않고, 대소문자를 무시하고 겹치지 않게.
- 이름 바꾸기: 모든 수식·이름·조건부 서식·유효성·차트 계열 참조의 시트 이름을 바꾼다 (필요하면 작은따옴표).
- 삭제: 그 시트를 가리키는 참조는 `#REF!`, 3차원 참조의 끝 시트를 지우면 그 자리에 오는 시트로 바꾼다. 그 시트의 시트
  범위 이름은 지운다. 마지막 보이는 시트는 지울 수 없다.
- 옮기기: 시트 번호를 쓰는 곳(시트 범위 이름, 활성 탭)을 고친다. 활성 시트는 선택된 시트를 따른다.

## 7. 보호

- 보호된 시트의 잠긴 칸은 바꿀 수 없다: "변경하려는 셀은 보호되어 있으므로 읽기 전용입니다 (시트 보호)".
- 보호 설정이 막은 동작(서식, 행·열 삽입·삭제, 열 너비·행 높이 …)은 할 수 없다.
- 통합 문서 구조 보호는 시트 추가·삭제·이름 바꾸기·옮기기를 막는다.

## 8. 다시 계산과 되돌리기

- 편집마다 계산 엔진(`rcell::calc`)으로 모든 수식을 다시 계산한다. 엔진은 수식을 한 번씩만 계산하고(되부름은 기억해
  둔 값) 서식 파일 크기의 문서는 수 ms 안에 끝나므로 의존 그래프에 따른 부분 계산은 하지 않는다.
- wasm 에는 시계가 없으므로 편집 앞에 `rcell_set_clock(Date.now(), 시간대)` 를 부른다 (`NOW()`·`TODAY()`·`RAND()`).
- 되돌리기는 편집 앞 문서의 사본을 100 단계까지 둔다 (편집하지 않는 그림·매크로 같은 이진 파트는 빼고).

## 10. 검증

1. **단위 시험** — `cargo test edit`: 한셀 대조 실험 결과를 기대값으로 한 시험 (행 삽입·삭제 때 수식 40종·이름·
   병합·조건부 서식·유효성·메모·링크·차트 앵커와 계열, 열 삽입·삭제, 시트 이름 바꾸기·삭제·추가, 복사·잘라 붙이기·
   채우기, 서식 물려받기, 입력 규칙·수식 결과 형식, 테두리 묶음 규칙, 병합, 표지 오프셋, JSON 대본).
2. **대조 실험** — `tools/probe/edit-oracle.ps1` 이 편집 대본을 한셀 COM 으로 실행해 저장하고, `tools/probe/edit-e2e.js`
   가 corpus 문서 48종(한셀 서식 파일 28종 + 조작 문서 20종)에 대본 5종(셀 입력 22, 행 삽입·삭제, 열 삽입·삭제, 서식 8,
   복사·채우기·옮기기·시트 6)을 rcell 과 한셀로 각각 실행한다. 판정은 HCell(편집) 대 HCell(rcell(편집)) — rcell 이
   저장한 것을 한셀이 다시 읽어 저장한 결과를 `rcell diff` 로 비교한다. 차이가 나면 한셀 결과도 한 번 다시 저장해 한셀이
   다시 연 결과끼리도 비교한다 (한셀은 문서를 열면서 기록 없는 행을 자동 높이로 맞추고 그 행에 걸린 도형 표지를 옮긴다).

   | 대본 | 같음 |
   |------|------|
   | 셀 입력 | 48/48 |
   | 행 삽입·삭제 | 44/48 |
   | 열 삽입·삭제 | 44/48 |
   | 서식 | 44/48 (한셀이 다시 연 결과끼리 45) |
   | 시트·복사 | 44/48 |
   | 합계 | 224/240 (한셀이 다시 연 결과끼리 225) |

   따로 만든 실험 문서도 같은 방법으로 비교했다: 참조 조정 18가지·서식 물려받기 9가지는 모두 같고, 테두리 17가지 중
   15가지, 병합 4가지는 칸 서식이 모두 같다 (남은 것은 11절). 입력 규칙은 94가지 입력 × 형식 14종을 한셀이 저장한 값·
   형식과 맞췄다.
3. **브라우저 시험** — `node tools/web-smoke.js`: 헤드리스 Edge(원격 디버깅)로 웹 편집기를 열어 칸 고르기, 값·수식·
   날짜·백분율·작은따옴표 입력, 다시 계산, 굵게, 행 삽입과 참조 조정, 되돌리기·다시 실행, 복사·붙여넣기, TSV
   붙여넣기, Ctrl+방향키, 지우기, 시트 추가, `.cell` 저장을 실제 키·마우스 사건으로 실행하고, 저장한 문서를 rcell 로
   다시 읽어 값과 계산을 확인한다 (26가지).

## 11. 남은 차이

corpus 대조에서 차이가 남은 16건과 실험 문서에서 남은 차이:

- 열 삽입·삭제: 한셀은 행 서식이 있는 행의 칸을 시트 끝(XFD)까지 모두 칸 기록으로 만든다 (행마다 1만 6천여 칸).
  rcell 은 행 서식으로 두고 만들지 않는다 (서식 파일 2종).
- 열 삭제로 병합이 한 칸이 되면 한셀은 병합 칸에 보이던 위 선(위 칸의 아래 선)을 남은 칸의 위 선으로도 적는다
  (서식 파일 1종).
- 행 삽입·삭제 뒤 메모 상자의 오른쪽 끝 표지와 틀 고정의 오른쪽 아래 첫 칸을 한셀은 다르게 정한다 (조작 문서 2종).
  열 삭제 뒤 세로 페이지 나누기도 (1종).
- 보호된 시트: 한셀 COM 은 보호를 무시하고 열 너비를 바꾸고 시트를 더한다 — rcell 은 보호를 지킨다 (조작 문서 2종의
  서식·시트 대본). 필터로 숨긴 행이 있는 보호 시트의 행 삭제, 개요를 접은 보호 시트의 행 삽입(한셀은 아래 행들을
  숨긴다)도 다르다 (2종).
- 복사·채우기·옮기기: 한셀은 조건부 서식 규칙을 복사할 때 우선순위·중복을 다르게 정리한다 (조작 문서 2종).
- 1px 보다 작은 EMU 오프셋을 한셀은 다시 맞춘다 (조작 문서 1종).
- 테두리 안쪽 선의 색: 첫 칸들에 이미 서로 다른 색의 선이 있을 때 실험 2가지가 다르다.
- 병합: 한셀은 병합한 첫 행의 높이를 고정 높이로 적고 나머지 행의 자동 높이를 지운다 (기록이 자동 높이인 행에서만).
